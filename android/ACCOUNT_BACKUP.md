# Android 계정 기록 백업과 복원

2026-10-02 구현 범위입니다. 실행 결과는 `PORTING_STATUS.md`의 같은 날짜 항목을 확인합니다.

## 저장과 계정 전환

- 게스트 기록은 `taste-buddy-state.json`, 로그인 계정 기록은 계정 ID의 SHA-256으로 구분한 `taste-buddy-account-<hash>.json`에 보관합니다. 모두 Android 앱 전용 `filesDir` 안의 원자적 파일입니다.
- 로그아웃은 계정 기록과 사진을 지우지 않습니다. 다른 계정으로 로그인하면 별도의 보관함을 엽니다. 이전 계정에서 시작한 지연 저장·복원은 새 계정에 적용할 수 없습니다.
- 이전 버전 파일에는 소유자 정보가 없으므로 게스트 보관함에 그대로 남깁니다. 이전 기록은 로그아웃 → 게스트로 시작하기에서 확인할 수 있습니다. 계정의 출처를 추측해서 옮기지 않습니다.
- 게스트 화면의 ‘현재 계정을 이메일에 연결’은 비어 있는 해당 계정 보관함으로 게스트 상태를 복사합니다. 기존 계정에 기록이 있으면 게스트 원본을 별도로 유지합니다. 인증 코드 요청 중 앱을 다시 시작해도 익명 세션은 게스트 보관함을 사용합니다.
- 새 계정의 기본 프로필에 예시 인물의 이름·닉네임을 넣지 않습니다.

## 계정 백업

`native_account_data`의 공유 스냅샷에 다음 값 하나를 추가합니다.

```text
values["tastebuddy.android.archive.v1"] = base64(UTF-8 JSON)
```

```json
{
  "schemaVersion": 1,
  "state": { "schemaVersion": 1, "entries": [] },
  "photoFilenames": []
}
```

`state`에는 실제로 전체 `AppState`가 들어갑니다. 기록, 작성 중인 기록, 설문 원응답, 선호 제출, 프로필, 질문 진행, 북마크, 댓글 등 원래 저장 객체를 보관하며 다른 플랫폼 형식으로 변환하지 않습니다. 위 JSON은 축약된 형태입니다.

- iOS·웹의 값과 알 수 없는 다른 확장 값은 그대로 보존합니다. Android의 기록·분석은 Android 기기 사이에서 복원되며 iOS·웹 기록에 합쳐지지 않습니다.
- 확장 내부 사진 목록은 모든 기록·작성 중인 기록·아바타의 원본 파일명을 정확히 포함합니다. 공유 스냅샷의 사진 목록에도 이 이름을 포함합니다. 기존 목록의 추가 사진은 보존합니다.
- 사진은 계정별 비공개 `native-dining-photos/<user ID>/<filename>`에 먼저 업로드합니다. 기존 파일을 덮어쓰지 않고, 이름이 같은 원본은 바이트가 일치하는지 확인합니다. 사진 준비가 끝난 뒤 `save_native_account_data`에 기대 revision을 전달합니다.
- 로그인·앱 시작·원문 변경 후 백업을 시도합니다. 프로필 설정에서 다시 실행할 수도 있습니다. 화면의 탭 이동만으로 원문 변경을 만들지 않으며 자동 백업 중에도 로컬 편집을 저장할 수 있습니다.
- 계정 삭제·로그아웃을 요청한 뒤 로그인 상태가 바뀌면 이전 응답으로 현재 세션을 지우지 않습니다. 같은 계정에 다시 로그인했고 응답 값이 같아도 이를 새 로그인으로 구분합니다. 기기 기록 초기화도 요청을 시작한 계정인지 확인합니다.
- 요청은 시작한 계정의 토큰에 고정합니다. 지연 응답이 다른 계정의 로컬 상태를 바꾸지 못하며 로그아웃 뒤 늦은 토큰 갱신이 세션을 되살리지 못합니다.

## 충돌과 실패

- 기기 원문이 손상되어 앱을 열지 못하면 오류 화면에서 ‘계정 백업으로 복원’을 직접 선택할 수 있습니다. 정상 계정 백업과 사진을 먼저 확인하고, 읽을 수 없는 기기 파일의 정확한 바이트를 `taste-buddy-unreadable-<hash>-<UUID>.bin`으로 보관한 뒤 교체합니다. 원문 파일 읽기·사진 준비·복구본 쓰기에 실패하거나 준비 중 원문·계정이 바뀌면 교체하지 않습니다. 선언된 새 버전의 기기 기록은 이 경로로 낮은 버전으로 바꿀 수 없습니다.
- 새 기기는 Android 계정 백업의 사진을 모두 확보한 다음 원문 상태를 적용합니다. 사진 누락·손상·같은 이름의 다른 바이트가 있으면 현재 상태를 교체하지 않습니다.
- 다른 Android 기기의 원문과 이 기기의 수정이 모두 존재하면 자동 덮어쓰기를 멈춥니다. 마지막 기록을 삭제해 빈 목록이 되어도 수정 의도를 유지합니다.
- 설정 화면에서 ‘이 기기 기록으로 백업’ 또는 ‘계정 백업으로 복원’을 명시적으로 선택합니다. 교체되는 원문은 계정별 `taste-buddy-recovery-<hash>-<UUID>.json`으로 먼저 보관합니다. 원격 원문을 교체할 때에는 그 사진도 먼저 기기에 확보합니다.
- 복구본은 내부 보관 파일입니다. 현재 UI에는 복구본 목록을 탐색하는 기능이 없으며, 지원 도구나 기기 파일 접근을 통한 원문 회수가 필요합니다.
- 서버 저장이 성공하고 응답만 유실된 경우, 다음 조회의 전체 Android 원문이 같으면 해당 revision을 확인 처리합니다. 응답 대기 중 생긴 새로운 로컬 수정은 지우지 않습니다.
- 지원하지 않는 버전·새 원문 필드·손상된 JSON·잘못된 사진 목록은 수정하지 않습니다. 새 감각 선택의 알 수 없는 필드는 원문으로 보존하고 분석 근거를 만들어내지 않습니다.
- 사진 파일은 계정별 기록이 참조하는 공유 기기 디렉터리에 있습니다. 같은 이름의 다른 바이트를 복원하면 기존 사진을 사용하거나 덮어쓰는 대신 작업을 거절합니다. 계정별 사진 디렉터리는 아직 구현하지 않았습니다.
- 원격 사진 삭제나 전체 기기 사진 자동 정리는 수행하지 않습니다. 다른 계정과 복구본이 참조하는 원본을 함께 지우지 않기 위한 경계입니다.

## 실제 출시 전 확인

1. 실제 Google·이메일 계정으로 Android 두 기기 사이에서 기록·사진·작성 중인 기록·설문·선호 원문을 왕복합니다.
2. 수정/삭제 충돌, 마지막 기록 삭제, 사진 업로드 중 종료, 오프라인 재시작, 세션 만료·로그아웃·다른 계정 로그인 후 재시도를 확인합니다.
3. 운영 Supabase의 RLS, 사진 bucket, 업로드 lease, CAS RPC와 배포한 migration 상태를 확인합니다. 이 구현 작업에서 운영 데이터를 쓰거나 migration을 배포하지 않습니다.
4. iOS·웹의 실제 배포 클라이언트가 Android 확장과 사진 목록을 보존하는지 확인합니다. Android와 iOS·웹 사이의 기록 변환과 공통 분석은 아직 제공하지 않습니다.
5. 안정된 Android 실기기에서 설정의 백업 상태·충돌 선택·사진 표시와 TalkBack을 확인합니다. 개발 APK 빌드만으로 이를 검증한 것으로 보지 않습니다.
