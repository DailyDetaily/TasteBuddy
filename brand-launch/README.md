# Taste Buddy 앱 소개 영상 · 1차 시안

**1920 × 1080 · 16:9 · 30fps · 30초(900프레임)**  
컴포지션: `TasteBuddyLaunch`

좋아했던 한 끼가 기록과 맛 피드백을 거쳐 나의 취향을 이해하는 이야기로 이어집니다. 실제 SwiftUI 화면, 큰 타이포, UI 확대, 원과 선의 로고 모션으로 구성했습니다.

## 미리보기

```sh
cd brand-launch
npm run dev
```

[Remotion Studio에서 보기](http://localhost:3110/TasteBuddyLaunch)

`dev`는 Studio와 iOS 소스 감시를 함께 실행합니다. 현재 소스와 일치하는 캡처가 있으면 재사용하고, 변경되면 자동으로 빌드·캡처합니다. 처음 실행할 때는 Xcode 빌드 시간이 필요합니다. 기본 실행은 MP4를 생성하지 않습니다.

## 실제 iOS 화면 자동 갱신

원본은 `ios/TasteBuddy/`입니다. 광고용 JSX로 앱 UI를 다시 만들지 않습니다.

1. SwiftUI 소스 저장 후 2초간 변경을 모읍니다.
2. 소스 복사본을 격리된 빌드 경로에서 빌드합니다.
3. 전용 `Taste Buddy Brand Video` 시뮬레이터에서 실제 앱을 실행합니다.
4. 식사 기록(`dining`), 맛 피드백(`feedback`), 취향 해석(`analysis`)을 캡처합니다.
5. 세 이미지가 모두 준비되고 소스가 일치하면 Studio에 자동 반영합니다.

확대 화면도 같은 캡처 원본을 사용합니다. SwiftUI 변경에는 빌드·캡처 시간이 필요하며, Remotion 문구와 모션 변경은 Studio에 바로 반영됩니다. 캡처는 예시 식사 데이터를 사용하고 실제 사용자 계정에 접속하지 않습니다. 진입점은 `ios/TasteBuddy/App/BrandVideoRuntimePreview.swift`입니다.

갱신에 실패하면 이전 이미지를 유지하고 상태를 표시합니다. 오류 로그: `.native-ui-cache/build.log`. 빌드 중 소스가 바뀌면 최신 소스로 다시 갱신합니다.

```sh
npm run native:capture
npm run native:check
```

## 네이티브 온보딩 모션

영상 속 세 그래픽을 코드로 재구성했습니다. 원본의 도형·색상·주기를 참고한 절차적 모션이며
원본 영상의 모든 프레임과 픽셀 단위로 같지는 않습니다. 영상 재생이나 이미지 시퀀스를 사용하지 않습니다.

| 페이지 | Remotion 컴포지션 | SwiftUI 스타일 | 주기 |
| --- | --- | --- | --- |
| 2 | Onboarding-analysis | .analysis | 20.4초 |
| 3 | TasteMotion-rotatingLayers | .rotatingLayers | 분할·결합 2초 |
| 4 | TasteMotion-feedbackRings | .feedbackRings | 첫 변환 1.7초, 이후 파동 3초 |

선 모션은 고정 시드로 선택한 8개 위치를 불규칙한 간격으로 이동합니다. 이동은 약 0.9~1.3초이며,
내부 빈 원의 기본 반지름은 큰 원 반지름 316의 1/4인 79입니다. 이동 후반 62~92% 구간에서 기본 크기로 수축하며, 대기 중에도 작은 박동을 유지합니다.
수축 시 기존 선 사이를 동시에 나누며 12 → 24 → 48개로 늘고, 확대 시 역순으로 줄어듭니다. 보이는 선마다 미각 순서로 6색을 반복하며, 맞은편 선은 같은 색과 투명도를 유지합니다. 최소 개수에서도 6가지 색이 모두 보입니다.
전체 경로는 20.4초마다 반복됩니다.

추가 모션 `TasteMotion-rotatingLayers` / SwiftUI `.rotatingLayers`는 선택한 개수의 선을 3·6·12층으로 나눠 시계방향으로 회전합니다.
중앙 빈 원과 3분할 선의 길이는 큰 원 반지름의 25%이며, 6분할 선은 12.5%, 12분할 선은 6.25%입니다. 처음에는 같은 색의 세 선이 일직선으로 붙어 있고,
12개 선 기준으로 분할은 바깥층만 15° 이동 → 바깥층 추가 15°와 중간층 15° 동시 이동의 두 동작입니다. 안쪽층은 두 동작 동안 정지합니다.
3분할 상태(안쪽 0°·중간 15°·바깥 30°)에서 각 선을 절반으로 나눕니다. 바깥쪽 쌍부터 각 쌍의 바깥 절반만 7.5°씩 회전하여 안쪽부터 0°·7.5°·15°·22.5°·30°·37.5°가 됩니다.
6분할 상태에서 한 번 더 절반으로 나누고, 바깥쪽 쌍부터 바깥 절반만 3.75°씩 회전하여 12분할이 됩니다.
합체는 안쪽 절반이 따라붙어 **12분할 → 6분할 → 3분할**로 돌아온 뒤, 안쪽층만 15° 이동 → 안쪽층 추가 15°와 중간층 15° 동시 이동의 두 동작이며, 바깥층은 고정됩니다.
분할부터 결합까지 한 주기는 60프레임(2초)입니다. 각 회전은 약 0.056초 동안 임계 감쇠 곡선으로 감속하며 목표 각도에 안착합니다. 중간 정지는 약 0.032초, 일직선 정지는 약 0.092초이며 매 주기 41.25° 전진합니다. 같은 색과 위치로 돌아오는 전체 주기는 192초입니다. 기존 미각 색상을 사용합니다.
모드는 `divisions`로 3·6·12 중 선택합니다. SwiftUI는 `.three`·`.six`·`.twelve`, 화면 기본값은 6분할입니다. 네이티브 Preview의 분할 선택기와 Remotion `RotationModes`에서 비교할 수 있습니다. `rayCount`는 12·24·48개의 선을 선택하며 SwiftUI는 `.twelve`·`.twentyFour`·`.fortyEight`를 사용합니다. 기본값은 12개입니다. 분할과 선 개수를 독립적으로 조합하는 9개 프리뷰(`TasteMotion-{분할}-segments-{선개수}-lines`)를 제공합니다. 세 모드 모두 분할·결합은 2초입니다.
24개 선은 회전 각도를 1/2, 48개 선은 1/4로 줄입니다. 기본 회전은 각각 7.5°·3.75°이며 추가 분할 때마다 절반으로 줄여, 중간 정렬에서 다른 색의 옆 선과 이어지지 않게 합니다. 분할·결합은 모두 2초이고, 전체 방향이 돌아오는 반복 주기만 선 개수에 맞게 늘어납니다.
같은 `TasteMotionView`의 `style`을 `.analysis`에서 `.rotatingLayers`로 바꾸면 현재 빈 원이 1.2초 동안 중앙으로 이동하고 기본 크기·선택한 선 개수로 정돈된 후 회전을 시작합니다.
전환에서 사라지는 선은 시작 시의 투명도를 유지한 채 바깥 끝이 내부 빈 원 쪽으로 짧아집니다. 회전으로 이어지는 선은 바깥 원까지 연결된 상태를 유지하고, 추가되는 선은 안쪽에서 길어지며 나타납니다.
전환 예시 `TasteMotion-analysisToRotation`은 분석 4초 → 중앙 이동 1.2초 → 회전 순서로 재생됩니다.

`TasteMotion-completeFlow`는 분석 4초 → 중앙 이동 1.2초 → 조정 4초 → 직선에서 세 원으로 변환 1.7초 → 피드백 파동 6초 → 종료 수축 0.8초를 이어서 보여줍니다. 미리보기 끝에 0.5초를 둡니다. 이 예시는 6분할·12개 선이며, 기존 9가지 회전 조합은 유지합니다.

피드백은 각 선을 세 조각으로 합쳐 조각 중심을 유지한 채 90도 회전하고, 호로 휘어 세 원을 만듭니다. 같은 6색이 각도에 따라 그라데이션으로 연결됩니다. 완성된 세 원은 반지름 118.5·197.5·276.5에서 출발해 79 간격을 유지하며, 분석 바깥 원과 같은 반지름 316까지 퍼집니다. 외곽에서 투명해진 원은 안쪽에서 다시 나타나며, 첫 변환은 반복하지 않습니다.

같은 네이티브 뷰의 `style`을 `.rotatingLayers`에서 `.feedbackRings`로 변경하면 현재 2초 분할·결합 주기가 끝날 때까지 회전을 이어서 선을 정렬합니다. 그 위치·색 순서를 유지한 채 세 원으로 변환합니다. 분석의 중앙 이동이 아직 진행 중이라면 먼저 중앙 이동을 마칩니다. `feedbackComplete: true`를 전달하면 현재 원의 크기와 투명도에서 안쪽부터 수축하고 타임라인을 멈춥니다. 원 변환 전에 종료를 요청하면 변환 완료 후 수축합니다. 네이티브 Preview의 ‘분석 → 조정 → 피드백’에서 단계 전환과 종료를 직접 확인할 수 있습니다.

앱 UI: `ios/TasteBuddy/Components/TasteMotionView.swift`.
`TasteMotionView(style: .analysis, isActive: true)`로 원하는 정사각형 크기에 배치합니다.
온보딩 2·3·4페이지는 각각 분석·조정·피드백 스타일을 사용하며, 회전 기본 상태는 6분할·12개 선입니다. 페이지 이동과 완료 버튼의 기존 동작은 유지합니다. `.detailMatrix`는 다른 사용처를 위해 보존했습니다.
Canvas와 TimelineView로 직접 그리며 기존 TasteAxis 색상을 사용합니다. 화면 이탈·백그라운드·
비선택 페이지에서는 타임라인을 멈춥니다. 동작 줄이기에서는 분석·조정의 첫 프레임, 피드백의 완성된 세 원을 표시합니다.
1번 페이지의 정지 이미지는 유지했습니다. 장식용 도형이며 실제 사용자 취향 수치는 아닙니다.

Remotion의 `src/taste-motion.ts`와 SwiftUI의 `TasteMotionGeometry`는
같은 640 단위 좌표·수식·주기를 사용합니다. 수식을 바꿀 때 양쪽 구현을 함께 수정합니다.

```bash
cd brand-launch
npm run studio            # TasteMotion-completeFlow에서 전체 전환 확인
npm run test:motion   # Node 22.18+; 좌표 범위·움직임·루프 경계 검사
npm run lint
```

iOS의 `SystemParityComponentTests.testOnboardingMotionStaysInBoundsAndLoops`도 같은 조건을 검사합니다.
앱에서 `--onboarding-preview` 실행 인자로 온보딩을 직접 열 수 있습니다.


인사이트 링(`.insightRing`, Remotion `TasteMotion-insightRing`)은 중앙의 6개 점에서 시작합니다. 각 줄의 가운데에서 시작해 좌우 점이 동시에 돋아나며 126개를 규칙적으로 채웁니다. 새로운 점은 같은 미각의 가까운 기존 점에서 메타볼로 이어지고, 가운데에서 양끝 순서로 채워집니다. 동심원마다 6·12·18·24·30·36개씩 배치해 바깥쪽에서도 점 간격을 일정하게 유지합니다. 채워지는 영역은 회전 모션의 중앙 빈 원(640 좌표계에서 반지름 79) 안에 맞춥니다. 0.6초에 채움을 마치고 0.2초 유지한 뒤 1.1초 동안 바깥 링으로 펼쳐지며, 이후 기존 자유로운 파동이 시작됩니다. 상세 화면은 같은 모션과 렌더러를 사용하고 중앙 정보는 펼쳐짐에 맞춰 나타납니다. 동작 줄이기·빈 기록에서는 완성된 링을 정지 상태로 표시합니다.

채움 단계는 안쪽 불투명도 1에서 바깥쪽 0.35로 점점 연해집니다. 펼쳐진 링은 여섯 미각 컬러가 섞인 상태이며, 누르는 동안 0.5초에 걸쳐 같은 컬러끼리 원 둘레의 여섯 구역으로 모이고 놓으면 다시 섞입니다. 정렬 도중 점은 원 둘레를 따라 이동합니다. Remotion Studio에서는 재생 프레임으로 전환하며, 정지 상태의 입력은 즉시 반영합니다. 네이티브 동작 줄이기에서도 정렬 상태는 즉시 반영하고, VoiceOver에는 정렬 전환 동작을 제공합니다.

정돈된 배치의 시작은 왼쪽 상단 주황색(-120°)이며, 시계방향으로 주황·노랑·초록·파랑·보라·갈색이 이어집니다.

펼쳐진 링은 드래그한 각도만큼 직접 회전합니다. 빠르게 놓을수록 더 멀리 돌아가며 최대 1.8초 동안 감속한 뒤 원래 자동 회전 속도로 이어집니다. 움직임을 멈추고 0.12초 이상 지난 뒤 놓거나 다시 잡으면 관성을 멈춥니다. 웹 좌우 방향키와 iOS VoiceOver 조절 동작으로도 회전할 수 있고, 동작 줄이기에서는 관성을 생략합니다.

펼쳐진 링은 고정 시드로 점을 흩뿌려 배치합니다. 안쪽·바깥쪽 윤곽에 일부 점을 남기고 나머지는 링 내부에 자유롭게 배치하며, 같은 미각 색은 처음 배치할 때 최소 54만큼 띄웁니다. 링은 평균 50.2초에 한 바퀴씩 시계방향으로 회전하고, 각 점의 속도는 서로 다른 박자로 기준 속도의 ±6% 안에서 달라집니다. 누르는 동안에는 기존 불규칙한 배치를 여섯 미각 구역으로 나누어 모으고, 각 점은 자기 구역 안에서 조금씩 움직입니다. 정렬 중에도 각 방향에 안쪽·바깥쪽 점이 남도록 보정해 링의 실루엣을 유지합니다. 입력 시점의 이동 방향을 유지해 회전 경계를 지나도 점이 튀지 않습니다.

Remotion Studio에서 링을 직접 눌러 확인할 때는 `More actions → Outlines`를 끕니다. 검사 테두리가 켜져 있으면 Studio가 마우스 입력을 먼저 받습니다.

메타볼 연결은 [Paper.js 공식 예제의 기하 모델](https://github.com/paperjs/paper.js/blob/develop/examples/Paperjs.org/MetaBalls.html)을 바탕으로 두 원의 반지름·거리·교점에서 연결점을 구하고, 원의 접선 방향으로 곡선을 잇습니다. 분리 직전에는 연결 폭을 줄입니다. 채움 단계에서는 같은 미각의 점과 연결부를 불투명 마스크로 합친 후 중앙에서 바깥으로 옅어지는 색을 한 번만 적용해 겹친 부분이 진해지지 않습니다.
