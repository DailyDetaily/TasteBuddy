# Taste Data Category Motion

기존 `TasteMotion`의 다섯 스타일, 누르기 정렬, 드래그 회전, analysis → rotatingLayers → feedbackRings 전환은 수정하지 않는다.
새 이름은 `TasteDataCategoryMotion` 폴더에 등록하며 현재는 iOS 카테고리 상단에도 연결되어 있다. TBA, 집계 엔진, 저장 모델은 변경하지 않는다.

현재 수축 규칙: 진입 후에는 대기만 계속 반복한다. 맥락·변화도 대기 루프 경계에서 자동 수축하거나 재진입하지 않는다. 수축은 그림 위 스크롤 / 네이티브 화면 스크롤에 따른 진입 프레임 역탐색으로만 작동한다. 아래 과거 변경 이력의 자동 수축 설명보다 이 규칙을 우선한다.

2026-10-12 취향 링 크기: 경험·감각과 같은 340×340 표시 영역에서 중심 기준 좌표 배율 0.92, 기본 점 반지름 9.5(640 좌표계)를 사용한다. 기록 있음·빈 상태·미응답·보류에 같은 취향 링 크기를 적용한다. 126개 비율 점과 평가 분포·실제 응답 수·회전 및 선택 동작은 유지한다.

2026-10-12 맥락·변화 크기: 표시하는 링 수에 따라 중심 반경과 지그재그 이동 폭을 같은 비율로 확대하여, 바깥 점의 가장자리 반경을 285(640 좌표계, 340 화면에서 지름 약 303)로 맞춘다. 점 자체의 반지름 9.5와 링별 점 개수·안팎 순서·상대 간격은 유지한다. 맥락은 현재 표시 조건 수(최대 4층), 변화는 이전/최근 2층에 같은 규칙을 사용하며 빈 상태의 기본 3층/2층에도 적용한다. 기존 ±6은 확대 전 기준이며 8초 주기·정렬·진입/스크롤 역재생 타이밍과 데이터 의미는 유지한다. 미리보기 범례는 커진 바깥 링 밖으로 배치한다.

2026-10-12 빈 상태: `noData`에서도 경험·감각·취향의 기존 기본 링, 맥락의 3중 링, 변화의 2중 링을 남긴다. 원본 배치 함수만 재사용하며 합성 기록·응답은 만들지 않는다. 표시용 점은 `data: false`, 정지 상태이며 값과 분모는 `—` / `— → —` 및 기존 상태 문구를 유지한다. 부분적으로 확인된 비교 값은 보존한다.

2026-10-12 컬러: 옅은 점은 Light tint/60 · Dark tint/70, 진한 점은 main, 미응답·보류 중립 점은 Light #D0D0D0 · Dark #A3A3A3이다. 빈 상태는 전용 insight-empty(Light #E4E4E4 · Dark #343434)로 더 옅게 표시한다. Light 페이지 #F3F3F3 위의 점만 가독성을 보정한다. `motionTint`는 tintSurface를 원본 역할 표시값으로 출력하고 웹·iOS가 모드별 motion/companion 색으로 해석한다. 취향 링의 장식용 alpha 농도도 불투명한 main / motion/companion으로 통일했다. 진입과 선택 해제의 alpha는 유지하며, 아래 과거 기록의 pigment 16% 혼합 규칙보다 이 규칙을 우선한다.

## 재현성과 갱신

- fixture는 렌더러와 분리되어 있고 모든 수치/점/선이 동일한 fixture를 참조한다.
- 경험 기록은 안정적인 ID로 정렬하고 고정 시드 42를 사용한다. 기록 추가 시 126개의 기존 링 위치 안에서 비율을 다시 배분한다. 전체를 새로 무작위 배치하지 않으며 수량 변화에 따라 색 경계와 간격이 조정된다.
- 확인 필요 기록은 별도 군집에 모으되, 동일 메뉴라고 단정하는 내부 연결선은 만들지 않는다.
- 경험은 120Hz 고정 시간 간격으로 점의 위치·속도·관성·충돌을 계산하고 fixture별 궤적을 한 번만 캐시한다. 구슬이 닿을 때 운동량을 교환하며, 겹치거나 다른 위치로 순간 이동하지 않는다. 실제 같은 메뉴 점과 충돌한 주변 점은 0.24초 동안 기존 main 컬러에서 tintSurface 컬러로 바뀐다. 내부를 채우며 테두리는 없다. 진한 점은 조금 커지며 모든 다른 점의 경계까지 최소 7 논리 단위 간격을 확보한다. 대기에는 안정적인 ID로 시드를 정한 각 점이 서로 다른 위상·방향·속도로 작게 움직인다. 공통 국소 흐름 없이 점마다 독립적인 변위를 사용한다. 정착 위치에서 최대 약 10 논리 단위 이내로 움직이며, 12초 경계의 위치·속도가 이어진다. 가까운 점들이 비슷한 국소 흐름을 따라 움직여 보호 간격을 유지한다. 모든 점이 동시에 멈추거나 중간에 같은 위치로 모이는 공통 리듬은 사용하지 않는다. 점 사이 간격과 진한 점의 보호 여백을 동시에 계산한다. 진입 마지막 구간은 감쇠된 스프링으로 승인한 정착 배치에 도착하며, 대기 중에는 캐시된 배치 주변에서만 움직인다. 반복할 때 물리 계산을 다시 시작하지 않는다.
- 하이라이트는 기존 선 위의 얇은 구간이다. 추가 기록 점이나 새 데이터 원호를 만들지 않는다.
- 맥락은 한 화면에 최대 4조건이며 생략 수를 표시한다. 조밀한 맥락은 같은 음식 종류 차원에서 페이지로 이동한다. 경험 조밀한 fixture는 8메뉴·88기록을 제공한다. 7개 이상 메뉴에서는 기록 수를 오른쪽 선택 목록에 표시하고, 도형 내부에는 선택한 메뉴의 이름만 표시해 글자가 겹치지 않게 한다.
- 변화의 유효한 0은 0, 자료 없음/미응답/보류/연결 미확인은 —와 상태로 표시한다. 비교 불가 시 시간 연결 하이라이트를 만들지 않는다.
- 예시 기간별 값은 fixture의 직접적인 기간 값이다. 하위 구간의 고유 메뉴 수를 합산하는 구현이 없다.

## 공통 대기 이동과 스크롤

경험·감각·취향은 점 ID별 독립적인 12초 주기 위치 함수를 공유한다. 공통 각도 흐름을 제거했으며 각 점은 기준 위치에서 최대 1.87 논리 단위 이내로 움직여 경험의 충돌 여백을 지킨다. 맥락·변화는 점과 선, 레이블을 같은 오프셋으로 움직여 원호 각도와 조건별 비율을 보존한다. 모든 이동은 같은 데이터와 시간에 재현되며 모션 줄이기에는 적용하지 않는다.

Studio의 다섯 카테고리에서 그림 위 아래 방향 스크롤은 진입 되감기, 위 방향 스크롤은 펼치기다. 스크롤하면 일시정지하며 재생 버튼으로 이어간다. 대기 전용 미리보기에서도 스크롤 시 진입 탐색으로 전환한다. 원본 TasteMotion 컴포넌트는 변경하지 않는다.

### 감각 대기 이동 폭 후속 조정

감각만 링 접선 방향 최대 12, 반경 방향 최대 6 논리 단위의 독립 이동으로 확대했다. 경로 진행 속도는 이전의 2배다. 실제 반경별 안전 여백으로 안팎 이동을 제한한다. 진입 타이밍, 비율, 색 토큰, 모션 줄이기, 스크롤 동작은 유지한다. 경험·취향 이동 폭은 변경하지 않았다.

### 감각 드래그 관성 / 점별 속도

감각 링은 드래그로 회전하며 놓는 순간의 각속도에 기존 insightInertia 감속 함수를 적용한다. 좌우 키로 15도씩 회전할 수 있다. 회전은 점 좌표에만 적용해 중앙 글자는 고정한다. 드래그 후 클릭 선택을 억제하고 스크롤 되감기는 관성을 중지한다. 점별 속도는 안정적인 ID 해시로 1·2·3·4배를 배정하며 12초 루프 경계를 유지한다.

### 취향 클릭 정렬 및 농도

취향 링을 클릭하면 기존 push 정렬 함수를 사용해 색별로 모이고, 다시 클릭하면 펼친다. 드래그는 회전으로 구분하며 클릭 선택과 충돌하지 않는다. 정렬 보간은 루프를 넘는 누적 프레임 시간을 사용한다. 점 농도는 원본 insightFrame의 dot.opacity를 사용한다(정착 시 약 45~95%). 색 범주의 비율 및 중앙 실제 평가 수는 유지하며 농도는 평가 강도가 아니다.

실제 웹 검증: 클릭 정렬값 1 → 재클릭 0, 126개 점, opacity 약 0.4500~0.9499 확인. 변경 파일은 Preview.tsx / geometry.ts / 본 문서. 네이티브 실행은 검증하지 않았다.

## 맥락 참고 영상 모션

맥락 기본 모션은 `context.ts`에서 점과 조건별 링으로 구성한다. 진입 1.8초 → 대기 12초 → 수축 1.8초 후 중심의 작은 점으로 모여 반복한다. 통합 미리보기의 맥락 탭에서 전체 흐름, 대기만 반복, 모션 줄이기를 선택할 수 있다. 기존 조건별 n과 응답 비율은 유지하고 점은 구역별 14칸의 비율 눈금으로 사용한다.

`node scripts/render-category-frames.mjs --context`로 22개 상태·단계 프레임을 렌더한다. 상세 변경 파일, 명령/종료 코드 및 미검증 범위는 `CONTEXT-VALIDATION.md`에 기록했다.

### 맥락 점 크기·간격 후속 조정

맥락의 모든 선과 원호를 제거하고 점만으로 조건별 링을 표현한다. 정착 점은 기본 점 링과 같은 반경 9.5(지름 19)다. 링 둘레에 따라 36/45/54/63개 점을 배치하고, 반경을 역산해 각 링의 인접 점 중심 거리를 정확히 26으로 맞춘다(가장자리 여백 7). 대기에는 점마다 간격이 흔들리지 않도록 링별 미세 이동을 사용한다. 진입·수축에서는 점도 함께 커지고 작아진다.

각 응답 구역은 해당 링 점 수의 1/3을 사용한다. 진한 점 비율은 반올림한 조건별 응답 비율이며 정확한 횟수는 조건 선택 패널에 표시한다. 이전의 '원호가 정확한 비율' 설명은 이 점 전용 표현으로 대체한다. 중심 전환 점도 기본 점 크기에 맞췄다.

### 맥락 지그재그 배치

참고 이미지처럼 같은 링의 점을 기준 반경에서 +6 / −6 논리 단위로 번갈아 배치한다. 각 링을 짝수 점 36/48/60/72개로 구성해 이음새에서도 교대가 이어지게 했다. 두 점의 반경이 다른 현 길이를 기준으로 링 반경을 역산하므로 인접 점 중심 간격 26과 기본 점 반경 9.5를 유지한다. 선은 없으며 진입·수축과 데이터 의미는 유지한다. 링별 비율 눈금 수가 달라 반올림 해상도는 다르지만 정확한 응답 수는 조건 선택 패널에서 유지한다. 중앙 문구는 점이 충분히 펼쳐진 뒤 나타난다.

### 맥락 대기 지그재그 반전

대기 중 반경 교대량을 6×cos(2πt/12)로 변화시킨다. 0초 지그재그 A → 3초 원형 → 6초 반대 지그재그 B → 9초 원형 → 12초 A로 연결된다. 기준 링 반경과 점 크기·개수·색은 유지한다. 각 시점에서 같은 링의 인접 점 간격은 균일하며, 원형으로 펴질 때 그 간격이 약간 좁아진다. 모션 줄이기는 A 형태를 고정한다. 수축은 대기 12초가 끝난 A 형태에서 시작하므로 기존 진입·수축을 유지한다.

맥락 지그재그 이동 폭을 ±6에서 ±4 논리 단위로 줄였다. 승인된 링 기준 반경은 기존 배치 계산값으로 고정하고, 점 크기·개수와 12초 주기를 유지한다.

### 맥락 진입을 취향 점 링 방식으로 변경

`context-entry.ts`는 원본의 여섯 방향 증식 배치를 맥락의 가변 점 수에 맞게 구성한다. 취향과 같은 insightFillEnd/insightExpansion 및 1.8초 진입 시간 변환을 사용해 중앙에 점이 늘어나고 잠깐 모인 뒤 정착 링으로 펼쳐진다. 대기의 ±4 지그재그 반전과 수축은 유지한다. 중앙 문구는 펼쳐짐이 충분히 완료된 뒤 표시한다.

변경 파일: context-entry.ts 신규, context.ts, scripts/taste-data-category.test.mjs, 본 문서. 관련 context 테스트 6개 종료 0. 첫 여섯 점, 단계적 생성, 모인 상태, 정착 배치, 중앙 여백, 기존 수축/반복/모션 줄이기 검증을 포함한다.

### 맥락 수축을 피드백 방식으로 변경

피드백의 `feedbackEndDuration = 0.8`과 동일한 smoothstep 감속·층별 시차를 사용한다. 안쪽부터 점의 중심 반경과 불투명도가 함께 줄어들며, 이전 수축의 비틀림은 제거했다. 기본 3층은 약 0.8초, 4층은 약 0.91초에 수축을 마치고 기존 수축 구간의 남은 시간에는 중심 점을 유지한다. 전체 15.6초 반복과 진입·지그재그 대기는 바꾸지 않았다. 중앙 문구는 빠른 수축보다 먼저 사라진다.

변경 파일: context.ts, scripts/taste-data-category.test.mjs, 본 문서. `node --test --test-name-pattern='context' scripts/taste-data-category.test.mjs`: 종료 0, 7개 통과. 실제 feedbackRings의 수축 반경 비율과 맥락의 반경·불투명도가 일치하는지 비교했다. `tsc --noEmit` 및 context.ts eslint도 종료 0. 네이티브 동작은 이번 범위 밖이다.

### 맥락 대기 전환 완화

지그재그 A↔B의 반주기(6초)에 5차 smootherstep을 적용해 양 끝의 속도와 가속도를 0으로 맞췄다. 3초와 9초의 원형은 멈춤 없이 지나가며, 12초 루프 경계도 이어진다. 작은 접선 방향 흔들림을 제거하여 안팎 반경 이동만 남겼다. 이동 폭 ±4, 점 크기·개수·색, 진입 및 피드백 방식 수축은 유지한다.

변경: context.ts, scripts/taste-data-category.test.mjs, 본 문서. `node --test --test-name-pattern='context' scripts/taste-data-category.test.mjs`: 종료 0, 8개 통과. 0/6/12초 방향 전환의 속도·가속도 연속성과 대기 전체 361프레임의 순수 반경 이동을 검증했다.

### 맥락 수축을 진입의 정확한 역재생으로 변경

피드백 방식 수축 계산을 제거하고, 수축 구간의 진입 시간을 1.8초에서 0초로 되돌린다. 진입과 같은 함수에서 점 위치·크기·불투명도·생성 순서·중앙 문구를 계산하므로 정확히 역재생된다. 고정된 목표 링과 12초 지그재그 대기는 유지하며 전체 흐름은 1.8초 진입 / 12초 대기 / 1.8초 수축이다.

변경: context.ts, scripts/taste-data-category.test.mjs, 본 문서. `node --test --test-name-pattern='context' scripts/taste-data-category.test.mjs` 종료 0, 8개 통과. 기본·조밀·단일·빈 데이터에서 55개 진입 프레임과 반대편 수축 프레임의 좌표·크기·색·농도·중앙 문구를 비교했다. `tsc --noEmit` 및 context.ts eslint 종료 0. 네이티브 변경 없음.

## 변화 모션을 맥락과 통일

`change.ts`는 실제 이전·최근 지표와 공통 상한을 계산하고, `context.ts`의 순수 `dotRingMotion`을 맥락과 공유한다. 데이터 의미를 섞지 않고 점 크기·배치·진입·대기·역재생 수축을 동일하게 유지한다. 기본 두 층은 36/48개 비율 눈금이며 실제 평가/식사 수와 동일하지 않다.

통합 미리보기의 변화 탭에서도 전체 흐름과 대기 반복을 선택한다. 감소·동일·이전 미확인 예시를 선택할 수 있다. 자료 없음/해석 보류/미응답은 점 없이 표시하고, 한 기간만 미확인이면 그 층은 회색으로 구분하며 움직임을 멈춘다. 유효 0은 해당 기간 색의 틴트 점으로 표시한다.

렌더 명령: `node scripts/render-category-frames.mjs --change`. 출력: `output/category-motion/change-dots/`. 상세 검증은 `CHANGE-VALIDATION.md`.

2026-09-21 미리보기 컨트롤 수정: Gallery/Preview의 배경 컨테이너는 편집용 AbsoluteFill 대신 같은 레이아웃의 PreviewSurface를 사용한다. 일반 `npm run studio`에서 선택 테두리를 켜 두어도 카테고리·재생 방식·예시 데이터 버튼을 직접 조작할 수 있다. 꽃잎 로고의 편집 가능한 레이어에는 영향을 주지 않는다.

### 맥락·변화 지그재그 범위·속도 후속 조정 · 2026-09-23

현재 구현은 과거의 ±4 / 12초 설정보다 움직임을 분명하게 보이도록 `CONTEXT_ZIGZAG`을 **±6 논리 단위**, `CONTEXT_IDLE`을 **8초**로 사용한다. 따라서 대기 모션은 0초 지그재그 A → 2초 원형 → 4초 반대 지그재그 B → 6초 원형 → 8초 A로 반복한다. 5차 smootherstep의 방향 전환 연속성은 유지한다.

`changeRipples`는 `contextLayers`와 같은 `dotRingMotion`을 공유하므로 동일한 진폭과 속도가 적용된다. `categoryLoopDuration`은 맥락·변화만 8초로 맞추고, 감각의 12초 및 경험·취향의 기존 주기는 변경하지 않았다. 점 크기·개수·색·응답 비율·기간 수치 등 데이터 의미도 변경하지 않았다.
