# TasteBubbleMap · 화면 범위 기반 단일 미각 격자

## 현재 구성

`TasteBubbleMap`은 기본 속도에서 1080×1080, 30fps, 550프레임(약 18.33초)이다. `TasteBubbleMap-Idle`은 14초 루프, `TasteBubbleMap-Reduced`는 3초 정지 버전이다.

기존 72개 표현·좌표·축·intro delay는 네이티브 fixture와 Swift 엔진을 실행해 내보낸 `catalog.ts` / `native-layout.ts`를 사용한다. 원본의 0.72→1 진입은 SwiftUI `.sheet` spring의 120Hz 샘플을 사용하고, 최초 0.18초 white veil과 `.content` fade도 유지한다. 추가 셀은 처음부터 같은 맵에 존재하며 기존 72개의 진입만 별도로 수행한다.

## 단일 격자와 간격

기본 버블 지름 126, 중심 간격 136, 기본 표면 간격 10, 선택 지름 164를 유지한다. `hexPoint(q,r)` / `hexCell()`이 모든 좌표의 유일한 기준이다. 추가 셀은 `(q,r)`로 식별하고 같은 축의 실제 표현을 안정적으로 배정한다. 이 표현의 반복은 BX 시각화이며 별개의 TBA 지식 항목 수를 뜻하지 않는다.

추가 버블을 따로 렌더하거나 별도 배율로 밀지 않는다. 네이티브와 추가 셀 모두 하나의 `bubbles` 배열, 하나의 카메라 변환, 하나의 렌더러, 하나의 간격 보정기를 거친다. 화면 중심 `(q=0,r=0)`은 끝까지 비워두고, 다른 누락 셀은 같은 격자에 채운다.

선택 확대 시 반지름 증가량은 19이다. 여러 선택 버블의 이동량을 단순 합산해 전체 맵이 과하게 벌어지지 않도록 선택 가중치를 정규화한다. 이후 근접 셀끼리 같은 표면 간격 10을 확보하도록 보정한다. 선택 주변은 큰 원이 들어갈 공간만큼 변형될 수 있지만, 기존/추가 여부에 따른 별도 밀어내기 배율은 없다. 선택 해제 후에는 정확한 기본 격자 위치로 복귀한다.

보정은 프레임 독립적이다. 근접 후보는 육각 격자 두 링에서 한 번 구하고 배열 기반으로 처리한다. 동일한 프레임은 탐색 순서나 이전 재생 상태와 무관하게 같은 위치를 만든다.

## 화면 범위와 성능

고정 3,960개(또는 더 큰) atlas 스냅샷을 불러오지 않는다. `buildBubbleGrid(camera,zoom)`이 현재 화면과 약 두 줄의 월드 좌표 여유 영역만 생성한다. 72개와 인접 링은 선택 보정의 안정적인 경계로 유지한다.

확대 상태에서는 전체 약 170~200개 규모의 작은 풀이 사용된다. 전체가 작아지는 마지막 줌아웃에서는 화면 끝까지 채울 만큼 셀을 더 생성한다. 최종 줌 0.134에서는 화면을 가득 채우는 셀만 생성하며, 회전은 적용하지 않는다. 나머지는 화면 밖 여유 셀이다. 최종 정지 상태는 이미 정렬된 격자이므로 충돌 반복 계산을 실행하지 않는다.

추가 셀의 ID, 단어, 색상은 뷰포트 배열 순서가 아니라 좌표에 의해 결정된다. 가속하는 줌아웃에서는 현재 재생 속도에 따른 다음 프레임의 범위까지 미리 생성한다. 카메라와 표시 배율은 현재 프레임 값을 유지하며, 0.5~1.5배 재생에서도 새 셀이 화면 안에서 갑자기 튀어나오지 않는다. 최종 프레임은 맵의 외곽을 보여주는 fit-all 구도가 아니라 연속된 격자의 일부를 사각형으로 잘라 보여주므로 큰 육각형 외곽이 보이지 않는다.

## 모션과 라벨

앞부분은 `간이 잘 맞음 → 맑은 감칠맛 → 버터리함` 선택 흐름을 유지한다. 후반부는 선택 강조 해제 → 맵 중심 이동 → **회전 없이 축소·줌아웃 → 화면을 가득 채운 전체 격자 정지 → 진입 모션을 빠르게 역재생하듯 바깥부터 제자리에서 소멸 → 빈 배경** 순서다. 꽃잎이나 심볼 윤곽으로 버블을 잘라내는 처리와 그에 따른 페이드는 제거했다.

추가 버블도 처음부터 단어를 표시한다. 기존 72개 단어도 후반부에 페이드하지 않고 카메라 줌과 함께 작아진다. 초반 중심 감쇠와 가장자리 마스크는 공통으로 적용하고, 마지막 전체 보기에서는 해제한다. 추가 단어는 실제 해당 축에 속하는 표현만 사용한다. 중앙 빈 칸에 주황색 등 새 버블은 생성하지 않는다.

## 파일

- `layout.ts`: 기본 데이터, 좌표 변환, 필요한 셀 생성, 정규화된 밀어내기와 공통 간격 보정.
- `motion.ts`: 시간축·선택·중심 이동·줌과 전체 렌더 상태.
- `TasteBubbleMap.tsx`: 모든 버블을 동일하게 그리는 단일 SVG 경로.
- `tba-atlas.ts`: 구 경로 호환용 작은 재수출 파일. 정적 버블 배열은 없다.
- `native-spring.ts`: 실제 SwiftUI spring 샘플.
- `scripts/taste-bubble-map.test.mjs`: 전체 시간축의 간격, 채워짐, 단어·축, 줌/선택 및 결정성 검증.
- `scripts/sync-taste-bubble-atlas.mjs`: 이전 명령 이름을 유지한 화면 범위 점검. 거대한 atlas 파일을 재생성하지 않는다.

```sh
node scripts/export-native-bubble-layout.mjs
node scripts/sync-bubble-map-catalog.mjs
node scripts/sync-taste-bubble-atlas.mjs
node --test scripts/taste-bubble-map.test.mjs
npm run lint
```

정지 프레임 검수와 선택 구간 MP4는 `output/taste-bubble-map/spacing-fix-20260924/`에 저장한다. 네이티브 앱과 다른 Remotion 카테고리 컴포지션은 이 리팩토링에서 수정하지 않는다.

## 현재 축소·소멸 타임라인 (2026-10-28 소스 대조)

시간은 약 1.706초의 네이티브 진입 이후를 기준으로 한다. 12.4~13.6초에 회전 없이 줌아웃을 진행하고 기존 3개 버블의 164→126 크기 복귀도 이 구간 초반에 겹쳐 진행된다. 줌아웃은 끝까지 가속하며 중간 시점에는 전체 축소량의 28.125%를 진행한다. 13.6~14.8초에는 각도 0°의 전체 격자를 완전히 정지한다. 추가 버블은 카메라의 사각형 영역과 다음 프레임에 필요한 셀만 생성하므로 화면 네 모서리까지 채워지고 별도의 심볼 외곽은 나타나지 않는다.

14.8~16.0초에는 외곽부터 안쪽 순서로 버블이 사라진다. 전체 소멸 시간은 **1.2초**지만 각 버블이 실제로 작아지는 시간은 전체의 약 **32%**, 나머지 **68%는 위치별 시작 시차**에 사용한다. 소멸 순서는 기존 72개와 추가 버블을 따로 정규화하지 않고 **맵 중심으로부터의 하나의 전역 반경**으로 계산한다. 따라서 추가 격자의 최외곽 → 추가 격자 안쪽 → 기존 72개 외곽 → 기존 72개 안쪽 순서로 하나의 파도가 이어지며 두 그룹의 외곽이 동시에 사라지지 않는다. 기존 72개의 native intro delay는 동일한 반경대 안에서 순서를 조금 나누는 tie-breaker로만 사용한다. 소멸 중에는 **opacity를 전혀 변경하지 않는다.** 버블과 단어는 끝까지 불투명하며, 각자의 격자 위치에서 단조로운 ease로 **scale 1→0**만 적용되어 작아져 사라진다. 역 spring의 미세한 rebound 때문에 인접 ring의 소멸 순서가 뒤집히지 않도록 scale은 한 방향으로만 감소한다. 16.0~16.6초는 버블 배열 자체를 비워 선택한 배경만 남긴다. 종료 시 흰색 덮개로 화면을 가리지 않는다. 중앙 셀은 생성하지 않으며, 기존 72개와 추가 셀은 같은 크기·격자·축·라벨 경로를 그대로 사용한다.

`finale.ts`는 방향을 고정한 축소와 역방향 소멸을 담당한다. `flowerMembership`, 꽃잎별 마스크 또는 별도의 심볼 레이어는 사용하지 않는다.

과거 검수 산출물은 `output/taste-bubble-map/full-grid-15deg-20260924/`의 PNG 7장, `TasteBubbleMap-FullGrid15-Finale.mp4`, `verification.json`이다. `node scripts/render-bubble-grid-finale.mjs`로 재생성한다.
