# 미니 그래프 모션

2026-10-28 제품 소스 대조: 그룹 막대의 이전 기록 트랙은 공통 비교 색상 토큰을 사용한다. 미확인 히트맵 셀은 제품과 같은 뉴트럴 채움으로 표시하며, 알려진 0의 미각별 연한색과 구분한다. 개별 히트맵과 영역→히트맵 전환에 같은 규칙을 적용한다. 라인과 과거 점은 선 그라데이션을, 현재 점은 제품의 별도 노드 그라데이션을 사용한다. 제품 SVG와의 대조 검사를 유지한다.

Studio의 `Graph-Motion`에는 `TasteGraph-Bar`, `TasteGraph-Line`, `TasteGraph-Area`, `TasteGraph-StackedBar`, `TasteGraph-GroupedBar`, `TasteGraph-Heatmap`, `TasteGraph-Pie`, `TasteGraph-Bubble`, `TasteGraph-Treemap`을 등록한다. 아홉 기본 컴포지션은 1080×1080, 60fps, 300프레임(5초, 프레임 번호 0~299)이다. 전환용 `TasteGraph-Transition`은 히트맵·트리맵·음식 아이콘 버블을 거쳐 파이까지 이어지는 1566프레임(26.1초, 0~1565)이다. 기존 상세·홈·분포 막대와 두 가로 그래프 컴포지션은 제거했다. 카드 모션에서 참조하는 가로 그래프 렌더러·계산·스키마는 공용 코드로 유지한다.

Studio: http://localhost:3110/TasteGraph-Bar

**오버슛 강도 · 2026-10-11 갱신:** 현재 버블 **4%**, 파이·트리맵 **0%**다. 파이·트리맵은 조각당 0.7초의 smootherstep을 사용한다. [Plating Motion](../../../docs/design/motion-system.md#오버슛-강도)에 각 그래프의 기준을 기록했다. 원본 최종 기하·300프레임·등장/퇴장 순서는 유지한다. Remotion 브랜드 연출의 기준이며 제품 웹/iOS의 자동 변경을 뜻하지 않는다. 아래 확인 이력의 파이 2%·4%와 8%·108%는 과거 기록이다.

## 그래프 전환 영상 · 씨앗·막대·캡슐·비교 영역

Studio: http://localhost:3110/TasteGraph-Transition

- 현재 순서는 **4점 라인 → 여섯 배경 씨앗과 진한 노드의 낙하·탄성 → 일곱 막대 → 바닥의 일곱 원 → 진한 노드 낙하·탄성 → 긴 캡슐 → 비교 영역 → 전체 면 채움 → 히트맵 격자 → 1·2·3·4단계 표시 → 셀 병합 → 트리맵 → 세 음식 아이콘 버블 → 파이**이다. 기존 메타볼/거리장 결합은 제거했다.
- 라인은 제품 `MiniLineGraphView`와 공통 라운드 경로를 사용한다. 4개 점을 먼저 확정하고 배경·얇은 선·노드가 같은 고정 경로를 공유한다. 중심선 꺾임 R12, 트랙 12, 현재 노드 지름 12이며 외곽은 x=0…132다. 작은 점은 동일한 경로 거리만큼 전진해 우측 노드에 흡수되고, 배경 스트로크 여섯 조각은 원으로 줄어든다.
- 기존 모션 순서는 유지한다. 시작 빈 구간은 15프레임(0.25초)이다. 라인 진입 15~87, 대기 87~147, 선/점 수렴 147~175, 배경 분할 175~205. 씨앗 낙하·착지 후 한 번의 탄성, 255프레임부터 막대 성장·309프레임 완성을 거친다. 주간 막대는 Figma·웹·iOS 공통으로 **폭 12 × 7 + 간격 8 × 6 = 132**, 양끝 여백 0이다.
- **369~411:** 막대의 x·폭·바닥 y=56을 고정하고 높이를 모두 12로 맞춘다. 0의 낮은 막대는 위로 늘어나고, 높은 막대는 줄어든다. 진한 우측 노드는 399프레임까지 원래 상단 위치에서 기다린다.
- **399~443:** 막대가 원으로 바뀌는 마지막 12프레임(0.2초) 동안 진한 노드의 낙하가 먼저 시작된다. 진한 노드의 두 낙하는 각각 0.41초(60fps에서 24.6프레임)이며 동일한 이차 가속 곡선을 사용한다. 마지막 확장 막대의 영상용 높이는 48px(노드 중심 y=14)로 조정해 기본값의 두 낙하 거리를 36px로 맞춘다. 다른 막대와 0/1 표시는 원본을 유지한다. 배경 씨앗은 기존 중력 0.12, 탄성은 낙하 거리의 8.5%(최대 3.2px)·14프레임 한 번을 유지한다.
- **443~455:** 노드 착지 후 12프레임(0.2초) 기다린다.
- **455~497:** 원들이 하나의 고정된 수평 중심선(x=6…126, y=50) 위에서 각자의 스트로크 구간을 늘린다. 앞선 라인→씨앗 분할의 역방향이며, 둥근 끝이 겹쳐 **132×12 캡슐**이 된다. 원을 찌그러뜨리거나 위쪽 면을 잘라 붙이지 않는다.
- **599~641:** 큰 영역의 네 번째 지점까지 완전히 올라간 뒤 진한 원도 오른쪽 끝 x=132와 바닥을 고정하고 왼쪽으로 늘어나 같은 132×12 캡슐이 된다. 노드는 599프레임까지 원형으로 기다리며, 가로 확장 시간은 42프레임을 유지한다.
- **527~599:** 옅은 캡슐의 네 상단 기준점이 왼쪽부터 **각 18프레임씩(총 1.2초)** 하나씩 움직인다. 개별 `TasteGraph-Area`의 `miniAreaProgress` 완화 곡선을 재사용한다. **641~713:** 큰 영역과 진한 캡슐의 가로 확장이 완성된 뒤 진한 영역도 같은 순서로 움직인다. 두 영역의 높이 변화는 겹치지 않는다. 전환은 12px 캡슐에서 출발하므로 첫 왼쪽 지점도 별도 순서에 포함한다.
- 두 면의 바닥 y=56과 x=0…132를 고정하고, 중간 상단 꺾임 R12·외곽 최대 R6을 매 프레임 같은 공통 원호 규칙으로 계산한다. 진한 원은 낙하 중 `main → tint/20`으로 바뀌고, 착지·탄성부터 캡슐 확장·최종 영역까지 `tint/20`을 유지한다.
- **713~772:** 완성된 비교 영역을 유지한다.
- **773~845:** 큰 영역의 4번 지점을 고정하고 **3 → 2 → 1** 순서로 각 24프레임씩 같은 높이까지 채운다. 기존 R12 굴곡과 R6 외곽을 유지한다. 기본값에서 4번은 최대값이므로 완성 면은 132×56이다. 편집된 값에서는 고정된 4번 높이를 채움 상단으로 사용한다.
- **773~845:** 작은 영역의 높이 변화를 기존 프레임의 역순으로 재생한다. **845~887:** 가로 확장도 역재생해 오른쪽 노드로 수축한다. **887~899:** 노드 중심을 고정한 채 반지름을 0으로 줄인다. 동시에 큰 면의 바깥 모서리를 R6→R2로 줄여 히트맵 셀과 맞춘다. tint/20을 유지한다.
- **911~959:** 꽉 찬 면을 기존 `miniHeatmapGeometry`의 7열×5행 좌표로 분할한다. 내부 간격은 0→2px, 각 셀 모서리는 0→R2로 연속 변화한다. 외곽 둥글기는 노드 소멸 때 완성된 R2를 유지한다. 외곽과 바닥은 고정한다. 이 단계는 tint/80 한 색의 격자 형성만 다루며, 일별 색 단계는 적용하지 않는다.
- **959~971:** 완성 격자를 유지하면서 달력 바깥 4칸을 뉴트럴로 바꾼다. **971~1019:** 기존 `miniHeatmapMotionColor`를 재사용해 모든 칸이 1→2→3→4단계를 함께 거친다. 단계마다 12프레임 전체에 걸쳐 연속 보간하며, 중간 멈춤 없이 각 칸이 자기 목표 단계에서 멈춘다. 기록 0의 연한색과 미확인의 뉴트럴 채움은 구분한다. 셀 위치·크기·R2·간격은 고정한다.
- **1019~1078:** 완성된 히트맵을 1초 유지한다. **1079~1091:** 원래 셀 위치와 R2를 유지하며 기존 히트맵 뉴트럴 컬러로 통일한다. 합체 구간도 이 뉴트럴 컬러를 유지한다. **1091~1127:** 시작 셀 R2에서 최종 트리맵의 캡슐 반경으로 직접 합쳐진다. 중간 R2 블록에서 다시 라운드를 키우는 단계를 두지 않는다. 출발 셀 묶음의 거리장을 평활화해 작은 요철과 V자 홈을 정리한다. 초반에만 이 보정을 부드럽게 적용한 뒤 고정하고, 최종 트리맵의 원본 거리장으로 수렴시킨다. 후반에 윤곽 필터를 해제하지 않아 수축한 면이 다시 부푸는 동작이 없다. 시작 셀 R2와 최종 원본 기하는 유지한다.
- 한식·양식·중식·일식·분식·기타 블록에는 각각 **2·6·12·8·4·3개** 셀이 합쳐진다. **1127~1157:** 완성된 원래 캡슐 형태를 유지하며 미각색으로 바뀐다. **1157~1169:** 숫자가 나타난다. 완성 상태는 실제 `MiniTreemapChart`를 그대로 렌더한다.
- **1169~1228:** 완성 트리맵을 유지한다. **1229~1247:** 쓴맛은 왼쪽 끝, 감칠맛은 위쪽 끝을 고정한 채 긴 축이 짧아져 원이 된다. 단맛은 1247까지 회전 없이 우측 수평으로 짧아져 원이 된 후 **1247~1261**에 오른쪽 버블 위치로 이동한다. 목표 x를 넘지 않고 그 위치에 멈춘다. **1247~1265:** 쓴맛이 y=56 바닥까지 떨어지는 동안 단맛은 구르기를 마치고 **1261~1291**에 위로 튕기며 성장한다. 쓴맛은 **1265~1277**에 같은 자리에서 작은 포물선 튕김을 한 번 더 하고 **1277~1281** 안착 후 **1281~1311**에 성장·상승한다. 감칠맛은 기존 낙하 후 **1277~1307**에 성장·상승한다. 세 성장 구간은 `miniBubbleEnterProgress`를 개별 버블 영상과 공유해 각각 30프레임(0.5초), 최종 지름의 104% 봉우리 뒤 100%로 안착한다. 시작 시각은 각 셀의 앞선 동작에 맞춰 독립적으로 배치한다. 나머지 셀은 1229~1247 동안 중심을 고정하고 지방맛은 좌우, 신맛·짠맛은 상하로 짧아져 원이 된다. 1247~1259에는 원의 지름이 작아져 사라진다. 여섯 셀의 숫자 3·8·18·12·6·4는 모두 1229~1239에 같은 곡선으로 페이드된다.
- 숫자는 원형 전환 초반에 사라지고, 원이 거의 완성될 때 쓴맛=볶음(웍), 단맛=디저트(케이크), 감칠맛=음료/페어링(와인)의 **원본 기본 SVG**가 나타난다. `FoodIcon`에 `animate={false}`를 전달해 케이크 먹기·와인 채움·웍 튕김을 재생하지 않는다. 아이콘의 등장·퇴장 페이드와 원 자체의 모션은 유지한다. **1311~1370:** 원과 아이콘을 1초 고정한다.
- **1371~1380:** 기본 상태의 음식 아이콘이 움직임 없이 페이드된다. **1371~1419:** 기존 원형 버블의 바깥 원호를 유지하면서 파이 각도가 줄어든다. 감칠맛은 12시 경계를 고정하고 반대 경계가 반시계 방향으로 줄며, 단맛·쓴맛은 기존 양쪽 경계 축소와 각도 회전을 유지한다. 도형 전체를 돌리는 회전이나 다른 윤곽으로 찌그러뜨리는 변형은 사용하지 않는다.
- 전환 중 간격은 초반에 부드럽게 생긴다. 180도보다 큰 조각의 중앙쪽 R은 같은 파이 경로의 접선 원호로 계산하며, 반경 하한을 반 간격으로 제한해 안쪽 끝이 원본 중심 간격보다 더 깊게 넘어가지 않게 한다. 파인 부분을 채우는 좌표 보정·추가 레이어·마스크는 없다. 최종 경로는 원본을 그대로 사용한다.
- **1371~1437:** 전환 시작부터 단맛은 아래, 쓴맛은 위로 이동한다. 가로 모임은 기존처럼 1385부터 진행해 초반 원끼리 겹치지 않게 한다. 1437에 **감칠맛 오른쪽·단맛 왼쪽 아래·쓴맛 왼쪽 위**로 정착한다. **1437~1496:** 완성 파이를 1초 유지한다. 개별 `TasteGraph-Pie`의 300프레임 모션과 기본 파이 기하는 유지한다.
- **1497~1551:** 개별 `TasteGraph-Pie`의 `MiniPieGraphView`를 종료 프레임 228부터 그대로 이어 쓴다. 조각은 반시계 순서로 6프레임 간격을 두고 각각 42프레임 동안 원래 중심으로 축소된다. 기존 경로·라운드·클리핑·완화 곡선을 재사용하며, 전체 축소는 54프레임(0.9초)이다. 파이의 중심 위치와 56×56 크기·색은 연결 시점에 유지된다. **1551~1565:** 전환 영상의 빈 끝 구간 15프레임(0.25초) 뒤 종료한다.
- 60fps·1566프레임(26.1초). 빈 라인 입력은 전 구간 빈 화면이다.

### 전환 견본의 데이터 범위

라인은 기존 `[1.2, 2.1, 2.4, 4.5]` 합성 미각 변화 값, 막대는 별도의 `[0, 1, 3, 2, 5, 4, 7]` 합성 요리 기록 수다. 큰 영역 `[4, 6, 7, 10]`·작은 영역 `[2, 2.5, 4, 6.5]`는 기존 비교 영역 견본의 독립 합성 값이며 공통 0축·최댓값을 사용한다. 웹·iOS·Figma 및 영상의 영역 높이는 값 0→0px, 값 1→12px, 1 이상은 `12 + (값−1)/(공통 최댓값−1) × 44`로 계산해 원형 막대와 기준 높이를 맞춘다. 0~1 사이 값은 0~12px로 선형 보간하며, 모든 값이 1 이하면 최대 높이도 12px 이하로 유지한다. 두 면에 같은 척도를 적용한다. 서로 다른 단위의 값을 집계·변환한 것으로 해석하지 않는다. 마지막 확장 막대의 48px 높이는 이 영상에서 두 낙하를 맞추기 위한 표현 보정이며, 제품의 기록 수→높이 계산은 바꾸지 않는다. 히트맵 전환은 기존 31일·목요일 시작 합성 견본의 35개 슬롯과 일별 합성 요리 기록 수를 재사용한다. 단위는 하루의 요리 기록 수이며 0/1/2/3/4개 이상 고정 단계다. 실제 날짜·시간대·계정·백엔드는 연결하지 않은 영상 표본으로, 영역 값에서 일별 기록 수나 색 단계를 만들지 않는다. 실제 계정·날짜·기간은 없는 디자인 영상이며 제품 데이터 계약은 `docs/design/data-component-contract.md`를 따른다. 트리맵은 기존 독립 합성 값 한식 3·양식 8·중식 18·일식 12·분식 6·기타 4를 사용한다. 후속 버블은 그중 쓴맛·단맛·감칠맛 색상의 원본 항목 3·8·18을 그대로 이어받는다. 원의 면적 비율은 3:8:18이며 실제 계정·기간·날짜가 없는 합성 영상이다. 볶음·케이크·와인은 사용자가 선택한 연출 아이콘으로, 해당 분류나 미각의 실제 요리 기록을 추론한 것이 아니다. 35개 시각 타일(날짜 31개와 padding 4개)의 병합 개수는 면적 비율을 근사한 모션 표현이며, 히트맵 날짜를 음식 분류에 배정하거나 원본 기록을 재집계한 것이 아니다.

후속 파이는 개별 파이 견본의 독립 합성 값 18·12·6과 합계 36을 분모로 하는 조각 크기 1/2·1/3·1/6을 재사용한다. 버블의 3·8·18을 같은 분모로 환산하거나 재집계한 값이 아니다. 실제 단위·기간·날짜·시간대·계정이 없는 디자인 전환이며 분류 추론·원본 저장·백엔드 및 제품 웹/iOS/Figma 연결은 이번 요청 범위 밖이다.

- 60fps·300프레임. 셀당 42프레임(0.7초), 기본 시차 6프레임(0.1초). 진입·퇴장은 시작과 끝에서 속도·가속도가 0인 smootherstep(`6t⁵ − 15t⁴ + 10t³`)을 사용해 멈춤까지 부드럽게 연결한다. 6개 셀은 18~48프레임에 순서대로 시작해 90프레임에 모두 완성된다. 210프레임부터 역순으로 수축해 282프레임에 모두 사라진다. 7~12개는 총 지연 폭을 30프레임 안으로 줄인다. 퇴장에는 오버슛이 없다.
- 단위는 분류별 합성 요리 기록 수. 원본 예시의 한식 3·양식 8·중식 18·일식 12·분식 6·기타 4이며, 유효한 양수 합계 51이 면적 구성비의 분모다. 기간·날짜·시간대·실계정이 없는 디자인 견본이다. 이미 집계된 입력을 사용하며 중복 제거·식사일/미래 판정은 수행하지 않는다. 0은 면적이 없고 null·음수·비정상 값은 미확인으로 설명하며 그리지 않는다. 극단적으로 작은 비율의 처리도 원본 기하를 따른다.
- 분류 색상은 한식 3=`bitter`(초록), 중식 18=`umami`(보라)다. 2026-10-12 색 교환을 플레이팅·요약 카드·Figma와 맞췄다. 연결된 버블·파이 전환도 같은 색을 이어받으며 항목별 궤적·타이밍·음식 아이콘은 유지한다.
- Inspector에서 재생·배율·배경·최대 12개 항목을 편집한다. `정지`는 즉시 완성 형태, `진입 후 유지`는 퇴장 생략이다. 입력 원본 값과 완성 상태의 면적 비율은 모션 때문에 변경되지 않는다.
- Remotion 합성 견본 범위다. 제품 저장소·로딩/실패/계정 변경·웹/iOS·Figma 모션 연결은 이 작업에 포함하지 않는다. 제품 적용은 [데이터 컴포넌트 계약](../../../docs/design/data-component-contract.md)을 따른다.

## 막대 데이터 범위

Remotion 전용 합성 모션 견본이며 제품 백엔드 연결 작업이 아니다. 단위는 요리 기록 수, 각 슬롯은 순서대로 하루다. 기본 7일은 특정 실제 달력·계정·시간대를 뜻하지 않는다. 입력은 이미 집계된 비음수 정수로, 중복 제거와 날짜 판정은 제품 집계 계층의 책임이다. 높이는 유효 슬롯의 최댓값을 기준으로 하며 비율·백분율이 아니다. 미확인·미래 슬롯은 null로 넣고 0으로 바꾸지 않는다. 로딩·오류·계정 변경은 이 합성 견본의 상태로 구현하지 않는다.

제품의 실제 계정 경로·기간·날짜·중복 규칙은 `docs/design/data-component-contract.md`를 따른다. 앱·네이티브·Figma에는 이번 모션을 적용하지 않는다.
