# 질문 카드에서 원문 보기 버튼만 나타나는 문제 수정

홈에서 완료 후 남은 질문 전체를 이어서 표시하는 후속 변경은 [홈의 남은 질문 연속 표시](</Users/sinjunho/Desktop/Taste Buddy/output/home-question-continuation/review.md>)에 기록했다.

2026-09-13. 앞선 UI 수정에서 선택지가 없는 경우의 원문 보기 버튼을 남겨둔 것이 원인이었다. 기존 QA는 구조화된 선택 배열이 있는 기록만 사용해 이 경로를 확인하지 못했다.

## 변경

- 오래된 버블·태그 기록은 분석에서 이미 선택 정보를 복원하고 있었지만, 인라인 답변은 저장 배열이 nil이라는 이유만으로 차단했다. 분석과 답변이 같은 `effectiveSelections` 복원을 사용하도록 연결했다.
- 실제 답변을 누르면 해당 식사의 빈 응답만 채운다. 기존 메모·사진·식사 ID·다른 선택과 알 수 없는 ID를 보존한다. 명시적인 빈 배열은 이전 선택으로 복원하지 않는다.
- 홈·나의 입맛·질문 전체보기 모두 `answerableQuestions`를 사용한다. 저장 가능한 선택지가 없는 원문 의미 확인·충돌·새 식사 제안은 답변 카드에 표시하지 않는다. 원문과 분석 대기열은 보존하며 음식 기억/원문 근거에서 수정할 수 있다.
- `PersonalTasteNextQuestionCard`의 원문 보기 대체 버튼 연결을 제거했다. 카드에 실제 선택지가 있는 경우에만 표시한다.
- 저장 형식 복원만으로 원래 감각의 기록 시각을 바꾸지 않는다. 새로 답한 응답에만 새 시각을 사용한다. 레거시 nil 복원 실행 취소와 명시적인 빈 배열 삭제도 구분한다.

## 검증

최종 코드의 `unit-3`: **49개 통과, 실패 0개**, 12.551초, xcodebuild 종료 코드 0. 질문 통합 26개, 질문 저장/해결 18개, 기억 수명주기 5개다. 기존 193개 전체를 다시 실행한 결과는 아니다.

포함한 회귀 사례:

- 레거시 선택지 표시 → 같은 식사에 저장 → 질문 완료 → 실행 취소 후 nil과 질문 복원.
- 명시적 빈 배열, 잘못된 값, 중복/바뀐 출처, 계정 전환, 저장 실패, 이후 편집의 보호.
- 원문 질문·충돌 항목이 섞여도 답변 카드에는 저장 가능한 질문만 포함.
- 알 수 없는 다른 선택과 원문 필드의 보존, 새 답변의 시각과 기존 감각 시각 구분.
- 실행 취소/재시작/삭제/계정 백업과 교정 이력.

초기 `unit-1` 63개와 중간 `unit-2` 49개도 실패 없이 통과했다. 최종 실행은 실행 취소의 레거시 복원과 삭제를 구분하는 마지막 변경을 포함한다.

`ui-build-1.log`의 UI 테스트 빌드가 통과했다. 최초 UI 실행 준비에서 전용 QA 시뮬레이터가 Shutdown 상태여서 러너 설치가 실패했다. 시뮬레이터를 다시 켜고 같은 빌드의 러너를 설치해 화면 검증을 진행했다. 소스나 사용자 기록을 초기화하지 않았다.

`ui-1`은 나의 입맛의 선택지·저장 사례 1개가 통과했고, 홈에서 답변 저장·전체보기 진입 후 첫 카드의 위치 검사에서 실패했다. 실제 캡처에서는 시트 첫 카드가 정상 표시되었지만 테스트가 홈 검색창 기준의 상단 180pt를 적용해 그 카드를 계속 아래로 스크롤하려 했다. 시트에는 120pt 여백을 적용하도록 테스트만 보정했다. 제품 코드는 이 재실행 과정에서 변경하지 않았다. 최종 재실행에서는 전체보기 안의 답변 저장 확인도 추가했다.

최종 `ui-2`: **2개 통과, 실패 0개**, 48.659초, xcodebuild 종료 코드 0. 홈의 레거시 카드에서 세 가지 호감 선택지를 확인하고 저장한 뒤, 기존 질문 전체보기 시트에서 선택지를 펼쳐 다시 저장했다. 나의 입맛에서도 카드 펼침·선택·저장이 통과했다. 원문 보기 대체 버튼이 없는지 함께 검사했다.
