# Taste Buddy 디시 카테고리 아이콘

2026-09-08 · Palate Bloom 색상을 사용하는 평면 SVG 아이콘 19종.

## 파일

- `svg/`: 배경 없는 벡터 원본 19종. viewBox 0 0 128 128.
- `png/`: 동일 벡터에서 내보낸 256×256 RGBA PNG 19종. 실제 투명 알파.
- `overview.png`, `overview.svg`: 전체 아이콘과 32px 크기를 함께 보는 비교 시트.
- `index.html`: 개별 원본 다운로드, 밝고 어두운 배경의 32px 미리보기.
- `manifest.json`: 앱의 기존 카테고리 ID·라벨과 파일 경로를 연결한 매핑.
- `build.mjs`: 벡터 도형 원본과 내보내기·검증 명령. 이 프로젝트 안에서 `node output/design/dish-category-icons/build.mjs`로 재생성.

## 제작 기준

[오늘의집: 디자이너의 감각이 AI를 만나 시스템이 될 때](https://www.bucketplace.com/post/2026-04-24-%EB%94%94%EC%9E%90%EC%9D%B4%EB%84%88%EC%9D%98-%E2%80%98%EA%B0%90%EA%B0%81%E2%80%99%EC%9D%B4-ai%EB%A5%BC-%EB%A7%8C%EB%82%98-%E2%80%98%EC%8B%9C%EC%8A%A4%ED%85%9C%E2%80%99%EC%9D%B4-%EB%90%A0-%EB%95%8C/)에서 설명한 단일 대표 대상, 일정한 구도와 시각적 크기, 불필요한 문자 제거, 투명 배경의 원칙을 적용했다. 사용자가 선택한 평면 스타일에 맞춰 SVG 도형을 직접 제작했으며, PNG는 이 벡터를 그대로 래스터화한 파일이다.

- 한 카테고리에 하나의 대표 대상. 그릇과 그 안의 음식은 한 요리 단위로 표현한다.
- 정면 또는 단면을 읽는 평면 구성. 원근 왜곡·그라데이션·조명·그림자 없음.
- 공통 128 좌표계, 둥근 끝, 넓은 색면, 3~6 단위의 구조선. 최소 8 단위 안전 여백.
- 브랜드 기본색: 오렌지 #FFA826, 옐로 #FCC94D, 라임 #A5D126, 블루 #87A8FF, 모브 #BE87BF, 토프 #A5988E.
- 밝은 부분은 기존 미각 tint surface #FFF7CC, #EAE7E4, #E3EBFF를 사용한다.
- 32px 이상에서 카테고리 라벨과 함께 쓰는 장식 이미지다. 색상은 맛 강도나 선호 값을 표시하지 않는다.

좋은 결과는 라벨과 함께 대표 대상이 읽히고, 32px에서 중요한 형태가 남으며, 가장자리가 잘리지 않는 것이다. 여러 음식의 모음, 떠 있는 식기, 브랜드 문자, 강한 입체감, 복잡한 미세 질감, 무의미한 장식은 피한다.

## 카테고리 연결

현재 `src/constants/dishKindTags.ts`와 `ios/TasteBuddy/Resources/Fixtures/dining-feedback-scenario.json`의 19개 ID와 라벨을 그대로 사용했다. 예를 들어 튀김/크리스피의 대표 형태로 튀김 닭다리를 사용해도 카테고리 자체를 닭다리로 바꾸지 않는다. 전체 매핑과 각 대표 대상은 `manifest.json`에 있다.

## 검증과 적용 범위

19개 카테고리의 개수·순서·ID 일치, SVG의 외부 이미지·스크립트·필터·그라데이션 부재, PNG 디코딩·크기·실제 알파·모서리 투명도·안전 여백·면적을 검사했다. 전체 비교 시트와 32px 렌더를 육안으로 확인하고 콩·구이·튀김의 식별성을 수정했다.

이번 결과는 아이콘 에셋 제작이다. 앱 UI에 연결하지 않았으며, 앱 UI·로직·빌드 설정 변경이 없으므로 앱 빌드는 생략했다. 식당·메뉴 데이터나 취향 계산에도 변경이 없다.
