# Analysis Page Direction Replan

문서 상태: 과거 화면 방향 제안의 참고 기록. **2026-09-06 이후 현재 설계 지침으로 사용하지 않는다.** 당시의 예약·셰프 가이드·다음 식사 중심 우선순위는 [현재 제품 경험 지침](../../src/guidelines/TASTE_BUDDY_PRODUCT_EXPERIENCE_GUIDELINES.md)으로 대체됐다.

현재 분석 화면의 최우선 가치는 사용자의 취향을 이해하고, 정제한 같은 근거에서 다양한 해석·인사이트를 제공하는 것이다. 비슷한 입맛 그룹 연결과 그룹 기반 식당·메뉴 추천은 후속 단계다. 아래의 메뉴 추천 상향 배치, 분석 탭 명칭 변경, 추세 분석 우선순위 하향 제안을 현재 UI 변경 지시로 적용하지 않는다. 아래 본문은 당시 검토 근거를 보존한 것이다.

## 목적

현재 `AnalysisPage`를 서비스 가치에 맞게 다시 정의한다.  
Taste Buddy의 핵심은 "분석" 자체가 아니라, 현재 프로필을 더 잘 맞는 다이닝 경험과 셰프 가이드로 번역하는 것이다.

이 문서는 현재 화면의 문제를 정리하고, 제품 가이드에 맞는 새로운 페이지 역할과 정보 구조를 제안한다.

---

## 1. 서비스 가치 기준

제품 가이드 기준으로 Analysis 성격의 화면은 아래 순서를 따라야 한다.

- 왜 이 프로필이 다이닝을 더 좋게 만드는지
- 지금 어떤 프로필이 형성되어 있는지
- 이 프로필이 예약과 셰프 가이드에 어떻게 쓰이는지
- 식후 피드백을 통해 다음 경험이 어떻게 더 좋아지는지
- 측정이나 하드웨어는 그다음에 보조적으로 다룰 것

핵심 해석은 다음과 같다.

- Taste Buddy는 분석 도구가 아니라 personalized dining service다.
- 결과는 수치가 아니라 action으로 연결되어야 한다.
- 프로필은 static result가 아니라 learning loop 안에 있어야 한다.
- 셰프에게 전달되는 정보는 chef-usable guidance여야 하며, recipe override처럼 보이면 안 된다.

## 2. 현재 Analysis 페이지 진단

### 잘하고 있는 점

- 프로필을 시각적으로 기억하기 쉽게 보여주려는 의도가 있다.
- 실제 메뉴 추천까지 연결하려는 시도가 있다.
- 측정 최신성, 변화 추이, 세부 맛 축 등 데이터 자산은 충분히 확보되어 있다.

### 핵심 문제

1. 페이지의 중심이 "다음 식사에 어떤 변화가 생기는가"가 아니라 "얼마나 많이 분석할 수 있는가"에 가깝다.

- 상단에서 바로 다이닝 효용을 말하기보다 시그니처 타입, 레이더 차트, 세부 분석, 추세 차트가 연속으로 나온다.
- 실제로 서비스 가치와 가장 가까운 "실제 메뉴 추천"은 하단부에 배치되어 있다.

2. 프로필 해석이 actionable guidance보다 decorative type 분류처럼 보일 수 있다.

- `Purist`, `Explorer`, `Curator` 같은 라벨은 인상적이지만, 서비스가 "fun taste quiz"처럼 느껴질 위험이 있다.
- 현재 설명은 감성적으로 읽히지만 예약, 셰프 전달, 다음 식사 변화와 바로 연결되지 않는다.

3. 고급 대시보드형 추세 UI가 MVP 우선순위를 넘어서고 있다.

- 기간 필터, 이전/다음 이동, 맛 축 슬라이드, 드래그, 핀치 줌 등 인터랙션이 매우 많다.
- 이는 "advanced stats" 성격에 가깝고, 현재 제품 가이드에서 우선순위가 높은 영역은 아니다.

4. confidence state가 드러나지 않는다.

- 화면에는 `Starter / Building / Refined` 같은 성숙도 표현이 없다.
- "이 프로필이 얼마나 믿을 만한가", "무엇이 더 쌓이면 좋아지는가"가 명시되지 않는다.

5. recommendation 표현이 다소 정밀 수치처럼 느껴질 수 있다.

- 메뉴 카드의 `% 적합`은 false precision으로 읽힐 가능성이 있다.
- 현재 서비스 포지션은 "가능성이 높은 방향"을 제시하는 것이지, 정답 확률을 제시하는 것이 아니다.

6. 재측정 CTA가 너무 이른 위치에서 전면에 나온다.

- 현재는 프로필 요약 직후 바로 "다시 측정" CTA가 등장한다.
- 이 순서는 서비스가 dining improvement보다 measurement maintenance를 더 먼저 말하는 인상을 줄 수 있다.

7. 하단 탭의 `분석` 명칭 자체가 제품 포지션과 어긋난다.

- 제품 가이드의 권장 IA는 `Home / Profile / Reservations / History` 중심이다.
- 현재 탭의 `분석`은 서비스의 성격을 analytics product처럼 보이게 만들 수 있다.

## 3. 재정의된 페이지 역할

### 새 역할 한 줄 정의

이 페이지는 "현재 프로필을 다음 다이닝 경험으로 번역하는 페이지"여야 한다.

### 사용자가 이 페이지에서 답을 얻어야 하는 질문

1. 내 현재 입맛은 어떤 방향으로 읽히는가?
2. 그래서 다음 식사에서 무엇이 달라지는가?
3. 셰프와 레스토랑에는 어떤 방식으로 전달되는가?
4. 이 프로필은 얼마나 정교하며, 다음에 무엇을 하면 더 좋아지는가?

### 전략적 포지셔닝

- 지금의 `분석 페이지`는 사실상 `프로필 가이드 페이지` 또는 `다이닝 가이드 페이지`에 더 가깝다.
- "분석"은 secondary function으로 내리고, primary meaning은 "translation"으로 바꿔야 한다.

## 4. 권장 정보 구조

### A. Hero: 현재 프로필 해석

상단은 타입명이 아니라 "현재 프로필 요약 + 다이닝 의미 + confidence"를 보여준다.

권장 구성:

- 제목: `현재 프로필`
- confidence badge: `Starter`, `Building`, `Refined`
- 요약 문장: `지금은 신맛과 감칠맛을 비교적 선명하게 읽고, 강한 쓴맛은 천천히 이어질 때 더 편안할 수 있어요.`
- 보조 문장: `이 프로필은 예약과 식후 피드백을 통해 더 정교해집니다.`

이 영역에서 중요한 것은 "정체성 분류"가 아니라 "현재 해석"이다.

### B. Primary Card: 다음 다이닝에서 달라지는 점

현재 화면의 최우선 카드는 레이더 차트가 아니라 reservation personalization이어야 한다.

권장 구성:

- 섹션 제목: `다음 다이닝에 이렇게 반영돼요`
- 예약이 있으면: 특정 레스토랑과 코스 기준으로 반영 포인트 제공
- 예약이 없으면: 다음 예약 시 어떤 기준으로 개인화되는지 generic하게 설명
- CTA: `예약에 반영 보기` 또는 `추천 다이닝 보기`

이 카드는 사용자가 "그래서 지금 이 페이지를 보는 이유"를 바로 이해하게 만들어야 한다.

### C. Chef-Ready Guidance Card

현재 프로필을 셰프 관점 언어로 번역한 섹션을 상단에 배치한다.

권장 구성:

- 제목: `셰프에게는 이렇게 전달돼요`
- 2~3개의 guidance bullet
- 안내 문구: `셰프의 구성을 바꾸라는 뜻이 아니라, 현재 취향이 더 자연스럽게 전달되도록 돕는 참고 정보예요.`

예시:

- 밝은 산미와 깨끗한 마무리가 더 또렷하게 느껴질 수 있어요.
- 단맛은 강하게 밀기보다 균형 안에서 드러날 때 더 자연스러울 수 있어요.
- 풍미가 겹겹이 이어지는 코스는 만족도가 높을 가능성이 있어요.

### D. Evidence: 왜 이렇게 해석했는지

이 영역에서 처음으로 프로필 디테일을 보여준다.  
다만 "분석 카드 모음"이 아니라 interpretation evidence로 보여줘야 한다.

권장 구성:

- `현재 더 또렷한 축`
- `천천히 이어지는 축`
- `최근 달라진 포인트`
- `최근 업데이트`

현재의 `Palate Signature`, `세부 분석`, 일부 `인사이트`는 이 영역으로 통합하는 것이 적절하다.

### E. Learning Loop: 이 프로필이 어떻게 더 좋아지는지

현재 페이지에는 learning loop가 문장으로만 약하게 존재한다.  
이를 독립된 섹션으로 승격해야 한다.

권장 구성:

- 제목: `프로필은 식사를 거치며 정교해져요`
- 현재 단계 설명: `Building profile`
- 다음 단계 조건: `피드백 1회 더 쌓이면 추천 안정도가 높아져요`
- CTA 우선순위:
  - 예약 후라면 `식후 피드백 남기기`
  - 예약 전이라면 `다음 예약 보기`
  - 측정이 오래되었다면 secondary로 `현재 컨디션 다시 측정`

### F. Deep Dive: 세부 분석은 접어서 제공

레이더 차트, 추세 그래프, 모든 맛 축의 상세값은 필요는 있지만 primary는 아니다.

권장 방식:

- 섹션 제목: `프로필 디테일 보기`
- 기본은 collapsed
- 열었을 때만 레이더 차트, 맛 축 카드, 추세 차트 노출
- 모바일에서는 핀치 줌이나 드래그보다 단순한 탭/범위 선택 위주로 축소

즉, deep analytics는 제거 대상이 아니라 priority downgrade 대상이다.

## 5. 모듈별 방향 전환

### 현재 `PalateSignatureHeroCard`

유지할 것:

- 상단 요약 카드라는 역할
- taste chip 기반의 빠른 스캔성

바꿀 것:

- 영어 성격 타입 중심 구조
- MBTI처럼 읽히는 라벨
- action보다 identity를 강조하는 카피

대체 방향:

- `현재 프로필 요약 카드`
- `이번 다이닝에서 더 잘 맞는 방향`
- `현재 더 또렷한 포인트 / 천천히 이어지는 포인트 / 최근 업데이트`

### 현재 레이더 차트

유지할 것:

- 현재 프로필을 기억하기 쉬운 visual signature로 보여주는 기능

바꿀 것:

- 상단 1순위 배치
- 비교축을 "민감/평균" 같은 단순 판단으로 강하게 읽히게 하는 방식

대체 방향:

- hero 바로 아래가 아니라 evidence 영역 안으로 이동
- confidence와 interpretation이 함께 붙어 있어야 함

### 현재 실제 메뉴 추천 카드

유지할 것:

- 실제 메뉴와 레스토랑을 보여주는 기능
- 추천 이유 텍스트

바꿀 것:

- `% 적합` 수치 중심 표기
- 하단 늦은 배치

대체 방향:

- `이번 프로필에 잘 맞을 가능성이 높은 메뉴`
- 적합도는 `높음 / 좋음 / 탐색 추천` 같은 label 기반
- 예약 맥락이 있으면 메뉴보다 "예약 반영 결과"가 먼저, 메뉴는 그 아래

### 현재 인사이트 카드

유지할 것:

- 짧은 문장으로 핵심을 전달하는 구조

바꿀 것:

- generic한 반복 문장
- 다음 행동과 연결되지 않는 독립 카드 나열

대체 방향:

- `이번 예약에 반영되는 이유`
- `다음 피드백에서 확인할 포인트`
- `최근 달라진 신호`

## 6. 권장 화면 흐름

### 추천 흐름

1. 현재 프로필 요약
2. 다음 다이닝에서 달라지는 점
3. 셰프에게 전달되는 가이드
4. 왜 이렇게 해석했는지
5. 프로필이 더 좋아지는 방법
6. 프로필 디테일 보기

### 간단한 와이어프레임

```text
[현재 프로필]
Building Profile
지금은 신맛과 감칠맛이 더 또렷하게 읽히고...

[다음 다이닝에 이렇게 반영돼요]
라연 디너 예약
- 클린한 피니시 중심 코스가 더 자연스럽게 맞을 가능성
- 단맛은 강도보다 균형 쪽으로 반영

[셰프에게는 이렇게 전달돼요]
- 밝은 산미가 더 선명하게 읽힐 수 있음
- 무거운 단맛은 과하게 밀지 않는 편이 자연스러움

[왜 이렇게 해석했는지]
현재 더 또렷한 축: 신맛, 감칠맛
천천히 이어지는 축: 쓴맛
최근 변화: 단맛 반응 완화

[프로필은 식사를 거치며 정교해져요]
피드백 1회 더 쌓이면 추천 안정도가 높아져요

[프로필 디테일 보기]
레이더 차트 / 추세 / 세부 맛 축
```

## 7. 상태별 설계

### Starter Profile

- 과한 해석보다 "시작 프로필"이라는 점을 분명히 보여준다.
- 추천은 broad guidance 수준으로 제한한다.
- CTA 우선순위는 `첫 예약`, `첫 식후 피드백`이다.

### Building Profile

- 최근 식사와 피드백이 반영되며 더 정교해지는 상태로 설명한다.
- 최근 변화 포인트를 보여주기 좋다.

### Refined Profile

- 더 안정적인 chef-ready guidance를 제공한다.
- 다이닝 추천 범위를 세분화할 수 있다.

### 예약 없음

- `다음 예약에서 이렇게 활용돼요`로 generic guidance 제공
- 추천 레스토랑/코스 탐색으로 연결

### 피드백 없음

- `식후 피드백을 남기면 다음 추천 정확도가 높아져요`
- admin task가 아니라 next experience improvement로 표현

## 8. 네이밍 제안

우선순위 제안:

- 탭 이름 `분석` -> `프로필`
- 페이지 이름 `미각 프로필` 유지 또는 `다이닝 가이드`
- 기존 `Profile` 탭은 `내 정보` 또는 `계정` 성격으로 재정리

이유:

- 현재 `AnalysisPage`는 이미 제목이 `미각 프로필`이고, 실질 기능도 profile interpretation에 가깝다.
- `분석`이라는 명칭은 서비스를 dashboard product처럼 오해하게 만들 수 있다.

## 9. 구현 우선순위

### Phase 1. 구조 재배치만으로 빠르게 개선

- 상단에서 재측정 CTA를 내리고, reservation personalization을 올린다.
- `PalateSignatureHeroCard`를 `현재 프로필 요약 카드`로 교체한다.
- `실제 메뉴 추천`을 상단 action 영역으로 이동한다.
- confidence badge를 추가한다.
- `% 적합`을 label 기반 표현으로 바꾼다.

### Phase 2. 메시지 품질 고도화

- chef-ready guidance 모듈 추가

## 10. 바로 활용할 수 있는 결론

현재 Analysis 페이지는 버릴 화면이 아니다.  
다만 중심축을 "분석"에서 "번역"으로 옮겨야 한다.

정리하면:

- hero는 type이 아니라 current profile interpretation이어야 한다.
- 첫 번째 핵심 섹션은 세부 분석이 아니라 다음 다이닝 반영 결과여야 한다.
- 셰프 가이드는 별도 모듈로 명확하게 보여줘야 한다.
- learning loop와 confidence는 반드시 visible해야 한다.
- 레이더 차트와 추세는 secondary 정보로 내리는 것이 맞다.

즉, 이 페이지의 새 역할은  
`내 프로필을 설명하는 페이지`가 아니라  
`내 프로필이 다음 식사를 어떻게 더 잘 맞추는지 보여주는 페이지`다.
