# TasteBloomMotion

Taste Buddy의 모션은 **꽃잎이 피고 지는 부드러움, 끝에서 봉우리가 ‘뽕’ 하고 살짝 맺히는 텐션**을 모티브로 한다. 입력에는 빠르게 반응하고, 목표 위치 근처에서 작은 봉우리를 만들고 부드럽게 안착한다.

## iOS에서 참고한 원칙

Apple은 짧고 정확한 피드백, 취소 가능한 전환, 반복 사용을 방해하지 않는 움직임을 권장한다. iOS의 스프링은 제스처와 현재 움직임의 속도를 이어받아 자연스럽게 멈춘다. 이를 TasteBloomMotion의 기반으로 삼는다. ([Motion HIG](https://developer.apple.com/design/human-interface-guidelines/motion), [Animate with springs](https://developer.apple.com/videos/play/wwdc2023/10158/))

## 공통 스프링

Apple `Spring(duration:bounce:)`의 `bounce: 0.18`을 기준으로 같은 감쇠 비율 `0.82`를 공유한다. 아래 역할의 시간은 Apple이 정의한 **체감 시간**이다. Canvas와 시퀀스 종료, 레이어 제거에는 `duration(_:reduceMotion:)`이 반환하는 네이티브 모델의 `settlingDuration`을 사용해 끝의 여운이 끊기지 않게 한다. 아래 시간과 바운스 조합은 Taste Buddy용 조정값이며 iOS 전체의 고정값을 뜻하지 않는다.

- 출발 속도는 0에서 시작한다.
- 정지 상태에서 출발하면 목표를 약 1.1%만 넘었다가 돌아온다. 눈에 띄는 반복 튕김은 만들지 않는다.
- 재입력과 제스처 뒤에는 SwiftUI의 네이티브 스프링이 현재 속도를 이어받는다. 이때의 봉우리는 입력 속도에 따라 달라진다.
- 펼침과 접힘은 같은 곡선 계열을 사용한다. 기존 버튼 중심 블룸은 같은 경로를 역으로 닫는다.
- 헤더의 봉우리 단계 목표 크기는 `1.018`배다.
- 색상·불투명도는 표현 가능한 범위에서 안착한다. 차트는 기록값을 넘지 않도록 제한한다.

SwiftUI의 `Animation.spring`, UIKit의 `UISpringTimingParameters`, Core Animation의 `CASpringAnimation`이 같은 `Spring`의 질량·강성·감쇠를 사용한다. Canvas는 같은 모델의 `value(target:time:)`를 사용한다. UIKit은 `animator(_:animations:)`가 반환한 `UIViewPropertyAnimator`로 실행과 취소를 제어한다. 새 라이브러리나 자체 물리 계산은 사용하지 않는다.

플랫폼마다 미세한 잔여 움직임의 완료 판정은 다르다. UIKit은 반환된 animator의 완료 콜백을 사용하고, 공통 시간값과 종료 시각이 완전히 같다고 가정하지 않는다. 테스트는 UIKit이 완료로 보는 시점에 공통 스프링이 목표에서 0.1% 이내에 도착했는지 확인한다.

## 다섯 역할

| 역할 | 체감 시간 | 적용 대상 | 움직임 |
| --- | ---: | --- | --- |
| `press` | 120ms | 버튼을 누르고 놓기, 짧은 마무리 | 기본 크기에서 0.98배로 눌린 뒤 복귀 |
| `feedback` | 180ms | 선택 표시, 칩, 탭 강조, 토스트 | 색상·테두리·투명도가 짧게 반응 |
| `content` | 300ms | 카드 정리, 단계 이동, 기간 교체 | 작은 요소는 8pt 이동과 페이드, 전체 콘텐츠는 페이드 |
| `sheet` | 500ms | 질문 펼침, 그래프 등장, 커스텀 시트, 뒤 배경, 미각 지도 초점 | 앞뒤 레이어가 함께 움직이고 안착 |
| `bloom` | 720ms | 기록 진입, 결과 카드, 브랜드 심벌 | 버튼 또는 카드 중심으로 꽃잎이 열리는 강조 동작 |

순차 등장의 기본 간격은 60ms다. 미각 버블은 기존 등장 순서를 유지하며 대기 시간을 이 토큰에서 계산한다. 토스트를 읽는 시간, 저장 완료 조건, 검색 대기 시간은 동작 계약이 정한다.

## 새 UI에 적용하기

정의 원본은 [`TasteBloomMotion.swift`](../../ios/TasteBuddy/DesignSystem/TasteBloomMotion.swift)다. 기존 `TBMotion`은 같은 타입의 별칭으로 유지한다. 새 코드에서는 역할 이름을 사용한다.

선택 상태처럼 값이 바뀌는 UI는 변경 대상에 직접 적용한다. `tasteBloomMotion`이 접근성 환경을 읽는다.

```swift
selectionIndicator
    .tasteBloomMotion(.feedback, value: isSelected)
```

펼침·접힘처럼 상태 변경의 범위가 명확한 경우에는 공통 애니메이션을 사용한다.

```swift
@Environment(\.accessibilityReduceMotion) private var reduceMotion

withAnimation(TasteBloomMotion.animation(.content, reduceMotion: reduceMotion)) {
    isExpanded.toggle()
}

if isExpanded {
    answerContent
        .transition(TasteBloomMotion.reveal(reduceMotion: reduceMotion))
}
```

커스텀 시트는 `sheetTransition(reduceMotion:)`과 `sheet` 역할을 함께 사용한다. 닫힐 때도 시트가 뒤 배경보다 앞에 머물게 하고 아래로 내려간다. Canvas는 `progress(_:)`로 스프링을 한 번만 계산한다. 이미 곡선을 계산하는 타임라인의 시계에는 추가 곡선을 적용하지 않는다.

## 적용 규칙

1. 선택·저장·뒤로 가기는 입력 즉시 처리한다. 꽃잎이 펼쳐지는 동안 저장을 기다리게 하지 않는다.
2. 한 동작에서 주인공은 하나다. 작은 선택에는 작은 반응을, 전체 블룸에는 큰 이동을 사용한다.
3. 수치·기록 근거·차트는 실제 값을 보존한다. 증가하는 숫자나 근거가 늘어난 것처럼 보이는 연출을 만들지 않는다.
4. 재입력하면 진행 중인 동작을 취소하거나 현재 상태에서 이어간다. 사라진 화면의 지연 작업은 다음 화면을 바꾸지 않는다.
5. ‘동작 줄이기’에서는 사용자 동작에 따른 확대·이동과 모션 대기 시간을 0으로 한다. 선택·완료 상태는 즉시 표시한다.
6. 손가락을 따라가는 드래그와 스크롤은 직접 추적한다. 손을 놓은 뒤의 안착부터 공통 곡선을 사용한다.
7. 시스템 키보드·기본 네이티브 시트는 플랫폼의 시간을 따른다. 온보딩 일러스트·미각 색상 흐름 같은 반복 콘텐츠는 원래 루프를 유지하고, 그 UI의 등장·누름·화면 전환에 이 규칙을 적용한다.
8. 같은 역할에 새 속도·스프링·곡선을 화면별로 추가하지 않는다. 새 역할이 필요한 경우 먼저 이 표와 원본을 함께 변경한다.

## 현재 iOS 적용 범위

| 영역 | 적용 |
| --- | --- |
| 공용 UI | 버튼, 다음 버튼 활성화, 선택 카드, 선택 칩, 진행 표시, 캡슐 탭 |
| 앱 셸 | 커스텀 시트와 UIKit 뒤 배경, 뒤로 가기 안착, 상단 아이콘 블룸, 탭과 가운데 기록 버튼 |
| 홈·분석 | 질문 답변 펼침, 대기 질문 순차 등장, 목록 정리, 처리 중/결과 교체, 답변·오류 토스트, 그래프 등장 |
| 식사 기록 | 단계 교체, 선택 평가 펼침, 메뉴 삭제·복원, 버블 등장·선택·초점, 결과 카드, 블룸 진입·닫힘 |
| 시작 흐름 | 스플래시, 온보딩 이동, 선호 입력과 감각 설문 전환, 로그인 시트 |
| 필터·검색 | 선택 캡슐의 위치 이동, 추천/결과 없음/결과 목록 사이 페이드, 검색 액션 누름 |
| 식당 상세 | 영업시간·메뉴 확장과 접힘, 펼침 화살표 회전, 북마크 아이콘 교체 |
| 저장·소셜 | 북마크 목록/생성 단계 교체, 커버 색상·아이콘 선택, 목록 추가 표시, 좋아요·팔로우 반응 |
| 프로필 | 설정·버디 찾기·테이스트 리스트 진입 버튼 누름 |

상단 헤더의 스크롤 흐림은 스크롤 위치를 직접 따른다. 모션 적용으로 기록·평가·필터 의미를 변경하지 않는다.

캡슐 필터는 `matchedGeometryEffect`로 선택 배경의 위치를 잇는다. Lucide Canvas 아이콘은 `tasteBloomReplace(value:)`로 이전/다음 모양을 짧게 겹치며 0.9배에서 원래 크기로 교체한다. 이 modifier는 내부 상태가 없는 아이콘에만 사용한다. 화살표는 같은 아이콘을 회전해 펼침 방향을 잇는다. 검색어 자체에는 애니메이션을 연결하지 않고, 검색 콘텐츠의 큰 상태가 바뀔 때만 페이드한다. 숫자와 저장·팔로우 처리 조건은 기존 동작을 유지한다.

질문 답변과 대기 카드는 위쪽 20pt·0.97배에서 제자리로 펼쳐진다. 대기 카드는 60ms 간격으로 등장하며 카드 높이는 `sheet` 스프링으로 늘어난다. 접힘은 지연 없이 `content` 스프링으로 정리한다. 접힌 카드의 60pt 내용 영역과 안내 문구 위치는 유지한다.

레이더는 중앙, 선 그래프는 왼쪽, 막대 그래프는 아래쪽에서 마스크가 열린다. `tasteBloomChartReveal`은 가장 가까운 스크롤 영역에 높이의 15%(최대 40pt)가 보이면 뷰가 유지되는 동안 한 번 실행한다. 수치와 좌표는 최종 데이터 그대로 그리며, 데이터 값에 스프링 오버슈트를 적용하지 않는다. 미각 지도의 기존 버블 순차 등장은 유지한다.

## 확인

`TasteBloomMotion.swift`의 SwiftUI Preview에서 캡슐 이동, 선택, 북마크 아이콘 교체, 펼침과 화살표 회전을 확인할 수 있다. 동작 줄이기는 시뮬레이터나 기기의 접근성 설정으로 확인한다. `TasteBloomMotionTests`는 정지 상태에서 출발하는 스프링의 작은 봉우리와 안착, 정확한 끝 위치, 역할별 시간, 동작 줄이기, 네이티브 스프링과 Canvas의 일치, UIKit 완료를 검사한다.

화면에서 확인할 순서는 질문 펼침·답변 → 식사 기록 단계 → 버블 초점 이동과 중간 재입력 → 결과/블룸 닫힘 → 시트 드래그 → 동작 줄이기다. 빌드·단위 테스트와 실제 기기에서 느끼는 속도 검증은 구분한다.
