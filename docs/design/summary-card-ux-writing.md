## 목적

보조 문구는 **기본 2줄**로 쓴다. **윗줄에는 핵심 값을 보완하는 사실·상태**, **아랫줄에는 그 정보를 해석하는 기준**을 둔다. 각 줄은 필수 정보 한 가지를 담은 짧은 구절로 끝낸다. 제목 바로 아래의 핵심 값·설명과 구분한다. 이전의 ‘반드시 한 줄’ 규칙은 이 기준으로 대체한다.

**미각 변화 카드는 기존 전용 구성을 유지한다.** 일반 보조 문구로 바꾸지 않고 `[상승 화살표 박스 · 미각명 · 상승 수치]`, `[하강 화살표 박스 · 미각명 · 하강 수치]` 두 행을 쓴다. 피그마는 과거 점이 있는 기존 `Content/Chart/MiniLinePaired` 인스턴스를 연결한다. 작은 과거 점은 4px, 현재 점은 12px이며 선과 옅은 미각색 캡슐 트랙의 끝은 둥글게 유지한다. 현재 기본 132 × 63 그래프를 지표 행에 맞춰 132 × 52로 배치하며, 점·선 두께를 확대하지 않고 두 행의 높이만 24pt로 맞춘다. 원본과 카드 안에서 캡 끝이 컨테이너에 잘리지 않게 한다. 비교 부족은 기존 중립 화살표 박스와 빈 비교 트랙을 사용한다.

`[보조 문구 2줄] [스페이싱] [미니 그래프]` 구성에서 **텍스트 블록은 카드 절반 이내**, 각 구절은 해당 폭 안에서 한 줄로 읽히도록 작성한다. 2026-10-08 피그마 요약 카드에 이 기준을 적용했다.

## 윗줄과 아랫줄의 역할

| 위치 | 전달할 정보 | 문구 형태 | 예시 |
| --- | --- | --- | --- |
| 윗줄 | 핵심 값에 없는 보완 수치·확인된 사실·해석을 제한하는 상태 중 하나 | 대상 + 수량 / 사실·상태 명사구 | 요리 기록 18개, 첫 기록 3곳 · 반복 1곳, 직접 남긴 응답, 비교 응답 부족 |
| 아랫줄 | 윗줄과 핵심 값에 적용되는 기간·대상 범위·비교 기준 중 하나 | 기간 / 대상 + 기준 / 비교 기간 + 대비 | 최근 1개월, 전체 기간, 같은 메뉴 기준, 직전 7일 대비 |

윗줄에서는 결과를 읽고, 아랫줄에서는 그 결과가 어느 범위에서 성립하는지 확인한다. 한 문장을 길이에 따라 둘로 끊지 않고 정보 역할에 따라 나눈다. 상태가 값의 해석을 제한하면 윗줄에서 우선 알린다. 아랫줄에는 실제로 확인한 기준만 넣는다.

제목이나 핵심 값에서 이미 전달한 정보는 반복하지 않는다. 추가할 필수 기준이 없으면 아랫줄을 생략할 수 있으며, 두 줄을 채우려고 정보를 추정하거나 같은 말을 반복하지 않는다.

## 필수 규칙

1. **각 줄에 필수 정보 한 가지만 남긴다.** 윗줄은 보완 사실·상태, 아랫줄은 해석 기준으로 역할을 나눈다. 부연 설명·권유·장식적인 표현은 덜어낸다.
2. **제목·핵심 값과 중복하지 않는다.** 이미 표시한 숫자나 분류를 다시 풀어 쓰기보다 빠진 맥락을 보완한다.
3. **각 구절은 한 줄로 끝내고 전체는 기본 2줄로 쓴다.** 카드 절반 이내의 실제 표시 폭으로 판단하고 글자 수를 고정하지 않는다. 윗줄이나 아랫줄이 자동으로 접혀 전체가 3줄 이상이 되면 짧게 다시 쓴다. 줄바꿈은 두 정보의 경계에만 둔다. 글자 축소·영역 확대·말줄임으로 긴 문구를 해결한 것으로 보지 않는다.
4. **설명은 명사구, 상태는 구체적인 상태명으로 쓴다.** `음식 전체 평가`, `최근 1개월 기록`, `비교 응답 부족`처럼 짧고 담백하게 표현한다. 마침표·느낌표·이모지는 붙이지 않는다.
5. **단위·기간·조건의 의미를 지킨다.** 식사와 요리 기록, 감각 강도와 호감, 전체 평가와 부분 평가를 바꾸어 축약하지 않는다. 수량·비율·비교에는 실제 원본과 집계 기준을 사용한다. 짧게 줄여도 뜻이 달라지면 안 된다.
6. **데이터 상태를 사실대로 쓴다.** 조회 중, 확인된 빈 기록, 응답 부족, 미확인, 조회 실패, 이전 결과를 구분한다. 실제 작업이 없는 상태에 `모으는 중`·`분석 중`을 쓰지 않는다. 실패를 `기록 없음`으로 바꾸지 않는다.
7. **행동 안내는 필요한 경우에만 쓴다.** 값을 설명하거나 그래프를 읽는 문구를 일괄적으로 `보기`로 끝내지 않는다. 목적지 탐색이 카드의 역할일 때만 `경험 기록 보기`처럼 실제 탭 동작과 일치시킨다.

## 문구 예시

아래는 작성법을 보여주는 예시이며 실제 계정 데이터나 적용 완료된 제품 문구가 아니다.

| 카드 | 윗줄: 보완 사실·상태 | 아랫줄: 해석 기준 |
| --- | --- | --- |
| 기록한 식사 — 핵심 값에 식사 수 표시 | 요리 기록 18개 | 최근 1개월 |
| 기록한 식당 — 핵심 값에 전체 식당 수 표시 | 첫 기록 3곳 · 반복 1곳 | 전체 기간 |
| 음식 전체 평가 — 핵심 값에 평가 수 표시 | 직접 남긴 응답 | 최근 1개월 |
| 기간별 비교 — 비교 결과를 확정할 수 없음 | 비교 응답 부족 | 최근 7일 |

보완 수치와 기간은 실제 집계에서 확인될 때만 쓴다. ‘처음 기록한’은 **첫 기록**, ‘다시 기록한’은 **반복 기록**으로 통일한다. 제목에서 식당·메뉴를 이미 밝히면 윗줄은 `첫 기록 3곳 · 반복 1곳`처럼 단위만 남긴다. 같은 분류 기준의 구성 비교는 한 줄에 함께 표시할 수 있다. 첫 기록을 실제 첫 방문으로 추정하지 않고, 반복은 같은 식사의 여러 요리 기록이 아닌 독립 식사 기록으로 판별한다.

| 길거나 모호한 표현 | 권장 표현 |
| --- | --- |
| 처음 기록한 식당 3곳 · 다시 기록한 식당 1곳 | 첫 기록 3곳 · 반복 1곳 |
| 처음 기록한 메뉴 5개 · 다시 기록한 메뉴 2개 | 첫 기록 5개 · 반복 2개 |
| 음식 전체에 대해서 남겨주신 평가 | 음식 전체 평가 |
| 최근 한 달 동안 남긴 기록이에요 | 최근 1개월 기록 |
| 아직 비교하기에 충분한 응답이 없어요 | 비교 응답 부족 |
| 데이터가 없어요 — 실제로는 식사일을 모름 | 식사일 미확인 |
| 데이터가 없어요 — 실제로는 조회 실패 | 기록 조회 실패 |

기간은 실제 조회 범위와 일치할 때만 쓴다. `최근 1개월`을 `이번 달`로 바꾸는 식의 의미 변경은 허용하지 않는다. 단순 출현·반복 횟수를 호감이나 선호 변화로 표현하지 않는다.

## 작성 완료 기준

- 제목·핵심 값·그래프에 없는 필요한 맥락을 보완하는가?
- 윗줄은 보완 사실·상태, 아랫줄은 해석 기준을 담았는가?
- 각 줄에 필수 정보 한 가지만 담았는가?
- 카드 절반 이내에서 각 구절이 한 줄로 온전히 들어가고, 전체가 2줄을 넘지 않는가?
- 줄이는 과정에서 단위·기간·부정·조건을 잃지 않았는가?
- 실제 데이터 상태와 탭 동작에 맞는가?

문구만 줄여서 핵심 의미를 보존할 수 없다면 완성된 문구로 보지 않는다. 상세 설명과의 역할을 다시 정하되 요약 카드 자체에서도 값을 오해하지 않아야 한다.

## 그래프별 메인 컴포넌트 나열 — 2026-10-10

[SummaryCard 컴포넌트 섹션](https://www.figma.com/design/HHwQ9suI1czmYEwCQ6wW1W?node-id=1282-14532)에 미니 그래프와 같은 3열 구성을 적용했다. 막대·비교 막대·누적 막대·라인·영역·버블·파이·트리맵·히트맵 9종이며, 기간·계열·표시 방식에 따른 19개 조합을 Light·Dark 총 38개 메인으로 나란히 볼 수 있다.

기존 `Layout=지표/메시지` 기본형의 메인 ID와 속성은 유지했다. 추가 조합은 각자의 문구와 그래프 기본값을 가진 독립 메인이다. Heading·Title·Detail, Indicator·Visualization 교체 및 표시 속성을 연결하고, 자세히보기는 중첩 인스턴스 속성으로 노출했다. 미각 변화 전용 카드는 기존 별도 계열을 유지한다.

기존 사용 예시의 문구·그래프·단위를 재사용했으며 라인 단일·두 계열 조합은 수치 주장을 추가하지 않은 합성 표본이다. 카드 352×119, 텍스트 폭 156, 그래프 슬롯 132×56을 유지한다. 기존 사용 예시 15개와 기본형 연결 보존, 새 인스턴스의 제목 편집·그래프 숨김, Light·Dark 배치와 표시를 확인했다. Figma와 연결 문서만 변경했으며 제품·백엔드 연결 검증은 이번 정리 범위가 아니다. 근거: `output/summary-card-catalog-20261010/`.

## 구분선과 범례 — 2026-10-11

일반 그래프 요약 카드에는 선택적인 하단 범례 영역을 둔다. 그래프가 나타내는 계열·단위만 표시하고, 본문을 다시 설명하는 긴 문단은 넣지 않는다. 미각 변화 전용 카드와 그래프가 없는 미니 카드 등은 별도 계열을 유지한다.

| 요소 | 공통 규격 |
| --- | --- |
| 구분선 | 0.5px/pt · `color/border/subtle` |
| 본문 → 구분선 / 구분선 → 범례 | 각각 `spacing/12` |
| 범례 항목 간격 | `spacing/8` |
| 색 점 → 텍스트 | `spacing/4` |
| 색 점 | 지름 5px/pt · 해당 그래프 계열의 의미색 |
| 범례 텍스트 | Product/Caption · Pretendard Medium 10, line height 14 · `color/text/body` |
| 폭 부족 | 웹/Figma 줄바꿈, 네이티브에서는 맞지 않는 한 줄을 세로 배치로 전환 |
| 범례 없음 | 구분선과 범례를 함께 생략 |

웹의 `SummaryCardLegend` / `SummaryCardFooter`를 `InsightSummaryCard`, 제품 `PeriodCard`, Remotion `HomePeriodInsightCard`가 재사용한다. `legend`는 `{ id?, label, color? }[]`이며 색이 없는 설명은 점 없이 표시한다. 트리맵의 분류 6개는 유지한다. 구분선에 새로운 색을 추가하지 않고 기존 Light `#E8E8E8` / Dark `#333333` 역할을 사용한다. 텍스트는 Light `#666666` / Dark `#B8B8B8`이다.

```tsx
<InsightSummaryCard
  category="experience"
  iconColor={TASTE_TOKENS[series[0].axis ?? 'umami'].palette.main}
  title="출처별 기록"
  legend={series.map(series => ({
    id: series.id,
    label: series.label,
    color: miniStackedBarColor(series.axis),
  }))}
>
  <MiniStackedBarChart series={series} />
</InsightSummaryCard>
```

네이티브의 대응 컴포넌트는 `TBSummaryCardLegend` / `TBSummaryCardFooter`이며 기존 `TasteInsightSummaryCardLayout`과 `HomePeriodInsightCard`에 연결한다. 일반 아카이브 그래프는 기존 `archiveChart.unit`에서 단위를 가져온다. 홈의 날짜별 요리 히트맵 범례는 실제 그래프와 같은 0/1/2/3/4개 이상 색 함수를 사용한다. 로딩·오류로 그래프를 숨기는 기존 조건은 범례에도 동일하게 적용한다.

[Figma 메인 38개](https://www.figma.com/design/HHwQ9suI1czmYEwCQ6wW1W?node-id=1282-14532)와 기존 사용 예시 25개를 갱신했다. 메인의 `Show legend`, 항목별 표시 속성과 중첩 `.Summary/LegendItem`의 Label / Show dot을 편집할 수 있다. 원본 그래프·본문·ID를 보존하고, Figma 카드 높이는 하단 내용에 따라 119에서 157.5로 늘어난다. 빈 상태 2개는 119를 유지한다. 그래프 교체 시 계열 이름·색·표시 항목도 함께 바꾼다.

플레이팅 `/design-system/components/summary-card`에서 1/3/6개 범례의 Light·Dark 실제 컴포넌트를 확인할 수 있다. Remotion은 같은 웹 범례를 사용하며 숫자는 합성 예시다. 제품 집계·원본 저장·계정 범위·날짜·분모·중복 규칙은 변경하지 않는다. 서버/실계정 왕복 검증은 이 표시 변경의 검증 범위에 포함하지 않는다. 근거: `output/summary-card-legend-20261011/`.


## 아이콘 형태와 그래프 미각색 · 2026-10-13

요약 카드의 아이콘 형태는 네이티브의 경험 Globe · 감각 Speech · 취향 Heart · 맥락 Orbit · 변화 RefreshCw를 재사용한다. 취향은 채움 없는 하트다. 아이콘 색은 해당 카드 메인 그래프의 `taste/{axis}/main`을 사용한다. 그래프의 tint 역할은 그대로 유지한다.

웹은 `InsightCategoryIcon.color`에 `PeriodCard.color`, 미각 변화의 첫 대표 그래프 미각, 일반 카드의 명시적인 `iconColor`를 전달한다. Remotion은 `accentAxis`의 main을 전달한다. 네이티브 `TasteInsightSummaryCardLayout`은 첫 `indicatorColors`를 `TDCategoryIcon.color`로 전달한다. 여러 숫자 버블의 메인 미각은 가장 큰 양수 항목의 기존 분류색이다. 메인 그래프가 없는 빈 상태는 기존 분류색을 유지한다. 이 색 선택은 표시 규칙이며 원본 기록·집계·저장 값은 변경하지 않는다.

## iOS 제품 카드 적용 · 2026-10-12

최신 SummaryCard의 본문·구분선·범례 구조를 기존 `HomePeriodInsightCard` / `TasteInsightSummaryCardLayout`에 반영했다. 352pt 카드의 텍스트는 156pt, 시각화는 132×56pt이며 더 좁은 화면에서는 텍스트 폭이 줄고 접근성 글자 크기에서는 세로로 배치한다. 메뉴·식당은 실제 한 번/반복 기록 수의 숫자 버블을 사용한다. 누적 식사 막대, 최근 7일 요리 막대, 월간 날짜별 요리 히트맵은 단위와 기간을 각각 표시한다. 음식 전체 평가의 긴 본문은 직접 응답·전체 기간의 두 줄로 줄이고, 응답별 건수는 범례로 옮겼다.

분석의 미각 변화는 기존 상세 데이터의 비교 가능한 이전/최근 강도를 전용 화살표·라인 행에 연결했다. 합성 예시의 퍼센트나 네 개 점을 복사하지 않는다. 실제 강도 범주를 ‘더 강하게/더 약하게/같은 강도’로 표현하며, 직접 식사와 회상은 다른 척도로 유지한다. 특이사항도 메시지형 카드의 짧은 두 줄과 비교 부족 상태를 사용한다.

현재 호출부별 연결과 제외 이유: [iOS 카드 점검](../../output/ios-summary-graph-20261012/audit.md). 데이터·기간·계정·상태 기준은 [데이터 컴포넌트 연결 계약](data-component-contract.md#ios-요약-카드-연결-복구--2026-10-12)을 따른다. 이 절은 iOS 소스 적용 범위를 설명하며 운영 계정·실기기 검증을 뜻하지 않는다.

## iOS 인사이트 전체 카드 라이팅 · 2026-10-25

적용 대상은 경험·감각·취향·맥락·변화의 측정 카드 19종과 해당 화면의 발견·회상 카드 18종이다. 승인된 현재/수정 비교안에 따라 지표 타이틀에는 대상과 수치를, 보조 문구에는 해석에 필요한 기준과 응답 분포를 남긴다. 카드의 기존 헤더·탭 목적지·계산·대표 항목 선정은 유지한다. 웹과 Figma는 이번 iOS 적용 범위에 포함하지 않는다.

- 횟수는 `식사 12회`, 가짓수는 `메뉴 8개`·`식당 5곳`·`기록한 음식 종류 4가지`처럼 대상과 단위를 함께 쓴다. `첫 기록`은 앱에서 확인 가능한 첫 기록이며, `첫 기록 이후 4회`는 첫 식사를 제외한 반복 횟수다.
- 감각 존재는 `산미 기록 · 식사 8회 중 5회`, 기준은 `감각을 기록한 식사 기준`으로 표시한다. 감각의 존재·강도·호감·알맞음과 요리 전체 평가는 서로 바꾸어 표현하지 않는다.
- 맥락은 음식 종류·부위·시점·강도, 감각명, 평가 종류를 보존한다. 겹치는 식사를 합쳐 전체 식사 수를 만들거나 원인·선호 순위를 새로 주장하지 않는다.
- 변화는 같은 길이의 이전·최근 구간을 유지한다. 비율이 정확히 같은 경우만 `비율 유지`를 쓴다. 반올림으로 0.0%p가 된 작은 차이는 `0.1%p 미만 증가/감소` 등 실제 방향을 남긴다. 원래 분자·분모와 비교 기준은 함께 확인할 수 있어야 한다.
- `전체 N개 항목`은 `감각 N가지`·`부위 N가지` 등 실제 대상 이름으로 바꾸고 본문과 분리한다. 호감·알맞음 변화의 수는 메뉴·감각·기록 조건별 `비교 묶음 N개`이며, 이전·최근 행 수를 항목 수로 세지 않는다.
- 감각을 식별할 수 없는 확인 항목이 포함되면 `표시 항목 N개`로 쓴다. 미분류 이슈 행을 새로운 감각 한 가지로 표현하지 않는다. 유효 관찰이 아직 없는 직접 응답도 있으므로, 빈 감각 집계는 `집계할 감각 기록 없음`, 한쪽 비교 분모 없음은 `이전/최근 비교 자료 부족`으로 표시하며 원본 응답이 없다고 단정하지 않는다.
- 유효 응답과 미응답·확인 필요가 함께 있으면 `식사 N회 응답`으로 유효 응답 수를 명시한다. 확인 항목의 `taste.sour` 같은 내부 ID는 기존 감각 계약의 이름으로 표시한다. 미분류는 감각 이름을 추정하지 않고 `호감 응답 확인 필요`처럼 쓴다. 수치·식사 단위는 렌더링에서 함께 줄바꿈하며 원래 값과 접근성 문구는 보존한다. 분포 범례의 식사 횟수는 `회`, 요리 기록은 `개`로 본문과 표기를 맞춘다.
- 분포의 `여러 강도`·`응답 나뉨`·`미응답`과 확인 필요 건수는 삭제하거나 긍정/보통/부정에 합치지 않는다. 이전·최근 분포는 각각 한 줄을 시작한다. 긴 이름이나 모든 유효 상태가 있는 경우 두 줄 제한에 맞추기 위해 정보를 잘라내지 않으며, 실제 너비에 따라 줄을 늘리거나 그래프를 세로로 배치한다.
- 발견은 `같은 요리`·조건별 분모·정확한 날짜·직접 응답 등의 한계를 보존한다. 기록 간격은 먹지 않은 기간이 아니고, 최근 한 번의 다른 평가는 취향 변화의 확정이 아니다. 알맞음뿐 아니라 부족·과함 분기도 유지한다.
- 알려진 0, 미응답, 응답 확인 필요, 조건 미확인, 비교 불가, 읽기 실패를 구분한다. `아직 발견 없음`은 발견 조건을 만족하지 않았다는 상태이며 자료 부족으로 일괄 대체하지 않는다.

문구 QA는 실제 SwiftUI 카드와 기존 원본 처리 경로를 쓰는 격리된 `--gastronomy-qa` 모드에서 수행한다. `--gastronomy-copy-comprehensive`는 여러 발견 조건을 충족시키는 합성 원본, `--gastronomy-copy-long-labels`는 긴 메뉴·식당명, `--gastronomy-copy-missing`과 `--gastronomy-copy-unresolved`는 미응답·해석 보류 입력을 제공한다. `--gastronomy-copy-unclassified`는 감각을 식별할 수 없는 응답, `--gastronomy-copy-partial`은 유효·미응답·확인 필요가 섞인 입력이다. 카탈로그에 없는 감각 이름을 임의로 유효 응답으로 만들지 않는다. 빈 화면용 기존 `--gastronomy-empty`도 유지한다.

`GastronomyUITests.testCopyAllMeasurementCardsAtDefaultSize`는 측정 19종과 카테고리별 발견의 캡처를 남긴다. `testCopyLongNamesAtAccessibilitySize`는 긴 이름·큰 글자, `testCopyResponseMissingAndUnresolvedRemainDifferentStates`는 미응답·해석 보류·미분류·부분 응답의 구분을 확인한다. 가로 경계 검사는 넘침 탐지이며, 실제 말줄임·줄바꿈 품질은 캡처 검토와 함께 판단한다. 테스트 정의나 합성 원본이 있다는 사실을 실행 성공·실기기·운영 계정 검증으로 간주하지 않는다.
