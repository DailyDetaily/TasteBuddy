# 데이터 컴포넌트 연결 계약

## 나의 입맛 전체 기록 레이더 · 2026-10-25

- 범례는 선택한 미각의 **이전 비율 → 현재 비율**이다. 왼쪽 `이전`은 text/hint 회색 48×24 블록, 오른쪽 `현재`는 text/secondary 밝은 블랙 48×24 블록이며 가운데 24×24 화살표를 유지한다. 정수 반올림 `%`만 표시하고 합집합 식사 수나 6축 평균을 넣지 않는다.
- 초기에는 선택 없이 값은 양쪽 `—`다. 범례 중앙 타이틀은 표시하지 않는다. 노드 또는 미각 라벨을 누르면 해당 축의 비율을 표시하며, 선택한 노드 링과 접근성 설명으로 축을 구분한다. 같은 축을 다시 누르면 해제한다. 이전/현재 분모 0은 각각 `—`, 유효 분모가 있는 실제 0은 `0%`다. 분모·긍정 횟수·혼합 제외 수는 선택한 축의 툴팁/접근성 설명에 둔다.
- 선택은 화면 상태로만 유지하고 원본 집계값을 복사·저장하지 않는다. 저장/수정/삭제/복원 시 같은 축의 최신 비율을 바로 사용하고 계정 전환·로딩·오류로 재진입하면 선택을 초기화한다. 웹 키보드 Enter/Space 및 네이티브 접근성 버튼으로 선택 가능하다.
- Figma 리프레셔 예시는 합성 입력의 신맛 `83% → 86%` 등 축별 값으로 표시하고 선택 전/미측정 상태도 유지한다.

- 화면 순서는 카드 없는 미각 타입 텍스트, 카드 없는 전체 기록 레이더와 라벨 아래 검정/회색 사각형 블록 범례, 미각 변화 카드, 특이사항 카드다. 인사이트·알맞았던 조건·음식 전체와 감각·첫 설문 근거 섹션은 이 화면에서 제외한다. 타입 판정과 미각 변화/특이사항의 기존 계산은 유지한다.
- 현재 계정의 기존 저장소 → 완료 기록의 `SensoryAnalysisEngine`/`buildNativeAnalysis` → 검증된 개인 모델의 직접 호감 근거 → 전체 기록 집계를 사용한다. 새 테이블/API/표시값 저장은 없다. 설문 회상 강도·음식 별점·감각 강도·알맞음을 호감 응답으로 바꾸지 않는다. 미각 6축에 속하지 않는 식감/향을 다른 축으로 추정하지 않는다.
- 단위는 **식사(mealID) × 미각 축**이다. 같은 식사의 여러 요리·부위·응답은 축마다 한 번만 센다. 같은 축의 호감이 나뉘면 혼합으로 남겨 분모에서 제외한다. 각 축의 분모는 긍정/중립/부정 중 하나로 확인된 식사 수, 분자는 긍정 식사 수다. 비율은 선형 0–100%이며 축끼리 합쳐 100%로 만들지 않는다. 분모 0은 미측정, 분모가 있고 긍정 0은 실제 0%다.
- 오른쪽 밝은 블랙 블록의 ‘현재’은 현재 보관된 전체 기간의 유효 응답을 집계한다. 왼쪽 회색 ‘이전’은 가장 최근 유효 호감 식사일보다 앞선 모든 기록을 같은 방식으로 집계한다. 날짜는 확인된 식사일과 기기 현지 달력이며, 같은 날의 기록을 임의 순서로 나누지 않는다. 이전 결과는 현재 원본의 이전 식사일 범위이며 과거 수정 전 상태를 복원한 스냅샷이 아니다.
- 미확인/서로 충돌하는 식사일, 미래 식사일/응답 시각, 미확인 응답, 중복 ID의 충돌은 제외한다. 저장일을 식사일로 대체하지 않는다. 레이더의 기존 육각 그리드·미각 색상·둥근 외곽선·막대·노드·최소 길이 표현을 그대로 유지한다. 미측정의 최소 길이는 기존 표시 규칙이며 원본 값은 null이다. 접근성 값에서는 미측정과 실제 0%를 구분한다.
- 로딩/계정 복원 중에는 값 대신 진행 상태, 읽기 실패에는 오류와 재시도를 표시한다. 기기 보관본/동기화 오류는 기존 계정 상태 안내로 표시한다. 계정 전환 시 이전 분석과 상세를 초기화한다. 원본 저장·수정·삭제·복원은 기존 저장소 이벤트와 분석 재계산을 따른다.
- 웹/iOS는 같은 합성 입력 사례로 계산을 검증한다. Figma의 예시는 명시된 합성 데이터이며 실계정/운영 검증으로 취급하지 않는다.

## 요약 카드 상세 그래프 · 2026-10-25

- 상세 라인에서는 선택한 날짜의 점만 지름 12로 표시하고, 나머지 점은 최신 날짜를 포함해 지름 4로 표시한다. 선택 링은 지름 18·두께 1이며 선택 노드와 같은 미각 그라데이션을 사용해 연한 노드에서는 테두리도 같은 밝기로 맞춘다. 두 라인 비교는 같은 날짜를 함께 선택한다. 초기 선택은 기존의 가장 최근 확인된 날짜를 따른다.
- 선택 전환 시 점과 링의 크기·링의 투명도는 220ms `cubic-bezier(.2,.8,.2,1)`로 보간한다. 데이터 좌표는 움직이지 않으며, 연속 선택은 현재 크기에서 이어진다. 동작 줄이기 설정에서는 즉시 전환한다.

- 상세 라인의 데이터 점(X·Y)은 고정하고, 기존 R 경로의 라운딩 전 가상 꺾임점 높이만 역보정한다. 보정 뒤 두꺼운 트랙과 얇은 선은 동일한 경로를 사용하고 점·선택 링은 실제 좌표에 둔다. 일반 간격에서는 R12를 유지한다. 매우 조밀한 점에서는 수렴 가능한 R로 줄이고, 같은 날짜의 점은 직선으로 연결한다. 미확인 구간은 먼저 나누므로 보정으로 결측을 연결하지 않는다. 기존 미니 그래프 경로와 원본 값·기간·집계·계정 범위는 변경하지 않는다.


- 두 라인 비교는 기존 감각 집계의 최근 8일 상위 미각 중 최대 2개를 선택해 최근 4일을 같은 날짜·선형 0축에 표시한다. 단위는 유효한 존재 응답을 남긴 독립 식사 수이며 같은 식사·미각은 한 번만 센다. 두 계열은 겹칠 수 있어 합계나 비율로 바꾸지 않는다. 현재 계정, 확인 식사일·현지 달력, 중복/충돌/미래 제외와 감각 미관측 null 규칙을 그대로 상속한다. 날짜 선택 시 두 값을 각각 표시한다. 계열이 하나면 한 선과 부족 안내, 없으면 기록 없음으로 표시하며 비교선을 합성하지 않는다. 새 저장값·API·집계 기간은 추가하지 않는다.

- 상세는 현재 계정 저장소 → 기존 검증·집계 → 상세 표시 경로를 그대로 확장한다. `recordChartData` / `TBRecordChartData`, 메뉴 아카이브 집계, 측정 상세의 수치형 분포·비교를 재사용한다. 새 API·테이블·표시값 저장은 없다.
- 기록량의 단위는 요리 기록 수다. 월간 날짜별 기록·출처 구성, 최근 7일/직전 7일 비교·출처 누적, 최근 4일 라인·영역을 유지한다. 감각 영역은 같은 식사·미각을 한 번 센 독립 식사 수이며 겹친 계열을 합산하지 않는다. 날짜는 사용자 확인 식사일과 현지 달력이고 저장일로 대체하지 않는다.
- 메뉴 탐험은 최근 30일의 고유 메뉴, 반복 순위는 전체 기간의 독립 식사 횟수, 만족도는 최근 30일 첫 메뉴 중 최초 식사의 유효 직접 별점 메뉴가 분모다. 4점 이상과 미만의 정확한 건수를 표시하며, 미평가를 낮은 평가로 처리하지 않는다. 기존 정체성·중복·충돌·첫 평가 판정 규칙은 아래 계약을 따른다.
- 상세의 숫자 눈금은 **선형 0축**이다. 미니 그래프의 작은 수치 가독성 보정을 확대해 눈금에 대응시키지 않는다. 비교와 누적은 공통 척도를 쓴다. 버블은 원의 면적으로 건수를 비교하고, 파이는 각 건수/명시 분모를 사용한다. 분포·범주 순위에 날짜 축을 만들지 않는다.
- 큰 플롯에 실제 날짜 또는 범주 이름, 단위, 눈금, 선택 항목의 정확한 값을 제공한다. 선택은 로컬 표시 상태이며 원본에 저장하지 않는다. 데이터·기간이 바뀌면 이전 선택값이 남지 않도록 초기화하거나 현재 데이터에서 다시 해석한다. 포인터 외에 키보드/접근성 선택 경로를 제공한다.
- 미래·미확인 값은 null로 남기고 라인·영역의 결측 구간을 연결하지 않는다. 확인된 0은 기준선에 표시한다. 달력은 날짜 숫자를 제공하며 월 바깥 padding을 선택·집계에서 제외한다. 미래/null의 뉴트럴 채움과 확인된 0의 색 단계를 구분한다.
- 로딩·읽기 실패는 숫자 그래프로 바꾸지 않고 기존 상태·재시도를 유지한다. 기기 보관본/동기화 실패 안내와 계정 변경 시 상세 초기화는 기존 호출부 경계를 따른다. 원본 저장·복원·수정·삭제에 따른 재계산도 기존 경로를 재사용한다.
- 그래프 표식은 기존 미니의 디자인을 따른다. 막대는 연한 `chartTrack` 캡슐과 main 끝점, 이전 비교는 기존 회색 계열이다. 라인은 12pt 트랙·2pt tint/70→main 코어와 둥근 꺾임(트랙·코어·이력점은 같은 R12 경로 공유), 영역은 둥근 R6·불투명 미각 tint 면, 누적 막대는 역순 누적 캡슐이다. 버블·파이는 기존 tint/40과 둥근 분리형 파이 조각을 쓴다. 선택은 가이드·외곽 강조로 추가하며 임의의 전체 계열 투명도로 기존 색 의미를 바꾸지 않는다. 숫자 눈금에 대응하는 높이만 선형으로 계산한다.
- 요약 카드의 132×56 미니 그래프는 유지한다. Figma 및 로컬 시각 검토용 표본은 합성 데이터로 표시하며 제품·운영 계정의 검증 증거로 취급하지 않는다.

## 홈 메뉴 아카이브 3종 — 2026-10-25

- 원본/범위: 현재 계정의 기존 저장소 → 검증된 식사·요리 기록과 직접 별점 → 파생 집계. 새 API·테이블·표시값 저장은 없다. 원본 수정·삭제·복원과 계정 변경마다 재계산한다.
- 새로운 메뉴 탐험: 오늘 포함 최근 30일, 사용자 확인 식사일과 현재 현지 달력 기준. 식당별 메뉴 정체성(직접 만든 요리는 기존 요리 ID)을 한 번씩 센다. 기간 전에 확인된 기록이 있는 메뉴는 ‘기존’, 모든 기록의 날짜가 확인되고 최초 날짜가 기간 안인 메뉴는 ‘첫 기록’이다. 한 메뉴는 한 집합에만 속한다. 같은 메뉴의 날짜 미확인 기록 때문에 첫 여부를 확정할 수 없으면 ‘첫 기록 여부 미확인’으로 별도 표시한다. 저장일로 대체하지 않는다.
- 다시 찾은 한 접시: 전체 기간, 같은 식당의 같은 메뉴를 기록한 서로 다른 mealID 수. 2회 이상 메뉴의 상위 3개를 횟수 내림차순, 동률은 안정적인 메뉴 ID 순서로 표시한다. 같은 식사에서 중복 저장한 요리는 반복을 늘리지 않는다. 날짜 미확인 식사도 전체 기간 반복 횟수에는 참여하며, 반복을 호감으로 해석하지 않는다.
- 새 메뉴 만족도: 최근 30일의 ‘첫 기록’ 메뉴 중 최초 식사에 유효한 0.5~5점 직접 별점이 있는 메뉴가 분모, 4점 이상 메뉴가 분자다. 최초 날짜에 여러 식사가 있어 선후를 알 수 없거나 최초 식사의 여러 기록에 별점 충돌이 있으면 평가 확인 필요로 제외한다. 최초 식사의 미평가·이전 5단계 응답은 새 별점으로 변환하지 않으며 나중 식사의 별점을 끌어오지 않는다. 분모 0은 평가 없음, 분모 > 0/분자 0은 확인된 0%다.
- 공통 결측: 중복·충돌·미래 제외는 기존 검증 계층을 따른다. 메뉴 연결 미확인, 식사일 미확인, 평가 미확인은 별도로 집계한다. 로딩/조회 실패 시 숫자와 그래프를 숨기고 재시도를 제공한다. 오프라인/오래된 계정 보관본은 동기화 상태를 명시한다. 계정 전환 시 다른 계정의 상세·집계가 남지 않는다.
- 표현: 탐험=숫자 버블 2개, 반복=동일 0축 TOP 3 막대, 만족도=절대값 파이(4점 이상 색·4점 미만 뉴트럴). 범례는 각 그래프의 정확한 메뉴 수/식사 횟수/평가 분모를 설명한다. 모든 카드는 해당 집계의 원본으로 연결한다.
- 홈 정리: 누적 식사·메뉴·식당 수는 한 줄로 표시하고 기존 4종 큰 집계 카드는 새 3종으로 교체한다. 기록량은 날짜별 히트맵 한 장으로 통합한다. 최근 기록은 원본 목록으로 표시한다. 새 반복 TOP 3와 같은 메뉴의 단순 반복 발견은 홈 스택에서 중복 노출하지 않되 다른 평가·조건·회상 발견은 유지한다.

## 집계 기준

- 공통 단위는 **요리 기록 수**다. 한 식사의 여러 요리는 각각 센다. 식사 수와 구분해 화면에 표시한다.
- 기존 검증 계층에서 중복 ID를 제거하며, 같은 ID의 서로 다른 원본과 충돌한 식사 전체는 제외한다.
- 확정된 식사일을 현지 달력 날짜로 나눈다. 저장일을 식사일로 대체하지 않는다. 같은 식사의 날짜가 서로 다르거나 하나라도 미확인이면 미확인으로 남긴다.
- 월간 그래프는 이번 달 전체 칸을 만들되 지난날·오늘의 무기록은 0, 아직 오지 않은 날짜는 null이다. 월 바깥 달력 칸은 별도 padding이며 집계하지 않는다.
- 음식 출처는 원본의 homeCooked / restaurant / unknown만 사용한다. 배달·외식 등을 이름이나 식당 유무만으로 추가 추론하지 않는다.
- 계정 전환 시 로딩과 결과를 계정 범위로 제한한다. 조회 중/실패 시 그래프를 0으로 만들지 않고 상태와 재시도를 표시한다.

## 미니 그래프 크기

기본 그래프 영역은 웹·iOS·Figma 모두 132 × 56이다. 요약 카드 텍스트 박스는 핵심값 23 + 간격 4 + 보조 문구 18 × 2 = 63이며, 그래프는 세로 중앙에 배치해 위아래 3.5씩 여백을 둔다. 막대 폭·간격과 0/1 표시 규칙은 유지하고, 라인·영역·히트맵은 새 높이로 좌표를 계산한다. 파이는 56 × 56 원형, 버블은 면적 비율을 유지하며 가로 공간이 부족하면 전체를 균등 축소한다. 집계·단위·기간·계정 범위는 바뀌지 않는다.

2026-10-11 가로 배치: 주간 단일 막대 7칸은 폭 12·간격 8로 132를 채운다. 실제 미각 변화 카드의 라인은 웹·iOS 모두 132 고정이며 두 점 이상의 중심선을 x=6…126에 배치한다. 한 점·기록 대기·빈 비교는 기존 상태 의미를 유지한다. 원본 단위(미각 변화는 계정 프로필 이력, 기록 상세는 요리 기록 수), 기간·확정 날짜와 현지 시간대·분모·중복 제거·미확인/미래 처리·계정 범위와 저장소 경로는 변경하지 않는다. 이 변경은 기존 연결 위의 가로 좌표 표현만 수정한다.

## 미각 영역 겹침·비교

- 단위: 유효한 `presence=present` 관찰을 남긴 **식사 수**. 같은 식사의 같은 미각은 요리·선택·관찰 개수와 관계없이 한 번만 센다. 서로 다른 미각은 한 식사에 함께 있을 수 있어 합산하지 않는다.
- 원본: 기존 계정 스냅샷 → 검증된 `State.observations` / `TDState.observations`. `taste.sweet/sour/bitter/salty/umami`, 지방감은 `mouthfeel.fatty`만 명시적으로 매핑한다. 강도·호감·알맞음은 포함하지 않는다.
- 기간: 확인된 식사일과 로컬 달력. 최근 8일(오늘 포함)에서 기록 수가 큰 상위 3개 미각을 선택하고, 최근 4일을 겹침 표시한다. 비교형은 1위 미각의 최근 4일과 직전 4일을 같은 4개 슬롯에 대응한다.
- 미확인: 날짜 미확인·미래 기록은 기존 검증에서 제외. 식사가 있지만 유효한 감각 존재 관찰이 전혀 없는 날은 `null`; 식사가 없는 날은 기록 횟수 0. 일부 식사만 확인된 경우 확인된 기록만 세고 미관측 식사 수를 함께 표시한다. 감각을 기록하지 않았다는 사실을 감각이 없었다는 응답으로 해석하지 않는다.
- 표현: 공통 0축·공통 최댓값, 누적 없음, 최근 4개 슬롯. null 사이를 연결하지 않는다. 공통 표시 높이로 계산한 사다리꼴 면적이 큰 순서로 뒤에서 그린다. 세 미각은 각각 차트용 tint/20, 같은 미각 비교는 큰 영역 tint/80·작은 영역 차트용 tint/20. 기간별 값과 계열 이름은 범례·접근성 요약으로 제공한다.
- 검증: 공통 척도, 그리기 순서, 교차·미확인 구간, 웹/Swift 좌표 일치, 식사 중복 제거, 미각 관찰과 강도 분리, 저장·복원·날짜 수정·삭제·계정 분리 경로를 확인한다. 운영 계정에서의 검증과 로컬 모의 저장소 검사를 구분한다.

## 요약 카드 범례

범례는 그래프가 이미 사용하는 계열 이름·색·단위를 전달하는 표시 정보다. 기존 계정 원본 → 검증 집계 → 그래프 경로에서 가져오며 새로운 API/테이블/캐시를 만들지 않는다. 단위·기간·식사일과 시간대·분모·중복·미확인/미래 제외 규칙은 위 계약을 그대로 따른다. 미확인 데이터를 별도 합성 계열로 채우거나 실패를 0으로 만들지 않는다.

홈 히트맵은 웹 `buildRecordChartData`, iOS `TBRecordChartData`의 동일한 날짜별 요리 기록을 유지한다. 범례의 0/1/2/3/4개 이상은 집계 결과가 아니라 기존 색 단계의 설명이며 실제 그래프와 같은 색 함수를 호출한다. 로딩·오류·계정 변경에 따라 기존 그래프가 숨겨지면 범례도 숨겨진다. 네이티브 일반 아카이브 카드의 단위는 기존 `HomeArchiveChart.unit`에서 읽는다. 범례가 없는 카드는 구분선도 표시하지 않는다.

공통 표시 규격과 디자인 견본의 범위: [요약 카드 구분선과 범례](summary-card-ux-writing.md#구분선과-범례--2026-10-11).

## 영역의 공통 높이 척도 — 2026-10-11

단일·겹침·비교 영역은 값 0=0px, 값 1=12px, 1 초과의 공통 최댓값=56px를 사용한다. 1 초과 값의 높이는 `12 + (값−1)/(공통 최댓값−1) × 44`; 0~1 사이 값은 0~12px다. 전부 1인 경우 12px, 전부 0인 경우 기존 빈/0 상태를 유지한다. 미확인(null·비정상·음수) 사이를 연결하지 않는다. 같은 입력의 웹·iOS 좌표를 비교하며 Figma/Remotion 견본도 같은 함수를 따른다. 단일은 요리 기록 수, 겹침·비교는 미각 존재를 기록한 식사 수라는 단위 구분과 기존 날짜·중복·계정 범위는 유지한다. 표시 높이는 원본 데이터에 저장하지 않는다.

## iOS 요약 카드 연결 복구 · 2026-10-12

## iOS 아카이브 음식 전체 평가의 별점 연결 · 2026-10-12

현재 계정 원본 → `SensoryAnalysisEngine` → `TDNativeAdapter`의 현재 원본·revision·응답·척도 검증 → `HomeArchiveSources` → 기존 요약 카드와 상세 차트를 사용한다. 직접 남긴 `dining-overall-stars/1`의 0.5~5점 응답은 0.5점 간격의 10개 구간으로 세며, 단위는 완료한 요리 기록의 직접 전체 평가 1개다. 같은 기록 ID는 한 번만 세고 상충·이전 원본·미래에 알려진 관찰·미응답을 별점 0으로 만들지 않는다.

전체 기간 별점 분포는 날짜 순서나 식당별 정체성 비교가 아니므로 식사일·식당 연결 미확인만으로 유효한 별점 응답을 버리지 않는다. 기간을 선택한 상세는 기존 확정 식사일·로컬 달력 필터를 따른다. 메뉴·식당 정체성 및 식사 시계열의 엄격한 확인 규칙은 그대로 유지한다.

## 네이티브 기록 정보 확인 — 2026-10-12

사진만 저장·피드백 완료의 기존 저장 경로 모두 `DiningRecordContext`를 확인한다. 확인된 식사일이나 사용자가 선택한 식당 연결이 없으면 기존 저장 직전에 ‘기록 정보 확인’ 시트를 연다. 사진 촬영일은 후보로만 보존하며, 날짜의 의미를 사용자가 ‘확인한 식사일’로 바꾸기 전에는 집계하지 않는다. 모르는 정보는 명시적으로 나중에 보완하도록 선택할 수 있고, 해당 기간/정체성 집계에서 제외됨을 안내한다.

- 식사일은 `DiningMealTime`의 확인 날짜이며 현지 달력을 사용한다. 저장일을 자동 승격하지 않는다. 같은 `mealID`의 여러 요리는 식사 수에서 한 번만 세고, 날짜 충돌·미확인·미래 제외는 기존 계약을 유지한다.
- 식당 선택은 기존 카카오 장소 검색과 현재 계정의 연결 기록을 재사용한다. 지도 결과의 이름·주소를 보고 선택한 ID를 저장한다. 이름의 일치만으로 다른 지점이나 카탈로그 ID를 자동 연결하지 않는다.
- 지도에 없는 식당은 사용자가 지점까지 명시하고 새 식당으로 연결한 경우에만 독립 식별자를 만든다. 다음 기록에서는 기존 연결 식당을 선택해 동일 정체성을 재사용한다. 차트 수치·비율을 저장하는 API/테이블은 추가하지 않는다.
- 기존 ‘기록 바로잡기’에도 같은 식당 연결 편집기를 제공한다. 장소가 바뀌면 이전 장소의 메뉴 ID를 제거하되 메뉴 이름, 원문, 응답, 사진, 완료 상태는 보존한다. 날짜·연결 변경은 기존 교정 이력, revision, 계정 스냅샷 동기화를 거친다.
- 메뉴/식당 그래프의 분모는 전체 기간에 연결된 고유 메뉴/식당이며, 같은 식사의 여러 요리로 반복 횟수를 늘리지 않는다. 기존 계정 격리·조회 실패·오프라인 상태를 재사용한다. 검색 취소·계정 변경 후의 늦은 응답은 폐기하고 오류를 검색 결과 없음으로 처리하지 않는다.

범위는 iPhone 기록 생성·교정 UI와 기존 공유 원본 필드다. 웹 원본 스키마와 Figma 그래프 정의는 변경하지 않는다. 과거 날짜/식당을 일괄 추측하는 마이그레이션은 추가하지 않는다.

이전 5단계 호감과 새 별점은 같은 척도로 바꾸거나 합치지 않는다. 별점이 있으면 미니 차트는 10구간 별점 분포를 표시하고, 이전 5단계 응답은 원래 문구로 상세의 별도 항목에 남긴다. 별점이 없으면 기존 5단계 분포를 유지한다. 기존 미식 측정 화면의 5단계 계약에 별점을 호감 범주로 주입하지 않는다. 새 API·테이블·저장값은 없으며 변경 범위는 iOS 홈 아카이브·해당 상세·공통 검증 어댑터의 별점 원본 전달이다.

분포 미니 막대는 채워진 각 구간에 main 끝점을 표시한다. 시간 순서를 나타내는 그래프의 마지막 구간 강조 규칙을 평가 분포에 적용하지 않는다. 0구간·1응답의 높이, 공통 최댓값 척도, 132×56 크기와 기존 색 토큰은 유지한다.


## iOS 기록의 식당 상세와 지도 정보 — 2026-10-13

현재 계정의 `DiningEntry` → 명시적으로 선택/확인한 `DiningFoodSource.restaurantPlace`와 `restaurantID` → 기존 `RestaurantDetailRouteView` → Kakao 원본 장소 + 기존 `google-place-enrich` 조회를 사용한다. 직접 만든 음식, 연결 ID가 없는 원본에는 임의의 카탈로그 식당을 대입하지 않는다. 다른 계정, 삭제된 원본, 연결이 바뀐 원본의 상세는 닫고 이전 조회 응답도 폐기한다.

- 단위는 제공자가 식별한 한 지점이다. Google 평점은 해당 장소의 5점 척도이며, 리뷰 수는 Google `userRatingCount`다. 앱의 식사/요리 응답·개인 매칭률·전체 평가와 합산하거나 같은 분모로 해석하지 않는다.
- 시간 범위는 조회 시점에 제공자가 반환한 장소 정보다. 식사 날짜·저장 날짜를 영업시간이나 평점 기준일로 사용하지 않는다. 요일별 영업시간 표시는 기존 현지 달력 표시를 사용하며 임의의 시간이나 휴무를 채우지 않는다.
- 저장하는 추가 정보는 선택한 장소의 ID·제공자 상호·주소·좌표·전화의 연결 참조다. 평점, 리뷰 수, 영업시간, 색 수준은 기록에 저장하지 않는다. 기존 계정 스냅샷과 교정 이력을 사용하며 테이블/마이그레이션을 추가하지 않는다.
- Kakao 보강은 원래 선택한 ID와 동일한 후보만 사용한다. Google은 확인된 Place ID가 있으면 직접 조회하고, 검색 응답은 이름·지점 위치·전화번호로 검증한다. 검색 첫 결과나 같은 주소의 다른 상호를 무조건 연결하지 않는다.
- 로딩, 실패/재시도, 일치 장소 없음, 일치한 장소의 정보 미제공을 구분한다. 값이 없으면 0점·리뷰 0개·24시간 영업으로 표시하지 않는다. 기존 주소가 있어도 Google 조회 실패를 성공으로 표시하지 않는다.
- 확인된 Google Maps URL은 장소 링크로, 일치 장소가 없을 때의 이름/주소 검색 URL은 ‘Google Maps에서 검색’으로 표시한다. 지도 검색을 장소 일치의 증거로 취급하지 않는다.

범위는 iPhone의 기존 기록→식당 상세와 공유 Google 조회 함수다. 웹 원본 타입은 추가 연결 참조를 보존하고 기존 서버 응답 형태는 유지한다. Figma 표본/그래프 계산은 변경하지 않는다. 소스·모의 테스트·실기기 화면·계정 백업 검증을 별도로 기록한다.

## iOS 인사이트 카드 문구 정리 · 2026-10-25

측정 19종과 발견·회상 18종의 지표 타이틀·보조 문구를 정리한다. 기존 현재 계정 원본/스냅샷 → 검증 어댑터 → 집계/발견 → 표시 경로를 유지하며, 표시 문구를 위한 API·테이블·계정 저장값을 추가하지 않는다. 문구 변경으로 발견의 의미 키·읽음·숨김 상태를 초기화하지 않는다. 원본 저장·복원·수정·삭제와 계정 변경에 따른 재계산도 기존 경계를 따른다.

- 단위는 식사 `mealID`, 요리 기록 ID, 연결된 메뉴·식당·명시 음식 분류를 그대로 쓴다. 식사 중복 제거와 상충 원본 제외, 첫 기록/반복 판별, 대표 항목 정렬 및 발견 임계값은 변경하지 않는다.
- 기간은 확인된 식사일과 현재 현지 달력 기준이다. 변화의 기본 최근 90일/직전 90일 및 선택 기간과 같은 일수의 인접 비교 구간을 유지한다. 저장일 대체, 날짜 미확인·미래 기록의 기간 집계 참여는 추가하지 않는다.
- 감각 기록 비율의 분모는 각 기간에 유효한 선택형 감각 존재 응답을 남긴 독립 식사다. 분자는 해당 감각을 기록한 식사이며 같은 식사·감각은 한 번만 센다. 자유 회고/사진, 강도·호감·알맞음은 이 비율을 채우지 않는다. 같은 식사의 여러 감각 비율을 합쳐 100%로 정규화하지 않는다.
- 표시상 `유지`는 원래 분수의 비율이 같은 경우에만 사용한다. 작은 실제 변화가 표시 정밀도에서 0.0%p로 반올림되더라도 변화 없음으로 분류하지 않는다. 한쪽 분모 없음과 응답 기준 불일치는 0%나 유지로 표현하지 않는다.
- 음식 전체의 기존 5단계 평가와 새 별점은 다른 척도다. 감각 강도·호감·알맞음, 혼합 응답·미응답·확인 필요 상태를 합치거나 다른 의미로 바꾸지 않는다. 조건별 겹침·비교 묶음·같은 요리 공존의 근거도 유지한다.
- 로딩·확인된 0·응답 없음·미확인/비교 불가·오류·이전 계정/오래된 결과의 구분은 계속 적용한다. 문구 축약이나 카드 높이 조정으로 중요한 상태를 숨기지 않는다.

이번 적용은 iOS 표시와 관련 문서 범위다. 합성 QA 원본은 격리된 `AppModel.preview`에서만 생성하며 실제 계정이나 운영 데이터에 쓰지 않는다. 소스/단위 테스트, 시뮬레이터 렌더, 실기기와 운영 서버 검증의 증거를 구분한다. 구체적인 문구와 QA 진입점은 [요약 카드 라이팅](summary-card-ux-writing.md#ios-인사이트-전체-카드-라이팅--2026-10-25)에 정리한다.
