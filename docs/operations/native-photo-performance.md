# 네이티브 사진·다이닝 목록 성능 개선

## 문제와 변경

기존 다이닝 화면은 `body`를 갱신할 때 전체 기록을 카드 모델로 변환하며 사진 파일을 동기적으로 읽었다. 일반 `VStack`과 사진 타일의 `UIImage(data:)`도 화면 밖 카드와 원본 크기 이미지까지 준비했다.

- [DiningView.swift](../../ios/TasteBuddy/Features/Dining/DiningView.swift): `LazyVStack` 안에서 기록별 카드를 만들고, 사진은 데이터 대신 파일명을 전달한다. 댓글·옵션·기존 기록의 분석 결과는 유지한다.
- [TBComponents.swift](../../ios/TasteBuddy/Components/TBComponents.swift): 144pt 타일에 화면 배율을 반영한 썸네일을 비동기로 표시한다. 화면 밖으로 나가면 타일의 디코딩된 이미지를 해제하고, 다시 나타나면 캐시 또는 파일에서 읽는다.
- [TasteModels.swift](../../ios/TasteBuddy/Models/TasteModels.swift): ImageIO로 원본 전체 디코딩을 피하면서 최대 1,600픽셀의 JPEG를 만든다. EXIF 회전·미러링을 반영하고 작은 사진을 확대하지 않는다. 사진 변환과 썸네일 파일 읽기는 백그라운드 작업에서 수행한다.

이전 사진 정규화는 `UIGraphicsImageRenderer`의 화면 배율을 그대로 사용했다. 최대 1,600 **포인트**가 @3x 화면에서 최대 4,800픽셀이 되는 문제를 픽셀 기준으로 수정했다. JPEG 품질 값 0.84는 유지한다.

## 메모리와 작업 수명

썸네일 캐시는 디코딩된 픽셀 버퍼 기준 최대 **16MiB 또는 32장**이다. 사용한 지 오래된 항목부터 제거하며 메모리 경고 시 캐시를 비운다. 화면에 표시 중인 이미지와 변환 중 버퍼는 이 캐시 예산과 별개다. 극단적인 파노라마도 썸네일의 최대 변을 1,600픽셀로 제한한다.

사진을 교체할 때는 새로운 파일명을 사용하여 SwiftUI 작업 식별자도 변경한다. 기존 `AppModel.updateDiningEntry`가 이전 파일을 정리한다. 저장·삭제와 진행 중 디코딩이 겹쳐도 이전 캐시 세대의 이미지를 다시 보관하지 않는다.

사진 선택은 시트 최상위에서 한 번만 처리한다. 새 사진 선택, 셔터 입력, 삭제, 카메라 닫기, 시트 종료 시 이전 작업을 취소한다. 완료 결과는 요청 식별자와 현재 선택값을 함께 확인한 뒤 반영하여 늦게 끝난 사진이 새 선택을 덮어쓰지 않게 한다.

## 검증과 측정

Xcode 26.6, iPhone 17 / iOS 26.5 시뮬레이터에서 기존 테스트를 포함한 **140개가 통과**했다. 마지막 작업 순서 보강 후 사진 관련 **12개를 다시 실행해 모두 통과**했으며, 검증 중 소스 파일이 바뀌지 않았음을 확인했다. 다음 두 테스트 파일을 추가했다.

- [DiningPhotoPerformanceTests.swift](../../ios/TasteBuddyTests/DiningPhotoPerformanceTests.swift): 최대 픽셀 크기, 작은 이미지, EXIF 회전·미러링, 잘못된 데이터, 파노라마, 캐시 재사용·교체·삭제·메모리 경고·용량 제한, 취소, 기존 방식 비교.
- [DiningFeedRenderingTests.swift](../../ios/TasteBuddyTests/DiningFeedRenderingTests.swift): 사진 기록 100개에서 첫 화면 주변 사진 영역만 생성되는지, 실제 사진 픽셀이 표시되는지, 스크롤 후 다시 표시되는지, 같은 카드의 사진 교체·삭제와 이전 파일 정리가 정상인지 검증한다.

100개 기록을 넣은 렌더링 테스트에서 최초 사진 영역은 **3개**만 생성되었다. 색상으로 구별되는 테스트 이미지를 화면에 렌더링하여 교체 결과를 확인했다.

2,400×1,800 비교용 이미지 한 장을 같은 테스트에서 변환한 결과:

| 항목 | 기존 @3x 방식 | 개선된 방식 |
| --- | ---: | ---: |
| 출력 픽셀 | 4,800×3,600 | 1,600×1,200 |
| 디코딩 픽셀 버퍼 | 69,120,000바이트 | 7,680,000바이트 |
| 픽셀 버퍼 크기 | 약 65.9MiB | 약 7.3MiB |
| 변환 시간, 최종 단일 실행 | 약 307ms | 약 101ms |

이 입력의 디코딩 버퍼는 **88.9% 감소**했다. 버퍼는 `CGImage.bytesPerRow × height`로 측정했다. 앱 전체 메모리 감소율이나 실기기 평균 처리 시간은 아니다. 시간은 시뮬레이터의 단일 실행 관찰값이며, 테스트 통과 기준으로 사용하지 않는다.

테스트 로그의 `PHOTO_NORMALIZATION_BASELINE`, `PHOTO_NORMALIZATION_RESULT`, `DINING_FEED_VISIBLE_RAILS`에서 같은 측정을 확인할 수 있다. 실제 촬영 장치와 사진 보관함 권한 화면은 자동 테스트 범위에 포함하지 않는다.

이번 변경은 네이티브 사진과 다이닝 목록에 한정한다. 웹 소스가 바뀌지 않아 Vite 빌드는 생략하고 iOS 빌드·테스트로 검증한다.
