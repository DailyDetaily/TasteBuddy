# 기준 음식 회상 설문 v2

2026-09-07 반영. 기존 12문항의 두 구성(salience/overload)을 음식별 강도 회상 6문항으로 바꿨다. iOS SwiftUI, 웹 React, Android Compose에 같은 계약을 적용한다. 라면 물 조절 선호 질문은 포함하지 않는다. 신라면의 물 550mL는 기준 조리 조건이다.

| 축 | 기준 음식 | 기준 조건 |
| --- | --- | --- |
| 단맛 | 빙그레 바나나맛우유 | 일반 240mL, 냉장, 첨가 없음, 첫 모금 |
| 짠맛 | 신라면 국물 | 봉지 120g, 물 550mL, 스프 전량, 4분 30초, 추가 재료 없음 |
| 신맛 | 생오렌지 과육 | 껍질 제거, 첨가 없음; 품종·숙도 차이는 미확인 |
| 쓴맛 | 스타벅스 따뜻한 아메리카노 | Tall 355mL, 기본 원두·샷, 시럽·설탕·우유·추가 샷 없음 |
| 감칠맛 | 생생우동 국물 | 용기 276g, 포장 조리 안내, 추가 양념 없음 |
| 지방맛 | 서울우유 나100% 흰 우유 | 일반 지방 제품 200mL, 냉장, 첨가 없음, 첫 모금 |

최근 3개월의 기억을 묻는다. `0 전혀 느끼지 않음 → 4 매우 강하게 느껴짐`은 순서가 있는 응답 범주다. 음식마다 강도와 혼입 조건이 달라 서로의 민감도 순위를 비교하지 않는다. 좋아함, 부담, 다음에 먹고 싶은 정도를 강도로부터 추정하지 않는다.

지방맛은 지방산에서 비롯되는 미각을 뜻하며 특정 수용체 하나로 한정하지 않는다. 우유는 예비 기준 음식이다. 질감·입안의 기름막·고소한 향·느끼함을 같은 항목으로 바꾸지 않으며, 이 회상 응답의 지방맛 측정 타당성을 검증했다고 표시하지 않는다.

## 저장 계약

- `schemaVersion: 2`, `instrument.version: 2.0.0`, `source: reference-food-recall`을 저장한다.
- 질문 원문, 도움말, 음식 ID·버전·명칭·조건, 척도 문구, 회상 기간, 응답 시점, 실제 응답과 선택한 참고 정보를 같은 제출 객체에 보존한다.
- `selectedValue: 0`은 유효 응답이다. 미응답은 응답 항목 없음, 모름은 `selectedValue: null`과 `uncertaintyReason`으로 보존한다.
- 모름 사유는 `never_tried`, `cannot_recall`, 지방맛에 한해 `cannot_isolate_taste`다. 이를 중립이나 낮은 강도로 채우지 않는다.
- 중복 문항은 마지막 상태를 사용한다. 마지막 값이 무효이면 이전 값을 되살리지 않는다. 이전 12문항 ID와 범위 밖 값은 새 응답에 섞지 않는다.
- 저장된 원문·조건을 최신 카탈로그 문구로 덮어쓰지 않는다. 기존 프로필에는 새 제출 객체가 없어도 복원할 수 있다.

기존 자료형과 연결하는 `snapshot.source`는 `recalled-intensity`다. 0–4 응답을 0–10으로 옮긴 값은 호환용 투영일 뿐이다. 사용자에게 민감도 점수·선호·인구 평균 대비 값으로 보여주거나 실제 식사 관찰로 넣지 않는다. 결과 화면·홈·분석은 같은 원응답을 재사용하며 관찰 수를 늘리지 않는다.

## 플랫폼 연결

- 웹: `src/constants/tasteSurveyItems.ts`, `tasteSurveyConfig.ts`, `src/lib/tasteSurveyEvidence.ts`가 문항과 원응답 계약을 정의한다. 로컬 상태와 Supabase `measurement_sessions.raw_payload.survey_submission`에 보존한다. 회상 응답은 `measurement_results`의 mm·평균 대비 열에 쓰지 않는다. 기존 필수 confidence 열은 0, 원문에는 `confidence_status: not_validated`를 명시한다.
- iOS: 독립 Swift 계약과 `TasteSurveyScoringEngine`이 같은 규칙을 적용한다. `TasteProfile.surveySubmission`을 기존 로컬 저장과 프로필 이력에 보존한다. 현재 프로필은 별도로 저장하고 다음 프로필이 저장될 때 이전 프로필을 이력에 넣는 기존 규칙을 유지한다.
- Android: 독립 Kotlin 계약과 `SurveyScoring`을 사용한다. `TasteProfile.surveySubmission`과 작성 중인 설문 버전을 기존 원자적 로컬 상태 저장에 보존한다. 결과·홈·분석은 `SurveyEvidenceCard`를 사용한다. 기본 생년월일은 선택한 값으로 저장하지 않는다.
- 네이티브 앱의 설문 제출은 현재 로컬 저장 범위다. 웹의 Supabase 저장 경로와 동일한 서버 연동이 네이티브에도 있다고 보장하지 않는다.

Android는 기존 전체 iOS 이식 기준을 유지하고 이번 설문 fixture만 명시적으로 갱신했다. `android/onboarding-survey-reference-update.json`에 이번에 참조한 소스와 해시를 기록한다.

## 검증

- 웹: `npm run build`, `npm test`. 0·미응답·각 모름·중복·구형 ID·원문 보존·저장 복원·이전 TBA 입력 경계 검사와 Supabase 전송 대역을 통한 실제 저장/복원 함수 검사.
- iOS: 앱 빌드, 전체 단위 검사 실행 후 설문 관련 검사와 플랫폼 공통 사례 확인. 시뮬레이터에서 실제 설문 문항과 결과 컴포넌트를 캡처한다.
- Android: `:app:testDebugUnitTest`, `:app:assembleDebug`, 설문·저장 관련 `:app:connectedDebugAndroidTest`. 별도 테스트 에뮬레이터에서 `qaMode`로 실행한다.
- 웹 브라우저 QA는 Supabase 설정을 비운 별도 로컬 포트에서 한다. 검증용 선택을 실제 계정의 기록에 쓰지 않는다.

운영 배포, 운영 DB 저장, 실제 iPhone·Android 기기에서의 검증은 이 작업의 로컬 빌드·시뮬레이터·에뮬레이터 검증과 구분한다.

### 이번 실행 결과

- 웹 빌드와 전체 테스트 통과. 백엔드 설정이 없는 로컬 브라우저에서 실제 온보딩, 0 응답, 세 모름 사유, 검토 화면 수정, 저장, 홈·분석 표시, 새로고침 후 복원을 확인했다. 브라우저 런타임 오류는 관찰되지 않았다.
- Android APK 빌드와 단위 검사 481개 통과. 기기 검사는 두 테스트 환경에서 부팅/시스템 ANR 문제로 완료하지 못했다. APK 설치 성공을 설문 화면 검증 성공으로 해석하지 않는다.
- iOS 앱 및 테스트 빌드 통과. 기존 시뮬레이터의 설문·공통 계약 XCTest 13개가 통과했고, 우유 문항의 실제 렌더를 확인했다. 이후 추가한 소수점 시각 복원은 실제 최신 Swift 계약·엔진과 모델의 비 UI 부분을 분리 실행해 6개 공통 사례 및 프로필 원응답 복원을 검사했다. 새 전용 시뮬레이터는 실행 준비가 완료되지 않아 마지막 XCTest 재실행과 결과 화면 추가 캡처는 완료하지 못했다.
