# TBA 음식별 미각 버블 맵 설계

작성일: 2026-09-05 · 상태: 함께 검토할 어휘·분류·관계의 초안. 앱에 적용하지 않았으며 일반 사용자 검증 전이다.

## 1. 이번 설계의 결과

음식 종류와 특징에 따라 다른 미각 버블 맵을 구성한다. 중앙에는 쉽게 떠올리는 말, 외곽에는 그 느낌을 구체화하거나 비교할 수 있는 말을 둔다. 중앙의 표현 하나만 선택해도 기록을 끝낼 수 있다.

| 항목 | 초안 규모 | 의미 |
| --- | ---: | --- |
| 중복 없는 미각 표현 | 845개 | 직접 작성한 검토 후보. 사용 빈도나 보편성이 검증된 단어 수가 아님 |
| 중앙 표현 | 35개 | 미각·향·식감·자극·온도·복합 인상 전체에서 사용하는 공통 입구 |
| 구체화 표현 | 270개 | 음식과 감각을 더 구체적으로 설명 |
| 세밀한 특징 | 540개 | 부위·시점·질감·향의 차이를 설명 |
| 음식별 기본 맵 | 43개 | 면·구이·중식·발효음식 같은 넓은 맵과 메뉴군별 맵 |
| 맵 하나의 전체 후보 | 90~148개 | 해당 음식군의 넓은 후보 집합. 실제 메뉴 구성으로 가지를 조정하기 전의 수 |
| 표현 묶음 | 45개 | 국물·면·크림·발효·향신료 등 조합 가능한 가지 |
| 명시적 연결 | 822개 | 구체화 관계 810개와 비교·맥락 연결 12개. 사용자 관찰 자체는 아님 |
| 사용자용 디시 종류 태그 | 50개 | 음식 형태·요리 문화·조리 특징이 함께 있는 복수 태그 |

## 2. 디시 종류는 익숙한 복수 태그로 고른다

**면·구이·중식·발효음식을 같은 디시 종류 선택 화면에 둔다.** 사용자가 음식 형태와 요리 문화, 조리 특징을 구분하는 설문을 먼저 풀 필요는 없다. 메뉴를 선택하거나 이름을 입력하면 검토된 이름·구성 규칙으로 근거가 충분한 태그를 자동 선택하고 맵을 준비한다. 사용자는 틀린 태그만 고치며, 하나만 골라도 되고 여러 개를 함께 골라도 된다. 태그 확정은 저장의 필수 조건이 아니다.

자동 선택은 실제 선택 상태에 반영하지만 사용자 확인으로 저장하지 않는다. 이름만으로 알 수 없는 태그는 비워두고 공통 맵을 제공한다. 사용자가 모두 해제한 빈 집합과 아직 자동 분류하지 않은 상태를 구분한다. 입력 중인 음식이 바뀌었거나 버블 선택을 시작한 뒤 도착한 자동 결과로 맵을 조용히 교체하지 않는다. 상세 규칙과 수정 사례는 [메뉴명 자동 선택 설계](./tba-menu-auto-tagging-design.md)를 따른다.

| 선택 예시 | 맵을 구성하는 방향 |
| --- | --- |
| 면 | 면의 식감을 중심으로 국물·소스·향 후보를 넓게 제공 |
| 구이 | 고기·생선·채소의 구운 향과 겉면·속살 차이를 탐색 |
| 중식 | 다양한 중식 경험에서 쓸 수 있는 넓은 후보 맵으로 시작 |
| 발효음식 | 발효향·신맛·감칠맛·질감의 서로 다른 가지를 탐색 |
| 중식 + 면 + 볶음 | 면 식감과 볶은 향·양념의 가지를 중심으로 조합 |
| 일식 + 면 + 발효음식 | 면·국물의 가지에 발효 재료 관련 후보를 추가 |
| 한식 + 구이 + 발효음식 | 구이의 겉면·속살과 장류 관련 후보를 연결 |

`중식`만으로 매운맛·불향·기름기를 확정하지 않는다. 요리 문화는 탐색 입구이며 실제로 느낀 감각의 응답이 아니다. `발효음식`도 신맛을 느꼈다는 뜻으로 바꾸지 않는다.

**종류와 메뉴 이름은 별도 정보로 둔다.** 종류 태그는 `튀김`, 메뉴 이름은 `돈가스`다. `리조또`·`카레`도 메뉴 이름으로 보관한다. 크림소스나 우유 첨가에 맞춘 세부 맵은 버블 조합이며 종류 태그가 아니다. 검토 화면의 맵 선택 목록과 메뉴 예시도 구분한다. 메뉴 이름과 종류를 모두 입력할 필요는 없다.

저장할 때는 태그의 의미를 음식 형태·요리 문화·재료·조리 방식·소스·제공 온도·기록 대상 부위로 구분한다. 이는 맵을 조합하고 잘못된 추론을 막기 위한 내부 정보다. 7단계 입력 화면을 뜻하지 않는다.

## 3. 음식마다 다른 맵을 만드는 방법

43개 맵은 완전히 별개의 사전을 복사한 것이 아니라, 공통 표현 ID와 음식별 가지를 조합한 후보 집합이다. 같은 뜻은 동일한 ID로 비교할 수 있고, 음식 고유의 부위·질감·향은 별도 표현으로 보존한다.

예를 들어 `연어 + 회`는 생해산물과 탄력·매끈함의 가지를, `연어 + 구이`는 생선껍질·속살·구운 향의 가지를, `연어 + 튀김`은 튀김옷·기름기·속살의 가지를 중심으로 구성한다. `크림소스`가 확인되면 크림 가지를 추가한다.

실제 메뉴를 알면 해당하지 않는 가지는 제외한다. 크림 파스타에서는 밥알 가지를 제외하고, 크림 리조또에서는 면 가지를 제외한다. 음식군 목록에 포함됐다는 이유로 모든 메뉴에 모든 부위·재료 표현을 동시에 띄우지 않는다. 재료가 미확인인 가지는 접힌 후보로 남긴다. 사용자에게는 전체 표현을 다시 탐색할 수 있는 경로를 제공한다.

미확인 메뉴의 기본 맵은 공통 미각과 마무리 표현으로 시작한다. 분류를 잘못했어도 고른 표현을 잃지 않고 맵만 수정할 수 있어야 한다.

## 4. 위치와 연결의 의미

### 중앙에서 외곽으로

1. 중앙: `달콤한`, `고소한`, `바삭한`처럼 쉽게 고르는 표현.
2. 중간: `견과류 같은 고소함`, `얇고 바삭한`처럼 구체화한 표현.
3. 외곽: `아몬드 같은 고소함`, `얇게 파삭 부서지는`처럼 더 세밀한 특징.

거리에는 **구체성**을 부여한다. 강도나 만족도에 따라 바깥으로 밀어내지 않는다. 강도·호감·대상·시점은 실제 선택된 말에 명시된 만큼만 따로 해석한다. 더 긴 문장이라는 이유만으로 더 신뢰할 수 있는 응답이 되는 것도 아니다.

### 가까이 있는 이유

| 관계 | 예시 | 해석 규칙 |
| --- | --- | --- |
| 구체화 | 고소한 → 견과류 같은 고소함 → 아몬드 같은 고소함 | 앞의 표현에서 더 세밀한 느낌을 찾는 후보 관계 |
| 비슷한 감각 | 구운 향 ↔ 불향 | 가까운 향을 탐색하지만 동의어로 합치지 않음 |
| 비교 | 쓴맛 ↔ 떫은 느낌 | 다른 감각을 구분할 수 있게 이웃으로 제시 |
| 음식 맥락 | 바삭한 겉면 ↔ 촉촉한 속살 | 함께 나타날 수 있지만 둘 중 하나가 다른 하나를 증명하지 않음 |

노드 간 관계는 먼저 편집자가 작성한 가설로 둔다. 일반 사용자가 실제로 관련 있다고 묶는지, 경로를 따라 원하는 말을 찾는지 확인한 뒤 거리와 연결을 확정한다. 단어가 후기에서 함께 나왔다고 감각 자체가 비슷하다고 단정하지 않는다.

### 6개 주요 축과 확장 감각

단맛·신맛·짠맛·쓴맛·감칠맛·지방감을 주요 탐색 기준으로 유지한다. 향·식감·온도·자극·복합 표현도 같은 맵에서 선택할 수 있다. 6개 축을 모든 감각을 담는 과학적 분류로 주장하지 않는다. 예를 들어 불향을 쓴맛 점수에 넣거나, 부드러움을 지방감으로 자동 변환하지 않는다.

새 맵 안에서 주요 축과 공통 표현의 상대적인 방향은 고정한다. 음식이 달라지면 주변 가지가 달라진다. 부모 표현과 자식 표현이 가까워지도록 배치하고 겹침은 작은 범위에서 조정한다. 화면을 열 때 무작위로 섞지 않으며 사용자 선호도가 높다고 지도 중앙으로 이동시키지 않는다.

## 5. 많은 버블을 가볍게 탐색하기

전체 맵의 90~148개 후보와 첫 화면에서 읽는 라벨 수를 구분한다. 글자를 작게 줄여 전부 읽게 만드는 방식은 피한다. 첫 화면의 라벨도 현재보다 풍부하게 보여주는 것을 목표로 하되, 24~36개 정도를 초기 비교안으로 두고 기기별 읽기·선택 시간을 확인한다. 이 숫자는 확정된 사용성 기준이 아니다.

- 중앙의 짧은 표현은 바로 선택하고 저장할 수 있다.
- 가까운 가지를 펼치거나 확대하면 구체화·세밀한 표현의 라벨이 나타난다.
- 주변의 관련 없는 가지를 지우거나 재정렬하지 않고 위치를 유지한다.
- 문구가 길면 자연스럽게 줄바꿈하고, 읽을 수 있는 크기를 유지한다.
- 선택 직후 세부 질문이나 외곽 탐색을 강제하지 않는다.
- 한 가지를 더 구체화한 응답은 같은 경험 안의 보완으로 기록하며 독립된 취향 증거를 여러 번 만들지 않는다.

대화 안의 관계 검토 화면은 전체 맵의 구조와 한 가지의 세부 표현을 확인하는 도구다. 실제 기록 화면의 전체 라벨 노출·팬·줌·저장 UX를 구현한 제품 화면은 아니다. 전체 보기에서는 중앙 표현과 연결점, 가지 보기에서는 각 표현의 라벨을 보여준다.

## 6. 데이터로 저장할 때

선택된 ID·라벨·정의 버전·음식 맵 ID·디시 태그·제시된 후보·배치 버전·실제 노출 상태·질문과 기록 대상을 보존한다. 인접 노드나 부모 노드를 자동 선택하지 않는다. 보이지 않은 후보와 보고도 고르지 않은 후보를 구분한다.

`고소한`처럼 여러 뜻이 있는 말은 그대로 원문 관찰로 저장하고, 구체적인 감각 의미는 미확정으로 남길 수 있다. `아몬드 같은 향`은 아몬드 재료가 실제 들어갔다는 확인이 아니다. `중식`·`구이` 태그나 음식 사진은 사용자의 호감이나 감각 강도를 대신하지 않는다.

기존 72개 단어의 intensity·rating 변환을 새 어휘에 재사용하지 않는다. 새 정의 버전으로 저장하고 기존 기록은 기존 라벨과 당시 질문을 보존한다. 구체적인 관찰 분해는 [수집·분해·정제 설계](./tba-sensory-data-design.md)를 따른다.

현재 JSON의 `domain`과 `root_id`는 탐색용 분류 후보다. 모든 말의 감각·시간·평가 성분을 정규화한 실행용 의미 사전은 아직 아니다. 따라서 이 값만으로 프로필 벡터나 점수를 갱신하지 않는다.

## 7. 연구 근거와 검증 범위

표현은 직접 작성한 확장 후보다. 블로그와 커뮤니티 전수 조사, 빈도 계산, 일반 사용자 이해도 실험을 수행한 결과로 표시하지 않는다. 근거를 확인한 자료는 다음의 설계 방법과 주의점을 뒷받침한다.

- 한국어 감각어의 20명 대상 FGI 연구는 고소·담백·깔끔 같은 표현에 여러 감각과 평가가 섞일 수 있음을 보여준다. [한국어 감각 표현 연구](https://doi.org/10.7318/KJFC/2016.31.1.096)
- 커피 향미 휠 연구는 72명 전문가의 단어 묶음 결과로 분류와 배치를 구성했다. 한국 일반 사용자에게 같은 관계가 성립하는지는 별도 확인 대상이다. [향미 휠 설계 연구](https://doi.org/10.1111/1750-3841.13555)
- 선택지 순서와 묶음은 선택 결과에 영향을 줄 수 있다. 안정된 지도를 유지하면서 노출 위치와 실제 선택률을 함께 기록해야 한다. [CATA 선택지 순서 연구](https://doi.org/10.1016/j.foodqual.2012.08.016)
- 실제 후기는 겉과 속의 식감, 향, 전체 평가를 함께 표현한다. [만두 후기](https://sems11.tistory.com/90), [뽈레 치킨 후기](https://polle.com/place/1oIM5N/자담치킨)
- 미쉐린의 요리 품질 평가 기준은 감각 어휘나 개인 호감의 척도와 구분해서 참고한다. [미쉐린 평가 기준](https://guide.michelin.com/sg/en/article/features/what-is-a-michelin-star)

다음 검증에서는 음식군별로 여러 작성자·플랫폼의 실제 사용 문장을 수집하고, 중복·광고 문구를 표시한다. 서로 다른 사람이 해당 표현을 자기 말로 설명할 수 있는지, 비슷한 표현과 구분하는지, 원한 단어를 얼마나 쉽게 찾는지 확인한다. 우선 일부 음식군과 혼동이 큰 표현부터 검토하며 모든 845개를 한 사람에게 평가시키지 않는다.

현재 완료 범위는 후보 어휘·맵·태그·관계 정의와 구조 검사다. 앱 연결, 의미 추출기 구현, 사용자 실험, 실기기 기록 시간 측정은 완료 범위에 포함되지 않는다.

## 9. 이번 검증 결과

- 845개 표현의 ID와 라벨 중복 없음. 모든 부모·자식 참조와 822개 연결의 대상이 존재함.
- 43개 맵의 후보 집합이 서로 다르고, 총 5,415개 맵 소속 참조가 유효함. 맵별 수와 깊이별 수가 데이터와 일치함.
- 사용자용 태그 50개, 내부 구성 태그 122개, 기존 19개 태그의 대응과 참조를 확인함. 면·구이·중식·발효음식의 복수 선택 계약을 확인함.
- 관계 검토 화면의 스크립트 구문, 음식 변경, 가지 펼치기, 세부 표현 선택을 확인함.
- 736px 화면과 360px 화면에서 확인함. 작은 화면의 최대 22개 표현 가지에서 원형 버블 겹침·영역 이탈과 실행 오류가 없었음.
- 앱 코드 변경이 없어 앱 빌드는 생략함. 일반 사용자 이해도·어휘 사용 빈도·실제 기록 UX는 아직 검증 전임.
