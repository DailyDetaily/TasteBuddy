# 홈 발견 카드

> 현재 구현은 `home-discovery/2`이다. 새 규칙·열람 정책·검증 결과는
> [발견 카드 v2 구현](home-discovery-cards-v2.md)을 따른다.
> 아래 v1 생성/노출 규칙과 미실행 기록은 최초 구현 당시의 이력이다.

## 목적과 배치

‘발견 카드’는 현재 원본 기록 사이의 확인 가능한 관계를 보여주고 해당 원본을 연다.
하단 아카이브의 식사/메뉴/식당/직접 평가 네 영역은 유지한다.
별도의 홈 섹션을 늘리지 않고, 기존 질문 스택에 발견과 질문을 함께 넣는다.

- 접힘: 한 장. 새로 볼 발견이 있으면 발견이 앞면이다.
- 펼침: 발견 → 질문 → 발견 → 질문 순서의 최대 세 장.
- 한 종류가 없으면 다른 종류만 표시한다. 양쪽이 비면 스택을 숨긴다.
- 세 장보다 많으면 ‘카드 전체보기’에서 같은 순서의 큐를 연다.
- 발견에는 ‘발견 카드’ 라벨과 원본 열기 동작을 사용한다. 질문의 답변 버튼/완료 처리/노출 이력은 공유하지 않는다.

## 원본과 공통 집계

`HomeArchiveSources`가 아카이브와 발견에 사용할 원본을 함께 정규화한다.
충돌하는 중복 entry ID, 미래 observedAt, 삭제 원본, 다른 revision의 관측, 제외 증거,
충돌하는 observation ID, 아직 알려지지 않은 관측은 집계에서 제외한다.
발견에서는 확인된 미래 식사일을 포함하는 mealID 전체도 제외한다.

메뉴 identity는 식당 identity + 메뉴 identity다. ID가 없으면 정규화한 이름을 쓴다.
서로 다른 식당의 같은 메뉴명을 합치지 않는다. 반복 횟수의 단위는 고유 mealID다.
날짜가 없는 captured 기록은 행동 규칙에 참여할 수 있으나 직접 평가의 근거가 되지 않는다.
정확한 시간 관계는 같은 mealID의 확인된 식사일이 하나로 일치할 때만 사용한다.

## 생성 규칙 v1

| 종류 | 생성 조건 | 표시/원본 범위 |
|---|---|---|
| 두 기록 사이의 시간 | 같은 메뉴의 최근 확인된 두 식사가 60일 이상 떨어져 있고 마지막 식사가 최근 90일 이내 | 실제 간격 일수와 두 날짜. 해당 두 mealID의 메뉴 기록만 연결 |
| 반복 메뉴 | 같은 메뉴가 서로 다른 식사 3번 이상 | 식사 횟수. 그 메뉴의 모든 현재 원본 |
| 식당의 메뉴 모음 | 같은 식당에 고유 메뉴 3가지 이상, 메뉴를 기록한 식사 2번 이상 | 메뉴 수와 식사 수. 그 식당의 메뉴 식별 가능한 원본 |
| 반복된 좋은 직접 평가 | 같은 메뉴에 ‘좋았어요’/‘정말 좋았어요’를 남긴 서로 다른 식사 3번 이상 | 좋은 평가가 있는 식사 수와 직접 평가가 있는 전체 식사 수. 반례·미응답을 포함한 해당 메뉴 전체 원본 |
| 지난해 이맘때 | 지난해 오늘 전후 7일의 확인된 식사일 | 그 식사의 원본. 앱 활성화/홈 진입 시 날짜가 바뀌었으면 재계산 |

반복된 좋은 평가에서 같은 메뉴/mealID의 직접 평가가 부정 또는 보통과 섞이면 그 식사를
좋은 평가로 세지 않는다. 별점, AI 요약, 회고의 긍정 문장은 사용하지 않는다.
현재 entry의 유효한 `DiningOverallEvaluation`과 같은 revision의 직접 응답 관측이 모두 일치해야 한다.
미응답은 직접 평가 분모에서 제외하지만 상세 원본 목록에는 남긴다.
‘두 기록 사이 86일’은 그 사이에 먹지 않았거나 방문하지 않았다는 주장이 아니다.

문구는 검증 가능한 원본 집계에 연결된 결정적 템플릿으로 생성한다.
v1에는 외부 AI 호출이나 자유로운 수치 생성이 없다. 생성 문구는 새 사용자 증거로 저장하지 않는다.

## 선정과 열람 이력

- 종류 우선순위: 지난해 이맘때 → 시간 간격 → 반복된 좋은 평가 → 식당 메뉴 모음 → 반복 메뉴.
- 같은 종류는 최근 원본 순, 동률은 안정적인 카드 ID 순. 홈 렌더마다 무작위로 섞지 않는다.
- 첫 묶음에는 종류와 대상이 겹치지 않는 후보를 우선한다. 이후에도 같은 대상은 중복 노출하지 않는다.
- 한 번에 최대 12개의 발견을 선정한다. 더 많은 질문은 기존 전체보기/추가 로드로 계속 접근할 수 있다.
- 발견을 열거나 길게 눌러 ‘이 발견 7일간 보지 않기’를 선택하면 같은 내용을 7일 억제한다. 현재 같은 대상의 다른 규칙도 함께 억제하여 바로 같은 메뉴를 다시 제시하지 않는다.
- 억제 키는 규칙 버전 + 종류/대상 + 문구/수치 + 연결 원본 ID/revision + 증거 ID의 해시다.
- 원본이 바뀌면 같은 대상의 카드라도 새 내용으로 노출할 수 있다. 삭제/수정으로 조건이 깨지면 제거한다.
- 열람 이력은 계정별 기기 로컬 저장이다. 재실행에는 유지되며 원본 백업/취향 모델/질문 진행에는 포함하지 않는다.
- 계정 전환 시 이전 계정의 카드 상세를 닫고 해당 계정의 이력을 불러온다. 계정 데이터 삭제/전체 초기화 시 이력도 제거한다.

## UI와 상세

기존 `TasteQuestionStackCard`의 카드 표면, 사진 영역, 간격, 뒷장 표현, 펼침 모션을 재사용한다.
발견은 고정 라벨, 짧은 제목/맥락, 연결된 실제 사진이 있으면 기존 사진 컴포넌트를 사용한다.
그래프나 별도 범례를 추가하지 않는다. 접근성 글자 크기에서는 제목과 맥락을 잘라내지 않는다.

발견 상세는 카드 ID로 현재 후보를 읽고, 기존 `FoodMemoryRow`와 `FoodMemoryDetailView`로 원본을 연다.
두 식사 이상이면 해당 entryIDs만 전달하는 `FoodMemoryComparisonView`로 이동할 수 있다.
수정/삭제 시 기존 분석 캐시를 바로 무효화하고 백그라운드 재계산 결과로 교체한다.
그동안 상세는 갱신 상태를 표시하며, 규칙에 더 이상 맞지 않는 발견은 사라졌음을 안내한다.

## 검증 인계

`HomeDiscoveryEngineTests`에 빈 상태/임계값, meal 중복, 식당별 메뉴 identity, 날짜 정확성,
미래 날짜/날짜 충돌, 직접 평가/반례/미응답, captured, 오래된 관측, 순서 안정성,
원본 직렬화 복원, 노출 억제/만료, 혼합 큐 계약을 추가했다.
`HomeTasteQuestionsIntegrationTests`에 열람과 원본/질문 증거의 분리, 재실행 이력,
수정 후 재생성, 삭제 후 발견 제거 사례를 추가했다.
기존 홈 UI 테스트는 질문을 펼친 혼합 큐에서 수행하도록 바꾸고,
발견 앞면 → 스택 펼침 → 발견 상세 → 음식 원본 경로도 추가했다.

사용자 요청에 따라 테스트 실행, 빌드, 시뮬레이터/UI 검증은 수행하지 않았다.
혼합 스택의 펼침/전체보기/원본 수정/질문 답변 및 Undo, 큰 글자, 계정 전환은 사용자가 실행 확인한다.
