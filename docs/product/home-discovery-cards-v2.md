# 홈 발견 카드 v2 — 기억을 연결하는 관계형 발견

작성일: 2026-09-15 · 엔진: `home-discovery/2`

상태: 네이티브 생성·선정·상세·열람 이력 연결 완료. 최종 iOS 빌드 및 선택 단위·통합 테스트 83개 통과. 화면 상호작용/실기기 검증과는 구분한다.

## 목적과 구현 범위

단순 기록 횟수를 주인공으로 삼지 않고, 직접 남긴 응답의 공통점·조건별 차이·예외·시간 관계를 보여준다.
기존 홈 질문/발견 스택, 원본 음식 기억과 비교 화면을 재사용한다. 새 서버/API 호출과 별도 감각 증거 저장은 없다.
외부 LLM, 별점, 사진 추정, 회고의 긍정 문장으로 새 호감 관찰을 만들지 않는다.

규칙의 식사 수·75%·기간·차이 기준은 초기 표시 정책이다. 통계적 유의성, 인과 효과,
보정된 예측 확률 또는 실제 사용자 검증을 통과한 취향 임계값으로 표시하지 않는다.

발견 결과는 개인 모델, 질문 답변, 원본에 다시 쓰지 않는다.

## 생성 규칙

| 종류 | 실제 구현 조건 | 주장 범위 |
|---|---|---|
| 공통 취향 | 같은 감각·참조·대상·시점에서 호감 식사 3회 이상, 평가 식사 중 75% 이상, 호감 근거 메뉴 2가지 이상 | 서로 다른 메뉴에 직접 호감이 반복됨. 반례·보통·한 식사 내 다른 응답을 함께 표시 |
| 강도와 알맞음 | 같은 메뉴·감각·대상·시점에서 해당 강도의 동일 알맞음 응답이 식사 3회 이상 반복. 두 강도 비교는 식사 집합이 겹치지 않을 때만 | 알맞음·과함·부족함을 실제 응답대로 표시하며 호감으로 전환하지 않음 |
| 조건별 차이 | 같은 감각·대상·시점의 메뉴별 비교. 각 집단 식사 3회 이상, 방향 75% 이상, 반대 방향, 한 식사 제외 후에도 최다 방향 유지 | 음식 종류 일반화가 아니라 구체적 메뉴 비교. 두 메뉴가 함께 나온 식사는 독립 집단 비교에서 제외 |
| 다른 한 번의 경험 | 날짜가 확인된 최근 한 식사가 앞선 4회 이상의 반복 방향과 반대. 앞선 방향은 75%와 한 식사 제외 검사를 통과. 최근 식사는 90일 이내 | 과거 집단에 최근 식사를 넣지 않음. 한 번의 예외이며 취향 변화 확정이 아님 |
| 전체와 부분의 차이 | 동일 experience+meal의 전체 5단계와 감각 3단계에서 반대 평가 쌍. 1회도 개별 경험으로 표시, 동일 쌍 3회 이상은 반복 관찰 | 다른 메뉴의 전체 평가를 가져오지 않음. 같은 식사의 서로 다른 쌍은 mixed로 보존 |
| 두 기록 비교 | 같은 식당·메뉴의 확인된 최근 두 식사일이 다르고 직접 전체 평가가 다름. 최근 식사 90일 이내 | 60일 간격을 요구하지 않음. 두 기록 차이만 설명하며 품질/취향 변화를 확정하지 않음 |
| 기간별 평가 차이 | 같은 식당·메뉴·감각·대상·시점·기록된 강도. 오늘 포함 최근 90일과 직전 90일, 각 식사 5회 및 식사일 2개 이상, 긍정 비중 차이 40퍼센트포인트 이상, 한 식사 제외 후 방향 유지 | 메뉴 구성이 바뀐 것을 전체 입맛 변화로 해석하지 않음. 정확한 기간과 응답 분포 표시 |
| 새 메뉴와 익숙한 취향 | 아카이브에서 확인 가능한 첫 메뉴 식사에 전체와 해당 감각이 모두 긍정. 이전 다른 메뉴의 직접 호감 3회 이상 및 75% 이상 | 처음 먹었다고 하지 않음. 이전의 부정·보통·충돌도 분모와 상세에서 보존 |

식사일 미확인은 비시간 규칙에 참여할 수 있지만 선후·기간·첫 경험 비교에는 참여하지 않는다.
확인된 미래 식사일을 포함한 meal 전체를 제외한다. 같은 meal의 확인 식사일이 충돌하거나,
날짜 확인 시각이 기준 시점 이후이면 관계형 시간 비교에서 제외한다.
하루 안의 순서는 날짜만으로 추정하지 않는다. 과거 수정본으로 당시 모델 상태를 완전히 복원했다고 주장하지 않는다.

레거시 `mealID` 복구는 실제 서로 다른 식사였다는 추가 검증이 아니다. 숫자는 앱에 식별된 식사 범위의 기록이다.

## 기존 기록/회상 카드

반복 메뉴와 식당 메뉴 모음은 보조 후보로 유지한다. 의미 키의 이정표는 3/5/10/20/50/100이며,
단순한 한 건 증가로 읽은 동일 이정표를 다시 올리지 않는다.
반복된 좋은 전체 평가는 좋은 식사 3회 이상 및 직접 평가 식사 중 75% 이상으로 제한한다.
지난해 이맘때와 두 날짜 간격은 회상 후보로 남긴다. 같은 메뉴의 두 평가 비교가 있으면 간격만 말하는 후보는 제거한다.

## 선정과 홈 배치

종류만의 고정 순서를 쓰지 않는다. 관계의 구체성에 따른 내부 relevance와 최근 근거 보너스로 정렬한다.
근거가 최근 14일 이내이면 +20, 90일 이내이면 +10이고, 동률은 근거 날짜와 안정적인 ID로 결정한다.
숫자는 내부 우선순위이며 사용자에게 신뢰도 점수로 보여주지 않는다.
첫 순회는 종류/대상을 분산하고, 다음 순회는 새 대상, 마지막 순회는 같은 대상의 다른 관점으로 최대 12개까지 선정한다.
12개를 채우기 위해 근거 없는 카드를 만들지 않는다.

질문과 발견은 기존처럼 교차 배치한다. 홈의 접힘 1장/펼침 최대 3장에서는 동일 대상 발견을 한 번만 표시한다.
다른 관점은 전체보기와 이후 방문에 남긴다. 원본 연결, 질문 답변과 Undo 경로는 바꾸지 않는다.

## 읽음과 명시적 숨김

| 키 | 의미 |
|---|---|
| 카드 `id` | 규칙 버전 + 종류 + 대상 + 적용 범위/비교 방식 |
| `revisionKey` | 현재 원본 revision, 표시 내용, 연결 관측 등. 상세 최신성/렌더 갱신용 |
| `meaningKey` | 주장 방향, 반복 수준, 반례 집합 등 의미 변화. 문구/사진/revision 자체는 포함하지 않음 |
| `read:<meaningKey>` | 읽은 동일 의미의 재추천 억제. 같은 방향의 단순 추가나 문구 수정으로 해제하지 않음 |
| `subject:<subjectID>` | 상세 열람 이후 24시간 동안 같은 대상의 다른 관점 간격 |
| `snooze:<id>` | 사용자가 명시적으로 요청한 7일 숨김. revision/의미 변화로 우회하지 않음 |

읽음과 미루기는 다르다. 상세를 열면 읽음을 기록하고, 길게 눌러 7일 숨김을 선택할 때만 미루기를 기록한다.
새 반례/방향 변화/반복 수준 변화는 규칙별 의미 키가 달라질 수 있다. 원본 정정은 새 식사 횟수를 늘리지 않는다.
revision 기반 숨김 조회도 유지한다. 다만 엔진 버전이 바뀌어 v1 카드 ID와 v2 카드 ID는 다르며,
v1에서 구분하지 않았던 읽음/미루기를 새 의미별 이력으로 자동 이관하지는 않는다.
이력은 기존 계정별 UserDefaults 저장소에 최대 2,048개만 남긴다. 상한에서는 활성 미루기/대상 간격을 읽음보다 우선 보존한다.
상한으로 일부 읽음 키가 빠지면 그 후보는 다시 노출될 수 있다. 원본/사진/취향 응답은 이 저장소에 넣지 않는다.

## 화면

앞면은 기존 카드와 실제 사진을 유지하며 ‘발견 카드 · 공통 취향’처럼 관점 라벨을 붙인다.
상세에는 ‘근거 요약’과 ‘해석 범위’를 추가했다. 수치의 분모, 반례/중립/충돌 및 시간 비교의 제외 범위를 설명한다.
연결된 원본에는 비교 대상 밖의 관련 기록을 포함할 수 있지만 실제 분모와 구분한다. 근거를 삭제하면 상세도 현재 상태로 갱신한다.

## 구현하지 않은 확장

메뉴를 넘어선 음식 분류 전반의 변화, 기록 다양성 기간 카드, 직접 만든 요리/레시피 버전 비교,
카드 앞면의 실제 체류시간 기반 노출 학습, ‘이미 알아요/해석이 달라요’ 입력은 추가하지 않았다.
조건별 차이는 현재 구체적 메뉴끼리의 비교이며 음식 종류 일반화나 조합의 인과 추론이 아니다.
