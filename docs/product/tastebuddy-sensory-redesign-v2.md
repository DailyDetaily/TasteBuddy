## 0. 이번 재설계의 결론

**6축 전체의 풍부한 미각 지도를 유지하면서 음식에 맞는 표현의 접근성만 일부 바꾸고, 상세 경험은 기존 5가지 관점형 디테일 체계에서 음식별로 설명한다.**

| 구분 | 미각 버블맵 | 디테일 태그 |
|---|---|---|
| 역할 | 어떤 단맛·신맛·짠맛·쓴맛·감칠맛·지방감을 느꼈는가 | 맛이 어떻게 어우러지고 이어졌는가, 질감·향·온도·조리와 구성은 어땠는가 |
| 구조 | 현재 6축·방향·원형 버블·풍부한 맵·팬/줌 유지 | 현재 5개 관점형 카테고리와 칩 선택 방식 유지 |
| 음식별 변화 | 일부 단어가 같은 축 안의 중앙 가까운 자리로 교환 | 카테고리 제목·순서·태그 후보를 프로필별로 실제 변경 |
| 금지 | 한 축만 집중, 관련 없는 축 삭제, 향·식감으로 수를 채우기, 중앙을 선호·강도로 해석 | 튀김옷·속살·면·소스 같은 부위 목록으로 상위 체계를 대체, 모든 태그를 활성 버블에 자동 귀속 |
| 최소 입력 | 버블 1개로도 기록 가능. 현행 최대 3개 선택은 우선 유지 | 선택사항. 독립 디테일만 고르는 기록도 허용 |

## 2. 두 화면의 어휘 경계

### 2.1 버블에 남길 표현

6축의 감각 자체, 감각의 명시적인 성격·강도, 미각으로 한정된 비유, 해당 맛의 명시적 대상·시점·지속을 허용한다. 짧고 익숙한 말이 기본이며 긴 설명 문장을 단어 수를 맞추기 위해 만들지 않는다.

| 버블 | 별도 디테일 | 구분 |
|---|---|---|
| 캐러멜 같은 단맛 | 캐러멜을 떠올리는 향 | 단맛의 비유 / 향 |
| 카카오 쌉쌀함 | 구운 향·탄 향 | 쓴맛 / 향 |
| 레몬 같은 새콤함 | 감귤류 향 | 신맛 / 향 |
| 풍성한 지방감 | 매끈함·입안에 막이 남음 | 앱의 지방감 인상 / 질감·잔여감 |
| 해산물의 달큰함·감칠맛 | 해산물 향·탱글함 | 맛 / 향·식감 |
| 첫입부터 달다 | 첫입에 두드러짐 | 미각에 한정된 표현 / 대상을 지정할 수 있는 일반 수식 |

‘고소한·구수한·담백한·깔끔한·느끼한’은 사용자 표현에서 없애지 않는다. 뜻이 하나로 확정되지 않은 경우 디테일의 **복합 인상**으로 보존하며, 자동으로 지방감·쓴맛·낮은 강도·좋아함으로 바꾸지 않는다.

**지방감은 기존 앱의 여섯 번째 표현축으로 유지한다.** 이것을 여섯 기본미가 과학적으로 동일한 방식으로 확정됐다는 주장으로 사용하지 않는다. ‘부드러운 질감·버터 향·고소한 인상’은 지방감 선택을 대신하지 않는다. JSON의 `app.fat_impression`은 실행 카탈로그에서 앱의 지방감 인상을 별도로 보존하는 속성이다. 객관적인 지방 함량이나 다른 감각으로 환산하지 않는다.

### 2.2 중복과 복합 표현의 처리

‘달콤한 여운’과 ‘단맛 + 오래 남음’은 같은 경험에서 같은 범위를 설명하면 보완 근거로 묶는다. 서로 다른 독립 관찰 2회나 취향 증거 2회로 세지 않는다. 단, 원문 선택 이벤트와 출처는 각각 보존한다.

‘바삭하고 촉촉함’처럼 둘 이상의 감각은 독립 태그 조합으로 기록하는 편을 기본으로 한다. 익숙한 복합어를 강제로 분해해 사용자가 말하지 않은 의미를 생성하지 않는다.

## 3. 미각 어휘: 확장 160개 후보

기존 96개 후보에 64개를 추가하여 **160개**로 확장했다. 단맛 32·신맛 30·짠맛 26·쓴맛 24·감칠맛 30·지방감 18개다. 수를 축마다 맞추지 않으며, 160은 검토 후보 규모이지 최적 개수나 검증된 어휘 수가 아니다. **160개 표현은 160개의 독립적인 기본 감각을 의미하지 않는다.**

| 축 | 이전 | 추가 | 합계 |
|---|---:|---:|---:|
| 단맛 | 18 | 14 | 32 |
| 신맛 | 18 | 12 | 30 |
| 짠맛 | 16 | 10 | 26 |
| 쓴맛 | 14 | 10 | 24 |
| 감칠맛 | 18 | 12 | 30 |
| 지방감 | 12 | 6 | 18 |
| 전체 | 96 | 64 | 160 |

추가한 64개는 미각에 한정한 비유 30개, 명시적 대상 표현 22개, 시점 표현 12개다. 예를 들어 ‘조청의 달큰함·라임처럼 새콤한·된장의 짠기·자몽의 씁쓸함·가쓰오부시의 깊은 맛’, ‘달콤한 소스·기름기 도는 국물’, ‘첫 모금의 쌉쌀함·삼킨 뒤에도 새콤한’을 보강했다. 향·식감·자극을 새 미각 버블로 넣지는 않았다.

새 비유는 모두 직접 작성한 미검증 후보다. 특히 식품 비유의 차이를 향·식감 없이 설명할 수 있는지 확인해야 한다. 구별되지 않으면 기존 표현의 별칭이나 디테일로 정리한다. 대상·시점 변형은 같은 미각 개념의 보완이며 독립된 새 감각이나 별도 취향 증거로 세지 않는다.

JSON의 각 신규 표현에 정의, `distinguish_from_ids`, 검토 질문을 붙였다. 첫 모금은 `temporal_qualifier=first-sip` 후보로 보존하며 첫입으로 자동 치환하지 않는다. 이 값의 실행 파서 지원은 공용 생성기와 iOS/웹 일치 테스트에서 관리한다. 기존 96개 ID·축별 기본 순번은 유지하고 추가 표현을 각 축의 뒤에 연결했다. 버블 확장은 `candidate-2`에 기록했으며 디테일 개정은 `candidate-3`, 이번 버블 문구 개정은 `candidate-4`다. 버블은 `redesign-bubble-wording-4`를 사용하고 이전 정의는 `bubble_definition_archive`에 보존한다. 기존 음식별 중앙 우선 후보는 유지하며, 신규 표현은 별도 검토 없이 자동 승격하지 않는다.

새 어휘는 안정된 ID, 축, 짧은 라벨, 정의 버전, 구별할 기존 표현, 실제 재료와의 관계, 시간·대상·강도 중 명시된 필드를 갖는다. 비유형은 이해도 검증 우선 대상으로 두며 구별되지 않는 말은 별칭 또는 디테일로 정리한다. ‘또렷한’은 자동으로 strong이 아니고, ‘오래 남는’도 강한 맛이 아니다.

각 축 첫 표현은 ‘퍼지는 달콤함·부드러운 산미·감도는 짭짤함·또렷한 쌉쌀함·입안을 채우는 감칠맛·퍼지는 기름기’의 고정 앵커다. 버블 라벨에 ‘맛있음·과함·잘 맞음’을 기본 포함하지 않는다. 호감과 내게 맞는 정도는 선택 후의 별도 응답으로 둔다.

전체 160개 목록은 부록 A, 개별 ID·후보 의미는 JSON에 수록했다.

### 3.1 자연어 라벨과 설명 — 2026-09-28 개정

6축은 분류 기준이지 모든 문구의 말끝이 아니다. 예를 들어 쓴맛 축에는 ‘은은한 쌉쌀함·첫입이 쓰다·뒤늦은 쓴 기운·쌉싸름한 여운’, 짠맛 축에는 ‘부드러운 간·간이 또렷함·속까지 밴 간’, 감칠맛 축에는 ‘은근한 깊이·국물에서 오는 깊이·짧게 끊긴 감칠맛’을 둔다. ‘캐러멜 같은 단맛’처럼 의미 구분에 필요한 미각 명칭은 남긴다.

`label`은 버블의 짧은 표현, `description`은 사용자가 읽는 설명, `definition`은 해석 경계를 포함한 내부 정의다. `search_aliases`는 이전 용어로도 찾을 수 있게 하되 이전 라벨을 새 응답으로 자동 치환하는 용도가 아니다. 이름만 바꾸어 강도·재료·호감을 새로 추정하지 않는다. 향·식감은 여전히 디테일 태그다.

기존 데이터 규모(160/147), 각 축의 순번·고정 자리, 음식 프로필의 참조 ID는 변경하지 않는다. 기존 버블 정의는 읽기 전용 archive로 보존하고, 기록의 ID+카탈로그 버전+정의 버전으로 당시 라벨과 의미를 복원한다. 알 수 없는 버전이나 일치하지 않는 라벨은 미확정으로 남긴다.

### 3.2 중앙 버블 교체 — 2026-09-28

기본 축 이름만 적혀 있던 중앙 6개 버블을 위의 구체적인 인상 표현으로 교체했다. 이번 정의는 `redesign-bubble-anchor-5`이며 나머지 154개는 `redesign-bubble-wording-4`를 유지한다. 교체 전 정의 6개를 archive에 추가해 기존 기록의 원문과 해석을 보존한다. 축 분류명과 좌표는 그대로다. 사용자 요청에 따라 빌드·테스트·화면 검증은 실행하지 않았다.

## 4. 버블 배치와 상호작용

### 4.1 고정과 가변의 경계

| 요소 | 정책 |
|---|---|
| 축 방향 | 현재 각도 유지: 단맛 -105°, 신맛 -45°, 짠맛 15°, 쓴맛 75°, 감칠맛 135°, 지방감 195° |
| 축별 핵심 버블 | 각 축의 구체적인 인상 표현 1개씩, 총 6개 위치 고정 |
| 중앙 가변 자리 | 각 축의 앵커 다음 가까운 2자리. 기본 비교안은 총 12자리 |
| 재배치 방식 | 같은 축 안의 기존 자리와 1:1 교환. 단어 삭제·복제 없음 |
| 변화 예산 | 축마다 최대 2쌍 교환 → 전체 최대 24개 위치 변경 → 160개 중 최소 136개 위치 유지 |
| 주변 버블 | 음식 관련성이 낮아도 같은 맵에서 계속 표시·선택 가능 |
| 시각적 강조 | 중앙이라는 이유로 크기·채도·좋아요 배지를 추가하지 않음 |
| 중앙의 의미 | 현재 음식에서 먼저 비교해볼 만한 표현. 강도·호감·확정 감각·과학적 거리 아님 |

변화 예산·확장 후보 160개·중앙 12자리는 모두 검증 가능한 초기 파라미터다. 고정 제품 상수로 섣불리 확정하지 않는다. 한 축에 적절한 후보가 없으면 억지로 바꾸지 않는다.

### 4.2 결정 순서

1. 사용자 수정과 알려진 음식 구조로 프로필을 정한다. 요리 문화 태그만으로 맛·향·기름기를 확정하지 않는다.
2. 전체 160개를 축별 기본 순서에 놓는다. 각 축 필요 개수에 맞는 슬롯을 생성한다.
3. 조건을 충족한 해당 축 후보만 우선순위로 정한다. 같은 후보는 한 번만 처리한다.
4. 고정 앵커를 제외하고 상위 최대 2개를 해당 축의 안쪽 자리와 교환한다. 동률은 기본 순서와 안정 ID로 결정한다.
5. 모든 축·모든 버블이 남았는지, 이동 개수·참조·겹침·좌표 범위를 검사한다.
6. 사용자가 탐색하기 전에 배치를 확정한다. 난수·네트워크 도착 순서·전체 호감으로 위치를 바꾸지 않는다.

공통 태그만 있을 때는 공통 배치를 사용한다. 예: `cold`만으로 신맛·쓴맛에 우선권을 주지 않는다. `raw_cured`만으로 회를 확정하지 않는다. 면·국물·크림 등 구체 구성은 각각 확인된 범위에서만 적용한다.

### 4.3 현재 맵 경험의 유지

새 기록은 카메라를 맵 중심에 둔다. 자동 선택이나 특정 축 줌은 하지 않는다. 현재 원형 버블·색·팬·줌·선택 확대·이웃 밀림은 유지 대상으로 한다. 음식 변경에 의한 **기본 위치 재계산**과 선택 확대에 따른 **일시적인 충돌 회피**는 다른 동작이다.

전체 지도에서 160개 모두 같은 탐색 층에 둔다. 24~36개만 남기고 나머지를 숨기는 요약 화면으로 바꾸지 않는다. 동시에 화면 안에 들어오는 개수는 기기 크기와 줌에 따라 다르며, 160개를 한 화면에 맞추려고 글자를 줄이지 않는다. 맵 범위는 실제 좌표·선택 반경·안전 여백으로 산출한다.

단어 선택을 시작한 후에는 음식 자동 분류 응답으로 맵을 다시 섞지 않는다. 사용자가 음식 분류를 직접 수정할 때만 적용하며 선택 ID·스크롤/줌 상태를 보존한다. 현재 최대 3개 선택은 우선 유지하되 3개를 채울 의무나 3개 선택 직후 강제 전환은 두지 않는다. 1개만 선택하고 다음 단계 또는 저장으로 갈 수 있다.

편집 재진입에서는 저장된 표시 버전·선택을 복원한다. 과거 위치를 재현할 수 없으면 라벨·선택 의미를 보존한 안전한 복원 화면을 사용하고 원래 좌표를 재현했다고 표시하지 않는다.

## 5. 디테일 카테고리: 기존 5개 관점 유지, 음식별 구성 변경

### 5.1 기본 관점

| 내부 ID | 기본 제목 | 유지할 역할 | 버블·다른 항목과의 경계 |
|---|---|---|---|
| balance | 맛의 강도와 균형 | 맛의 비중·어울림·가림·대비 | ‘감칠맛이 깊음’처럼 개별 맛을 다시 선택하는 항목은 버블/명시적 강도 응답으로 이관 |
| flow | 입안의 흐름 | 첫입·씹는 동안·삼킨 뒤·반복 섭취의 변화와 지속 | 오래감≠강함, 끝맛≠식사 후반 |
| texture | 질감과 온도 | 씹힘·수분·표면감·잔여감·온도·필요한 자극 | 매움·얼얼함·떫음·탄산은 별도 속성. 6축 점수로 환산하지 않음 |
| aroma | 향과 재료 인상 | 느껴진 향, 재료의 존재감, 복합 인상 | ‘향을 느꼈다’≠해당 재료·조리법이 실제 존재 |
| composition | 조리와 구성 단서 | 익힘·소스·재료 조합·비율·맥락 | ‘굽기가 좋음’은 사용자 적절성 평가. 조리 사실이나 전체 호감으로 복제하지 않음 |

‘튀김옷·속살·면·소스’는 태그의 대상 정보다. 상위 카테고리를 이런 부위별 목록으로 바꾸지 않는다.

### 5.2 음식별 카테고리 변형

일반 음식에는 익숙한 기본 제목을 그대로 둔다. 실제 맥락이 다를 때만 같은 관점의 제목을 바꾼다. 내부 가족 ID는 유지하여 서로 다른 음식의 감각을 비교할 수 있게 한다.

| 음식 맥락 | 카테고리 제목 변화 | 태그 구성 변화 |
|---|---|---|
| 튀김 | 기본 5개 유지, 질감과 온도 우선 | 파삭함·튀김옷의 단단함·눅눅함·속의 수분 등 추가 |
| 국물면 | 기본 5개 유지, 질감과 온도 우선 | 면 중심·표면·퍼짐, 국물 농도·온도 중심 |
| 회·생해산물 | 기본 5개 유지, 질감·향 우선 | 기본 익힘 평가 제거, 살의 탄력·표면감·소스 조합 중심 |
| 크림 파스타 | 기본 5개 유지 | 면과 소스의 질감, 소스와 면의 연결, 우유·버터 관련 향 후보 |
| 커피 | 입안의 흐름과 여운 / 향과 원료 인상 / 추출과 음료 구성 | 바삭함·굽기·가니시 대신 떫음·온도·커피향·농도·확인된 첨가 구성 |
| 차 | 입안의 흐름과 여운 / 향과 원료 인상 / 우림과 음료 구성 | 찻잎향·꽃향·떫음·모금 후 여운·농도 |
| 매운 음식 | 질감·온도·자극 | 매움·얼얼함·코의 알싸함 및 자극 지속 추가 |
| 탄산음료 | 질감·온도·탄산 / 음료의 구성 | 탄산감·거품·온도·음료 농도. 신맛을 탄산의 대리값으로 쓰지 않음 |
| 코스 맥락 확인 | 조리와 코스 구성 | 다음 코스와의 연결 추가. 단품에는 기본 노출하지 않음 |

제목뿐 아니라 카테고리별 후보 풀이 교체되어야 한다. ‘커피’인데 기본 ‘굽기가 좋음’을 맨 뒤로 옮기기만 하는 것은 이 요구를 충족하지 않는다.

### 5.3 칩 UI와 개수

현재처럼 제목 + 2줄 가로 스크롤 칩 + 카테고리별 직접 입력을 기본으로 한다. 첫 후보는 카테고리당 8~16개를 비교안으로 두되 정해진 수를 채우기 위해 부적합한 태그를 넣지 않는다. 후보가 많으면 같은 카테고리 안에서 더 탐색할 수 있게 하며, 전체 태그 검색은 프로필 밖의 표현도 찾는다.

전체 평가는 추천 순서에 쓰지 않는다. ‘바삭함’과 ‘눅눅함’, ‘소스가 잘 어울림’과 ‘소스가 재료를 가림’처럼 현재 음식의 차이를 설명할 대안도 접근하기 쉽게 둔다. 모든 태그에 기계적으로 반대말을 만들거나 억지 50:50 비율을 맞추지는 않는다.

상시 설명 문단·가이드 카드는 늘리지 않는다. 필요한 정보는 짧은 제목, 선택된 대상 칩, 선택 상태로 전달한다. 긴 정의는 검색 결과·도움말 등 요청 시 확인하는 경로로 둔다. 색만으로 선택 여부를 구분하지 않고, VoiceOver 및 큰 글자 모드에서도 목록 탐색 경로를 유지한다.

음식 프로필의 `family_tag_pools`는 해당 음식에서 제공할 기본 후보 전체다. 공통 60개를 먼저 붙인 뒤 프로필 후보를 더하지 않는다. 이 규칙으로 커피·차·탄산음료에 씹기·튀김옷·익힘 평가가 다시 섞이는 일을 막는다. 공통 프로필은 음식이 미확인일 때의 넓은 탐색 후보로 유지한다.

- **음료의 흐름:** ‘마실수록 쌓임·마실수록 약해짐·첫 모금과 끝맛이 다름’을 추가했다. ‘첫입·다음 한입·먹을수록·씹을수록’ 표현은 음료 기본 후보에서 제외했다. 씹는 고형 구성이 확인되면 ‘씹을수록 강해짐’과 해당 질감을 조건부로 탐색할 수 있다.
- **음식의 구성:** 회·생해산물과 샐러드 기본 후보에서 익힘 평가를 제외했다. 튀김·구이의 소스 관계, 샐러드의 드레싱, 디저트의 층별 구성과 구운 반죽은 해당 구성이 확인될 때 추가한다.
- **향:** ‘향이 은은함·향이 강함·삼킨 뒤 향이 올라옴·향이 오래 남음·캐러멜 향·카카오 향’을 추가했다. 향의 강도·시점을 활성 미각에 상속하지 않는다.
- **음료 농도:** ‘농도가 내게 너무 옅음·너무 진함’을 ‘알맞음’과 함께 제공한다. 음료의 묽음·걸쭉함이라는 질감과 사용자에게 맞는 농도를 구분한다.

조건은 `confirmed`일 때만 충족된다. 미확인·명시적 해제·상충 정보는 조건부 후보를 자동 추가하지 않는다. 여러 조건은 모두 충족해야 하며, 우유 확인에서 유제품 확인을 파생할 때도 사용자의 명시적 거절이나 상충 정보를 덮어쓰지 않는다. 예를 들어 우유는 확인됐지만 유제품 구성이 명시적으로 거절된 상충 상태라면 두 플래그를 해당 후보 계산에서 보류하고 입력 원문 상태를 보존한다. 프로필 밖의 표현은 전체 검색·직접 입력으로 찾을 수 있고 이미 선택한 태그는 별도 선택 영역에 남긴다.

## 6. 선택 버블과 디테일의 연결

현재 활성 버블이 있다고 해서 모든 디테일을 그 미각의 속성으로 해석하지 않는다. **독립 감각·수식·관계**를 나누고, 복합 인상은 의미를 확정하지 않은 상태로 보존한다.

| 태그 종류 | 예 | 연결 원칙 |
|---|---|---|
| 독립 감각 | 바삭함·구운 향·차가움·얼얼함 | 자기 속성과 명시적 부위를 가진 음식 관찰. 활성 미각을 상속하지 않음 |
| 수식 태그 | 첫입에 두드러짐·오래 남음 | 화면에서 지정한 ‘음식 전체 / 선택한 미각’에 적용 |
| 관계·구성 | 소스가 재료를 가림·단맛과 신맛이 어울림 | 라벨이 명시한 관계를 보존. 한 미각 또는 전체 호감으로 축약하지 않음 |
| 복합 인상 | 고소한 인상·깔끔한 끝맛 | 원문 보존, 불명확한 의미는 미확정 |

기본 대상은 ‘음식 전체’로 한다. 미각 수식이 가능한 영역에서는 기존 선택 버블을 이용한 짧은 대상 선택을 제공한다. 예: `음식 전체 | 캐러멜 같은 단맛 | 진한 감칠맛`. 대상은 보이게 하고, 실제 탭으로 선택한 경우에만 `relatedBubbleID`를 붙인다. 독립 감각을 고를 때는 별도 확인 질문을 강제하지 않는다.

예시 1: ‘단맛’을 선택하고 ‘오래 남음’을 그 버블 대상으로 고름 → 단맛 존재 + 지속 정보.  
예시 2: ‘단맛’이 활성화된 상태에서 ‘바삭함’을 고름 → 바삭한 질감의 독립 관찰. 단맛 강도·단맛 원인으로 기록하지 않음.  
예시 3: ‘감칠맛’ 활성 상태에서 ‘구운 향’을 고름 → 구운 향의 존재. 쓴맛·감칠맛 강도에 합산하지 않음.

수식 태그의 부모 버블을 해제하면 임의로 다른 버블이나 음식 전체로 재연결하지 않는다. 태그 원문·이전 참조를 보존한 미확정 상태로 두고, 필요한 경우 사용자가 대상을 고칠 수 있게 한다. 독립 태그는 버블 삭제와 함께 삭제하지 않는다. 같은 태그라도 대상·시점이 다르면 선택 인스턴스를 구분한다.

## 7. 음식 프로필 결합 규칙

기본 프로필 + 확인된 구성 오버레이로 구성한다. JSON에는 공통을 포함한 15개 음식 프로필과 4개 오버레이를 수록했다.

우선순위: **사용자의 명시적 수정 → 확인된 구체 음식 구조 → 확인된 재료·소스·조리 오버레이 → 공통 후보 → 안정 ID**. 태그 ID의 사전순이나 배열의 우연한 순서로 대표 음식을 정하지 않는다.

`grain_noodle + broth`라도 grain_noodle에는 곡물이 포함되므로 면인지 확인 전에는 국물면으로 강제 확정하지 않는다. `raw_cured + seafood`도 cured만으로 생해산물을 확정하지 않는다. `grilled_smoked`도 훈연만인지 구이인지 알려진 범위대로 처리한다. 요리 문화(한식·중식·일식)만으로 매운맛·불향·산미를 추가하지 않는다.

미분류 상태, 시스템 자동 분류, 사용자 확인, 사용자가 모두 해제한 명시적 빈 집합은 별도다. 선택을 시작한 뒤 도착한 자동 분류 결과는 후보로 보관하고 즉시 적용하지 않는다.

복수 프로필이 양립 가능하면 가족별 태그를 안정 ID로 중복 제거하여 합친다. 충돌하면 확인되지 않은 분기를 적용하지 않고 공통 체계로 복귀한다. 제목은 가장 구체적으로 확인된 관점형 제목을 사용한다. ‘질감·온도·자극’과 ‘질감·온도·탄산’이 함께 필요하면 제목을 ‘질감·온도·자극’으로 정리하고 탄산 태그의 내부 속성은 유지한다.

프로필이 바뀌어도 이미 선택한 표현·직접 입력은 별도 선택 영역에 남긴다. 범위를 알 수 없으면 원문을 보존하고 미확정으로 남긴다. 메뉴명이 바뀐 것만으로 과거 감각을 새 음식의 감각으로 자동 복제하지 않는다.

## 8. 음식별 완성 예시

### 8.1 튀김

버블 전체 160개는 유지한다. 지방감 축에서는 ‘오일감·기름진 여운’, 짠맛 축에서는 ‘겉면의 짭짤함·부드러운 간’이 안쪽 후보가 된다. 나머지 축의 앵커와 단어는 유지된다. 바삭함은 버블에 넣지 않는다.

| 디테일 관점 | 후보 예시 |
|---|---|
| 질감과 온도 | 얇게 파삭 부서짐 · 튀김옷이 단단함 · 눅눅함 · 속이 촉촉함 · 속이 푸석함 |
| 맛의 강도와 균형 | 양념이 재료 맛을 가림 · 재료 맛이 더 선명함 · 단맛과 짠맛이 어울림 |
| 입안의 흐름 | 끝맛이 가벼움 · 끝맛이 무거움 · 먹을수록 쌓임 · 느끼한 인상 |
| 향과 재료 인상 | 구운 향 · 탄 향 · 선택한 재료에서 떠올린 향 |
| 조리와 구성 단서 | 익힘이 알맞음 · 겉과 속의 대비가 좋음 · 소스 확인 시 잘 어울림 / 재료를 가림 / 따로 고임 |

### 8.2 크림 파스타

버블은 ‘우유 같은 달콤함·기름진 여운’ 등의 접근성을 높이고, 치즈·버터의 구체 비유는 확인된 구성 조건을 충족할 때 우선한다. 크리미함·매끈함은 질감, 버터향은 향으로 남긴다.

| 디테일 관점 | 후보 예시 |
|---|---|
| 질감과 온도 | 면 중심이 단단함 · 면이 퍼짐 · 소스가 꾸덕함 · 소스가 묽음 · 입안에 막이 남음 |
| 맛의 강도와 균형 | 균형이 좋음 · 지방감이 다른 맛을 가림 · 한 맛이 두드러짐 |
| 향과 재료 인상 | 우유 향 · 버터 향 · 허브 향 · 버섯 향 |
| 입안의 흐름 | 첫입에 두드러짐 · 삼킨 뒤에도 남음 · 먹을수록 쌓임 |
| 조리와 구성 단서 | 소스가 면에 잘 붙음 · 소스와 면이 따로 느껴짐 · 재료 비율이 치우침 |

### 8.3 커피

쓴맛·산미·단맛의 관련 표현을 각자의 축 안에서 일부 이동한다. 단맛이나 지방감 축을 삭제하지 않고, 무첨가 커피라는 이유로 느끼지 못할 감각이라고 단정하지도 않는다. 다만 우유·버터 같은 **구체 구성에 따른 승격**은 별도 확인 조건을 따른다.

| 디테일 관점 | 후보 예시 |
|---|---|
| 향과 원료 인상 | 볶은 커피 향 · 과일 향 · 견과 향 · 꽃향 · 탄 향 |
| 맛의 강도와 균형 | 한 맛이 두드러짐 · 맛의 대비가 뚜렷함 · 맛들이 따로 느껴짐 |
| 입안의 흐름과 여운 | 첫 모금에 두드러짐 · 다음 모금까지 남음 · 마실수록 쌓임 / 약해짐 · 첫 모금과 끝맛이 다름 |
| 질감과 온도 | 떫음 · 매끈함 · 음료가 묽음 / 걸쭉함 · 입안에 가루감이 남음 · 온도가 알맞음 |
| 추출과 음료 구성 | 농도가 내게 너무 옅음 / 알맞음 / 너무 진함 · 우유 확인 시 어울림 / 커피 맛을 가림 / 따로 느껴짐 · 얼음 확인 시 녹으며 묽어짐 |

‘떫음’을 쓴맛으로, 볶은 향을 쓴맛 강도로 자동 변환하지 않는다. 추출과 구성이라는 제목으로 객관적 추출 원인을 역산하지 않는다.

## 9. 어휘 생성·검수 운영

AI가 한 음식의 단어를 일괄 생성한 뒤 즉시 맵에 배포하지 않는다. 실제 사용자 기록·자유 입력·허용된 실제 사용 문장을 출처와 함께 검토하고, 기존 표현으로 나타내기 어려운 차이가 있을 때만 새 후보를 만든다. 이번 후보는 그런 전수 수집이나 이해도 실험이 완료된 결과가 아니다.

검수 질문은 다음 다섯 가지다. (1) 사용자가 자신의 말로 뜻을 설명할 수 있는가? (2) 가장 가까운 기존 표현과 실제로 구분하는가? (3) 단독 라벨만으로 대상·감각이 충분히 드러나는가? (4) 맛·향·식감·평가를 불필요하게 섞지 않는가? (5) 음식 맥락이 달라져도 같은 의미로 비교할 수 있는가?

어휘 상태는 `candidate → reviewed → pilot → active`로 제안한다. 각 상태의 실제 검증 자료를 보존하고 개수나 모델의 자신감만으로 승격하지 않는다. 읽기 쉬운 표현으로 바꾸더라도 이전 라벨과 정의 버전은 유지한다. 오직 표현 길이가 길다는 이유로 더 높은 신뢰도를 부여하지 않는다.

같은 뜻의 말투 차이는 별칭, 다른 부위는 대상, 시점 차이는 시점 정보로 먼저 검토한다. 별도의 차이가 없으면 신규 개념을 만들지 않는다. 버블의 맛 비유가 주로 향으로 이해되면 해당 후보를 보류하거나 디테일로 이관한다.

## 10. 저장·분석 계약

### 10.1 분리할 세 계층

| 계층 | 예시 필드 | 사용 |
|---|---|---|
| 표현 정의 | expressionId, conceptId, definitionVersion, label, allowedFacets | 어떤 선택지가 무엇을 뜻하는지 |
| 제시 정보 | presentationVersion, profileId/version, contextSource, layoutVersion, orderedIds, slotIds, shown/visible state | 왜 어디에 무엇이 보였는지 |
| 사용자 선택 | selectionInstanceId, expressionId, catalogVersion, labelSnapshot, scope, target, phase, explicit liking/intensity/fit | 실제 사용자가 무엇을 기록했는지 |

‘목록에 포함됨’, ‘화면 안에 들어옴’, ‘실제로 읽었다’는 다르다. 뷰포트 진입은 제시 상태일 뿐 주목·독해를 확인한 데이터가 아니다. 읽었는지 모르면 미확인으로 둔다. 후보와 배치 기록은 우선 로컬 입력 출처 정보로 보존하고, 별도 동의 없이 외부 분석 전송을 추가하지 않는다.

프로필·위치·자동 추천은 감각 관찰이 아니다. 재료 비유는 실제 재료 확인이 아니다. 버블을 고르지 않음은 해당 맛의 부재·싫어함·0점이 아니다. 같은 식사의 여러 표현은 같은 경험 ID로 묶고 근거를 중복 부풀리지 않는다.

`intrinsicIntensity`는 라벨에 명시되고 정의가 검토된 경우에만 사용한다. `또렷한`이나 축 위치로 강도를 만들지 않는다. 호감과 적정 수준은 각각 사용자가 답한 경우에만 존재한다. 맛의 조합을 좋다고 선택한 것은 구성 요소 하나하나에 좋아함을 복제하는 근거가 아니다.

### 10.2 연결 계약 보완

`relatedBubbleID` 하나로 모든 의미 상속을 처리하지 않고 `scopeKind`와 `bindingMode`를 추가한다. `bindingMode=modifier`인 허용된 표현만 명시된 버블 속성을 수식한다. `independent`는 자기 감각 속성과 부위를 유지한다. `relation`은 두 맛·재료 간의 관계를 보존한다.

동일 표현 ID의 여러 부위·시점 선택을 지원하려면 안정된 `selectionInstanceId`를 따로 둔다. 지금 파서의 같은 ID 충돌 처리와 배열 토글 코드는 이 단위에 맞춰 변경해야 한다. 신규 필드를 쓰더라도 기존 기록 읽기는 깨지지 않아야 한다. 알 수 없는 필드·버전은 원문을 보존하고 미확정으로 남긴다.

복합 인상 및 아직 등록되지 않은 `app.*` 의미는 검색·회상에 활용할 수 있지만, 실행 사전·정규화 규칙이 준비되기 전에는 자동 프로필 점수 갱신을 하지 않는다.

### 10.3 디테일 의미를 실행 규칙으로 옮기기 위한 구분

JSON의 `semantic_facets`는 라벨에 명시된 상태·강도·적절성·시점·관계를 구분한 **후보 정의**다. 현재 앱 파서에 등록되었거나 사용자 검증을 통과했다는 뜻이 아니다. 같은 `attribute_candidate`를 가진 표현도 아래 값을 포함하여 구분해야 한다.

| 표현 | 구분할 후보 의미 | 추가로 추론하지 않는 값 |
|---|---|---|
| 소스가 꾸덕함 / 소스가 묽음 | 점도 인상의 `thick` / `thin`, 대상 `sauce` | 소스의 실제 농도·호감 |
| 국물이 걸쭉함 / 국물이 묽음 | 점도 인상의 `thick` / `thin`, 대상 `broth` | 소스의 상태와 동일한 대상 |
| 음료가 걸쭉함 / 음료가 묽음 | 점도 인상의 `thick` / `thin`, 대상 `beverage` | 사용자에게 알맞은 농도 |
| 탄산이 잔잔함 / 탄산이 강함 | `gentle_carbonation` / `strong_carbonation`; 강함만 명시 강도 후보 | 잔잔함을 작은 기포·신맛으로 자동 변환 |
| 기포가 잘게 느껴짐 / 큰 기포가 느껴짐 | 기포 크기 인상 `fine_bubbles` / `large_bubbles` | 실제 지름·탄산 자극 강도 |
| 농도가 내게 너무 옅음 / 알맞음 / 너무 진함 | `below_preferred` / `just_right` / `above_preferred` | 점도·개별 미각 강도·전체 호감 |
| 첫 모금 / 씹는 동안 / 삼킨 뒤 / 반복해서 마심 | 서로 다른 `temporal.event` | 첫 모금을 첫입으로, 지속을 강도로 치환 |
| 단맛과 짠맛이 어울림 | `binding_mode=relation`, 두 맛과 `harmonizes` 관계 | 각각의 맛을 좋아한다는 독립 근거 |
| 우유가 커피 맛을 가림 | 우유를 source, 커피를 target으로 하는 `masks` 관계 | 실제 우유 양·커피 추출 원인 |

수식 가능한 흐름 태그는 `binding_mode=modifier`로 두고 사용자가 지정한 음식 전체 또는 선택 버블을 수식한다. 향·질감·온도·매운 자극은 자기 속성을 유지하는 `independent`다. 관계 태그는 `relation`으로 별도 보존하며 부모 버블 하나에 전부 귀속하지 않는다. ‘끝맛이 가벼움·무거움’과 기존 복합 인상은 뜻을 특정 미각으로 확정하지 않고 보존한다.

디테일 정의는 이번에 `redesign-candidate-3`으로 구분했다. 이전 후보는 개별 `definition_version`이 없었으므로 `detail_definition_archive`에 `candidate-2` 카탈로그의 122개 원본 정의를 보관했다. 같은 ID라도 기존 선택을 새 정의로 소급 재해석하지 않는다. 실제 구현에서는 저장된 카탈로그 버전으로 해당 정의를 조회하고, 버전을 알 수 없으면 원문을 보존한 미확정 상태로 둔다.

`beverage`, `rice_grains` 대상과 세부 시점 값도 이번 후보 계약에 속한다. 실행 파서가 지원하기 전에는 기존 대상이나 시점으로 임의 치환하지 않는다. 의미가 겹치는 버블·태그는 같은 경험·대상·시점의 보완으로 묶되 각 원문 선택 이벤트를 유지한다.

## 11. 기존 72개·845개와의 관계 및 마이그레이션

| 기존 표현/규칙 | 새 입력의 처리 | 이전 기록 |
|---|---|---|
| 구운 향·탄 향·훈연감이 강함을 쓴맛 영역에 표시 | aroma 계열 디테일 후보 | 기존 버블 ID와 라벨을 그대로 보존. 이미 분리된 분석 속성은 존중 |

| 강도값으로 자동 평점 계산 | 새 어휘·새 입력에서 사용 금지 | 기존 함수 존재와 실제 호출 여부는 구현 단계에서 구분 검증 |
| 845개 광범위 어휘 | 6축 어휘/디테일/별칭/보류로 분류할 원천 후보 | 845개 전체를 그대로 새 앱에 탑재하지 않음 |

v1/v2 카탈로그를 함께 읽을 수 있는 레지스트리를 둔다. 편집 복원 시 새 카탈로그의 `validExperienceIDs`에 없다는 이유로 기존 선택을 삭제하지 않는다. 불명확한 옛 정의는 원문 선택을 계속 보여주고 분석은 보류할 수 있다.

같은 말이라도 정의가 달라졌으면 새 버전이다. 화면상의 이관은 사용자 입력 이벤트를 새로 만든 것이 아니며, 이관 결과를 사용자가 새로 확인한 근거로 세지 않는다. 과거 기록은 당시 질문·라벨·대상으로 재현한다. 롤백 시에도 v2 원문을 보존하고 지원 불가 선택은 읽기 전용으로 남긴다.

## 13. 수용 기준과 검증 계획

### 데이터·배치 불변조건

모든 음식에서 6축이 유지되고 지도 후보가 96개를 넘어야 한다. 확장안 160개의 ID가 음식별로 삭제·중복되지 않아야 한다. 앵커는 고정되고, 기본 순서와 비교한 이동은 최대 24개이며 최소 136개 위치를 유지한다. 같은 입력·버전이면 같은 배치다. 자리 부족·NaN·중심 겹침은 조용한 폴백이 아니라 테스트 실패로 처리한다.

부정적 경험을 기록할 수 있는 대안은 프로필에서 지워지지 않아야 한다. 전체 평가만 바꿔도 후보·순서·배치는 같아야 한다. 회에 산미 소스가 없다는 이유로 신맛 버블을 삭제하지 않되, 회라는 이유만으로 산미를 중앙 우선시키지도 않는다.

### 의미·복원 테스트

‘구운 향 → 쓴맛’, ‘부드러움 → 지방감’, ‘얼얼함 → 쓴맛’, ‘떫음 → 쓴맛’, ‘탄산 → 신맛’, ‘강함 → 싫어함’, ‘중앙 배치 → 좋아함’의 자동 변환이 없어야 한다. ‘첫입’과 ‘식사 초반’, ‘삼킨 뒤’와 ‘식사 후반’을 구분한다.

새 맵에 없는 v1 버블을 편집·저장해도 원문이 사라지지 않아야 한다. 수식 대상 삭제·음식 종류 수정·오프라인 재시도·알 수 없는 버전에서도 원문은 보존한다. 같은 의미의 버블+수식 태그가 관찰 수를 부풀리지 않아야 한다.

커피·차·탄산음료는 기본 후보에서 ‘씹을수록·첫입·다음 한입·익힘’이 제외되어야 한다. 씹는 구성 확인 시 허용된 씹기 태그만 추가한다. 우유 미확인 커피에는 우유·커피 관계 태그가 기본 노출되지 않아야 하며, 우유 확인 시 세 관계 후보를 함께 제공한다. 얼음·드레싱·층별 구성·구운 반죽 조건도 미확인/확인/해제/상충 상태별로 검사한다.

‘꾸덕함/묽음’, ‘탄산이 잔잔함/강함’, ‘기포가 잘게/크게 느껴짐’, ‘농도가 내게 옅음/알맞음/진함’은 정규화 뒤에도 구분되어야 한다. 관계 표현에서 구성 요소별 호감이 만들어지지 않아야 한다. 프로필 후보가 교체되어도 저장된 태그와 직접 입력은 보존한다.

### 화면·사용자 검증

작은/큰 휴대폰 화면, 큰 글자, VoiceOver, 줄바꿈, 선택 버블 1~3개 조합, 모든 축 끝부분 팬/줌을 확인한다. 모든 버블을 한 화면에 보이게 하려고 글씨를 줄이지 않는다. 선택 중 음식 자동 결과가 도착해도 화면이 재배치되지 않아야 한다.

소규모 어휘 검토에서는 각 사람이 비슷한 단어를 자기 말로 설명하고 실제 음식 경험에 적용하는지 확인한다. 160개를 한 사람에게 한꺼번에 평가시키지 않는다. 비유형과 지방감 표현은 우선 검토한다. 배치 비교는 고정 지도와 부분 재배치 지도에서 원하는 단어 찾기·되돌아가기·잘못 누르기·표현 부족을 측정한다.

단어 선택률이 늘었다는 이유만으로 감각 기록이 더 정확해졌다고 결론내리지 않는다. 배치 변화가 선택을 유도했을 가능성과 실제 감각 차이를 함께 점검한다. 노출되지 않은 후보와 미선택 후보의 차이를 유지한다.

이번 개정에서는 **후보 JSON의 개수·중복·참조, 이전 정의 보존, 의미 대비 쌍, 음식별 기본 및 조건부 후보 조합**을 로컬에서 검사했다. 네이티브 좌표·성능·타이포그래피·사용성의 통과를 뜻하지 않는다.

## 14. 참고 근거의 범위

프로젝트 원본은 1절의 실제 읽은 파일과 `docs/product/tba-sensory-data-design.md`를 기준으로 삼았다. 후자는 명시적 관찰·전체 호감·감각 평가·대상·시점·미확정 정보를 분리하고, 디테일의 대상이 활성 인덱스만으로 정해지지 않아야 한다는 수집 계약을 담고 있다.

WCR의 Sensory Lexicon 공식 소개는 단어와 참조를 함께 정의하는 방법을 참고하는 데 사용했다. 커피용 전문 사전을 한국어 일반 식사 기록에 그대로 적용하거나 이번 160개 표현의 검증 근거로 인용하지 않는다.

Ares & Jaeger(2013), *Check-all-that-apply questions: Influence of attribute order on sensory product characterization*, DOI `10.1016/j.foodqual.2012.08.016`의 공개 초록은 선택지 순서와 질문 위치의 편향을 검토한 연구임을 확인하는 데만 사용했다. 이번 UI의 효과나 최적 버블 수를 검증한 결과로 주장하지 않는다.

후보 어휘의 사용 빈도·일반 사용자 이해도·실제 기기 선택 시간은 이번 작업에서 측정하지 않았다. 공개 자료 원문 일부 접근은 제한되어 공개 초록과 공식 소개 범위만 사용했다.

## 부록 D. 다음 구현 에이전트에게 전달할 범위

이 문서와 JSON을 **검토된 제품 방향 및 미검증 어휘 후보**로 구분해서 읽는다. JSON을 실행 사전에 바로 덮어쓰지 않는다. 먼저 기존 기록·정의 버전·선택 인스턴스와의 호환을 구현하고, 어휘 의미를 검수한 뒤 6축 부분 재배치와 관점형 디테일 프로필을 연결한다. 이번 설계에서 합의한 구조를 한 축 포커스, 음식 부위별 상위 카테고리, 긍정 태그만 우선하는 구성으로 되돌리지 않는다.
