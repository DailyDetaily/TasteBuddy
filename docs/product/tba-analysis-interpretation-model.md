# TBA 분석·해석 모델

작성일: 2026-09-06 · 버전: 0.2 · 상태: 개인 취향 이해·다양한 해석 우선의 모델 계약, 학습·성능 검증 전

[플랫폼 아키텍처](./tba-data-platform-architecture.md) · [수집 계약](./tba-sensory-data-design.md) · [기대 결과 사례](./tba-model-contract-examples.json)

**분석의 최우선 목적은 사용자의 취향을 이해하는 것이며, 해석은 정제한 근거를 다양한 관점의 인사이트로 돌려주는 것이다.** 감각·강도·호감·음식 전체 평가·대상·시점·맥락을 각각 보존해 같은 관찰을 여러 출력에 재사용한다. 비슷한 입맛 그룹 연결을 후속 단계로, 그 그룹의 추천·평가에 기반한 식당·메뉴 추천을 추가 단계로 둔다.

직접 기록의 요약·조건별 차이·미확정 지점은 근거가 허용하는 범위에서 먼저 제공한다. 예측 모델이 아직 없다는 이유로 이런 해석을 미루지 않는다. 넓은 취향 일반화나 미래 예측은 해당 주장에 맞는 검증을 거친 뒤 추가한다.

## 1. 모델이 답할 질문

| 모델 | 질문 | 학습 근거 | 출력 |
| --- | --- | --- | --- |
| M0 음식 식별 | 어떤 음식과 구성을 가리키는가? | 메뉴·별칭·재료·조리 정보, 사용자 정정 | 음식 후보, 채택 근거, 미확정 부분 |
| M1 의미 추출 | 사용자가 실제로 무엇을 말했는가? | 질문·선택지 정의, 원문 구절 | 출처가 있는 관찰, 모호한 뜻 |
| M2 음식 감각 | 이 음식에서 어떤 감각을 예상할 수 있는가? | 조건이 있는 시식·시료·조리 자료 | 속성별 예상 분포 또는 미확정 |
| M3 전체 호감 | 이 사용자가 이 음식을 좋게 평가할 가능성은? | 명시적 전체 호감과 당시 사용 가능했던 음식·상황 정보 | 호감 범주별 예측 분포 |
| M4 감각과 호감의 관계 | 어떤 감각·수준·조건을 좋게 느끼는가? | 감각에 대한 직접 평가, 적정 수준 응답, 반복 경험 | 조건별 관계·예외·불확실성 |
| M5 선택 | 그룹 연결 이후 어떤 식당·메뉴가 개인에게 참고가 되는가? | 그룹의 추천·평가, 후보 노출, 직접 선택 의향, 실제 선택, 당시 조건 | 후속 추천의 근거와 후보 순위 |
| M6 해석 | 같은 기록에서 어떤 취향 관점·차이·예외를 이해할 수 있는가? | 관찰, 모델 결과, 대안, 반대 근거 | 경험 요약·감각 프로필·조건 비교·미확정 정보 등 다양한 인사이트 |
| M7 그룹 연결 | 어떤 입맛 그룹과 무엇이 비슷하고 다른가? | 공유가 허용된 비교 가능한 개인 취향 근거와 결측 | 후속 그룹 연결, 유사점·차이·비교 범위 |

M0·M1은 검토된 규칙으로 시작할 수 있고 M6도 템플릿으로 작동한다. 번호는 역할 식별자이며 구축 우선순위나 대형 모델·별도 서비스 하나를 뜻하지 않는다. 초기에는 M0·M1에서 정제한 근거로 M6의 개인 해석을 제공하고, 관계 분석·M7 그룹 연결·M5 추천을 단계적으로 확장한다. 전체 반응 하나만 있으면 M3의 학습 자료가 되고, 버블 하나만 있으면 감각 관찰이 되며 M4의 선호 라벨을 만들지는 않는다.

## 2. 모든 모델에 적용하는 입력 규칙

### 2.1 서로 바꾸지 않는 결과 변수

| 기록 | 내부 값 예시 | 학습 가능한 대상 |
| --- | --- | --- |
| 전체 음식: 좋았어요·괜찮았어요·아쉬웠어요 | `positive / neutral / negative` + 질문 버전 | 음식 전체 호감 |
| 바삭한 | `sensory_presence(texture.crisp)` | 보고된 감각 |
| 진한 감칠맛 | 존재 + 해당 표현 척도의 `strong` | 보고된 감각과 표현상 강도 |
| 이 훈연향이 좋았어요 | `attribute_liking(aroma.smoky)=positive` | 해당 감각의 호감 |
| 소스가 너무 달아요 | `preference_fit(taste.sweet)=above_preferred` | 대상·조건 안에서 원하는 수준과의 차이 |
| 맛있지만 비싸서 다시 안 갈래요 | 전체 호감 긍정 + 가격 맥락 + 방문 의향 부정 | 맛 호감과 선택을 각각 학습 |

세 범주의 전체 반응은 제품 척도 제안이다. `neutral`은 사용자가 그 뜻으로 이해하는지 확인해야 하며 `unknown`, `skipped`, 빈 입력과 다르다. 다른 설문·평점·연구 척도는 원래 척도를 보존하고, 확인된 변환 없이 평균 내지 않는다.

### 2.2 결측·중복·관련성

- 미선택 버블은 부재·싫어함·강도 0의 라벨이 아니다. 제시하지 않은 표현과 제시했지만 고르지 않은 표현도 구분한다.
- 같은 의미를 부모·자식 버블이나 문장으로 반복해도 해당 관찰의 독립적인 지지가 늘어나지 않는다. 원문 참조는 모두 남길 수 있다.
- 학습 행의 기본 키는 `experience + target + kind + attribute + phase + scale + active_revision`이다. 같은 질문의 정정은 이전 라벨을 교체한다.
- 하나의 경험에 여러 종류의 라벨이 있으면 같은 경험의 관련 결과다. 전체 평점을 감각마다 복제하지 않는다. 여러 모델의 출력도 독립된 검증 표본으로 합산하지 않는다.
- 한 식사의 여러 디시, 한 접시를 공유한 여러 사용자, 같은 사용자의 반복 식사를 군집으로 추적한다. 경험 개수와 통계적으로 독립인 표본 수를 동일시하지 않는다.
- 의미가 분명한 관찰은 즉시 활용하고 미확정 필드만 보류한다. 기록 완성도·문장 길이·응답 속도로 사용자의 말을 일괄 할인하지 않는다.

## 3. M0·M1: 음식과 언어를 해석하는 방법

메뉴 식별은 `정확한 ID → 검토한 별칭 → 음식 범위가 맞는 이름/구성 후보 → 미확정` 순으로 처리한다. 이름이 비슷하다는 점은 후보를 찾는 근거이며 음식의 동일성을 확정하는 근거가 아니다. 알려진 재료·음식 범위와 충돌하는 후보는 채택하지 않는다.

M1은 `choice_mapping`을 우선한다. 검토한 의미 사전으로 처리할 수 없는 자유문장에는 LLM 추출을 사용할 수 있다. 필드마다 원문 위치와 대상·시점·부정·비교 기준을 반환해야 한다. 추출 결과의 검사는 다음 순서를 따른다.

1. 실제 원문에 해당 구절 또는 선택지가 있는가?
2. 질문과 원문이 가리키는 대상에 붙었는가?
3. 긍정·부정, 강도·호감, 현재·과거·가정이 보존됐는가?
4. 명시하지 않은 강도·재료·원인·재선택 의향을 채우지 않았는가?
5. 모호한 부분을 미확정으로 남겼는가?

LLM이 낸 “확신 0.9”는 모델 품질 평가를 대신하지 않는다. 이전 취향 프로필과 맞지 않는다는 이유로 새로운 관찰을 수정하지 않는다. 한 문장의 여러 추출은 공통 원문과 경험을 공유한다.

## 4. M2: 음식의 감각 특성 모델

음식 특성의 내부 표현은 맛, 향, 식감, 온도, 구강 자극, 여운·시간 변화를 확장 가능한 속성으로 가진다. 기존 6축은 탐색과 요약에 활용할 수 있지만 모든 표현을 6개 숫자로 강제 환산하지 않는다.

초기에는 확인된 음식 구성과 시식 자료의 범위만 사용한다. `z`를 특정 조건의 감각 상태, `K`를 음식 지식이라 하면 장기 목표는 다음 분포다.

```text
q(z | 음식/판매 메뉴 버전, 조리·제공 조건, K, 연구 절차)
```

이 분포를 학습할 자료가 없으면 감각 수치를 만들어 넣지 않는다. 음식 종류·확인된 재료·조리법을 M3의 알려진 특징으로 사용하고, 감각 예상은 미확정으로 둔다. 미확정 필드의 0.5 기본값을 실제 중간 강도로 취급하지 않는다.

자료를 추가할 때는 다음 경로를 구분한다.

- 훈련 패널·실제 시식 자료는 해당 시료와 척도에 관한 감각 근거다.
- 앱의 버블 선택은 무엇이 기억에 남아 보고됐는지에 관한 자료다. 선택하지 않은 버블을 부재로 학습하지 않는다. 공통 질문을 제시한 별도 평가 자료가 있어야 선택적 보고의 영향을 더 검토할 수 있다.
- 물질 존재·함량·조리 자료는 감각을 예상하는 설명 변수다. 그 자체가 사람의 시식 라벨은 아니다.
- 사진에서 예상한 감각은 별도 추정 출처다. 실제 시식 자료와 같은 라벨로 섞지 않는다.

개인의 지각 차이와 표현 차이를 분리하는 모델은 공통 시료·반복 관찰·척도 연결이 있을 때 검토한다. 일상 기록만으로 식품의 객관적 강도와 생리적 민감도를 각각 알아냈다고 설명하지 않는다. 설문 답변으로 유전자나 미각 수용체 유형을 추정하는 경로도 두지 않는다.

## 5. M3: 전체 호감 예측

### 5.1 기준 모델과 첫 개인화 모델

기준 모델은 메뉴별 전체 반응 분포다. 해당 메뉴의 자료가 부족하면 음식군, 그마저 부족하면 전체 분포로 완만하게 보완한다. 개인화 모델이 이 기준보다 미래 식사를 잘 예상하는지 비교한다. 기준 분포도 실제 평가 전에는 정확도나 사용자 확신으로 표시하지 않는다.

호감 예측 계층을 검증할 때의 첫 개인화 후보는 **계층적 순서형 로지스틱 회귀**다. 호감 범주의 순서를 보존하고, 개인 자료가 적으면 전체 경향에서 크게 벗어나는 추정을 억제한다. 이는 기본 개인 해석을 제공하기 위한 선행 조건이 아니다. 순서형 결과와 계층적 회귀의 구성 방법은 [Stan 공식 문서](https://mc-stan.org/docs/stan-users-guide/regression.html)를 참고했다. 아래 변수·제약·단계는 TBA를 위한 설계 제안이다.

```text
y_e ∈ {1: negative, 2: neutral, 3: positive}

P(y_e ≤ k) = sigmoid(τ_k − η_e),  k ∈ {1, 2},  τ_1 < τ_2

η_e = b_user[u] + b_dish[d] + h_meal[m]
      + Σ_j (β_j + δ_user[u,j]) · x_pre[e,j]
      + γ · context_pre[e]

δ_user[u,j] ~ Normal(0, σ_j²)
```

| 항목 | 의미 |
| --- | --- |
| `b_user` | 개인이 전체 평가 범주를 사용하는 평균 경향 |
| `b_dish` | 알려진 음식 특징으로 설명되지 않는 메뉴별 차이 |
| `h_meal` | 같은 식사의 여러 음식에 공통으로 생기는 차이 |
| `β` | 전체 자료에서 배우는 특징과 호감의 관계 |
| `δ_user` | 전체 관계에서 벗어나는 개인별 차이 |
| `x_pre` | 실제 추천 시각에 사용 가능했던 음식 특징 |
| `context_pre` | 당시 명시된 목적·조건 등. 미수집 상황은 결측 |
| `τ` | 세 호감 범주를 나누는 순서 있는 경계 |

식별 가능한 모델이 되도록 별도 전역 절편은 넣지 않고 집단 효과를 중심화한다. 초기에는 개인별 경계값과 개인 절편을 동시에 자유롭게 학습하지 않는다. 새 식사의 `h_meal`은 미지의 값이므로 예측 시 분포에 대해 적분한다. 새 메뉴·사용자도 해당 집단의 불확실성을 반영한다.

카테고리 특징은 범주와 미확정 상태로 인코딩한다. 연속 특징은 학습 구간에서 정한 변환만 적용하고 원 단위·관측 여부를 보존한다. 결측 대체가 필요한 구현에서도 별도 결측 표시와 대체 방법을 저장하며, 대체값을 실제 감각 관찰로 출력하지 않는다. 초기에는 작은 특징 집합을 사용하고 845개 단어를 곧바로 개인별 자유 파라미터 845개로 만들지 않는다.

### 5.2 식후 정보가 식전 예측으로 새어 들어가지 않게 한다

미래 추천의 입력에 **예측하려는 바로 그 식사의 식후 버블·후기·평점**을 사용하지 않는다. 해당 사용자가 전에 남긴 다른 경험은 예측 시점 이전의 이력으로 사용할 수 있다.

음식 감각 예상 모델 M2를 붙인 뒤에는 해당 시각에 얻을 수 있었던 감각 분포만 사용한다.

```text
P(y_next | 이전 개인 기록, 당시 음식 지식, 현재 조건)
  = ∫ P(y_next | z, 개인 상태, 현재 조건) · q(z | 당시 음식 지식) dz
```

M2를 학습할 때에도 평가할 식사의 관찰을 포함하지 않는다. 평가용 M2 특징은 학습 구간 내 교차 예측이나 과거 시점의 모델로 생성한다. 음식 지식도 그 시점의 스냅샷을 사용한다. 이후 수정된 레시피나 새로 수집된 후기를 과거 예측에 넣으면 별도의 회고 분석으로 표시한다.

### 5.3 추정과 갱신

첫 검증 모델은 작은 자료에서 사후분포를 추정해 작동을 확인한다. 운영 시에는 검증한 근사 추정과 공유 모델 산출물을 사용할 수 있다. 추정 방법·초기값·난수 시드·자료 버전·진단 결과를 모델 카드에 남긴다. 근사 추정의 구간도 실제 미래 자료에서 보정 상태를 확인한다.

공유 파라미터는 배치로 갱신하고 개인 상태는 현재 유효한 관찰 집합으로 다시 추정한다. 새 입력에 고정 점수를 더하는 누적 카운터를 개인 확신으로 사용하지 않는다. 모델 파라미터의 사전분포와 복잡도는 사전 예측 검사·시간순 평가로 정하며, 문서에 임의의 점수 가중치를 확정값으로 넣지 않는다.

## 6. M4: 조건에 따른 감각 선호

전체 호감 모델과 감각 평가 모델을 구분한다. `전체 긍정 + 바삭함`은 두 사실의 동시 관찰이다. 전체 긍정을 `바삭함 긍정`으로 복사하지 않는다. 전체 호감과 감각 사이의 통계적 관련성은 탐색할 수 있으나 원인 설명은 별도 검증이 필요하다.

M4의 직접 학습 대상은 `attribute_liking`, `preference_fit`, 명확한 대상의 `comparison`이다. 강도를 함께 알 때는 사용자가 실제 사용한 척도 안에서 관계를 추정한다.

```text
f(user, attribute, level, dish_context, target, phase)
  → 감각에 대한 호감/원하는 수준의 조건부 관계
```

초기의 `weak / medium / strong`은 순서가 있는 범주로 다루고 등간격 농도로 가정하지 않는다. 같은 사용자의 반복 자료가 있으면 수준별 효과를 규제해 추정한다. 공통 척도의 연속 시식값이 확보되면 스플라인 같은 완만한 곡선을 검토한다. 강할수록 좋다거나 모든 감각에 최적점 하나가 있다는 형태를 강요하지 않는다.

`above_preferred`와 `below_preferred`는 원하는 수준과의 관계다. 실제 감각 수준이 없으면 절대 선호 지점까지 계산하지 않는다. 단맛이 과했다고 말한 경험 하나에서 디저트 전체 회피를 만들지 않는다.

조합 효과는 단일 속성과 별도로 둔다. 예를 들어 지방감과 산미의 조합은 두 감각과 평가가 함께 관찰된 범위에서 검토한다. 자료가 부족한 개인·음식 조합은 효과를 축소하거나 사용을 보류한다. 음식 형태·소스·부위·시점이 다른 결과를 평균 하나로 지우지 않는다.

첫입의 훈연향 긍정과 식사 후반의 소스 단맛 부담은 서로 다른 조건의 결과다. 같은 시간 범위의 반대 반응은 예외·상황·음식 상태의 후보로 검토하고 사용자의 오류로 자동 처리하지 않는다.

## 7. M7 그룹 연결과 M5 식당·메뉴 추천 — 후속 단계

개인 취향의 해석과 인사이트를 제공한 뒤, 비슷한 입맛 그룹을 연결한다. 공유가 허용된 근거에서 비교 가능한 감각·호감·음식 조건을 맞추고 유사점·차이·비교하지 못한 영역을 함께 반환한다. 감각을 느꼈다는 기록과 그 감각을 좋아했다는 기록을 같은 선호 특징으로 넣지 않는다. 공통 관찰 부족을 낮은 유사성으로 확정하지 않는다.

그룹은 조건과 근거에 따라 연결·수정될 수 있다. 그룹의 평균이나 다른 사람의 평가가 개인의 명시적인 선호를 덮어쓰지 않는다. 그룹 비교용 특징의 준비와 실제 그룹 매칭·연결의 검증은 별도 단계다.

맛의 호감과 방문·주문 의향을 구분한다. 가격·거리·현재 목적·새로운 음식에 대한 의향은 선택 모델에서 다룬다. 클릭·저장·방문·주문·실제 섭취·호감은 서로 다른 사건이다.

그룹 기반 식당·메뉴 추천을 추가할 때는 다음 순서로 정한다.

1. 비슷한 입맛 그룹의 명시적 추천·긍정 평가·실제 식사 기록에서 식당·메뉴 후보를 구성하고 출처를 구분한다. 현재 조건과 사용자가 명시한 제외 조건을 적용하며 미확인 재료를 없다고 간주하지 않는다.
2. 그룹과 개인의 어떤 공통 취향이 해당 후보에 관련되는지 설명한다. 충분히 검증한 경우 과거의 개인 경험, 음식 관계와 M3의 예상으로 순위를 보완한다. 모델 미검증 상태에서는 그룹 기록에서 찾은 탐색 후보로 표시한다.
3. M4를 추가할 때는 해당 조건과 근거가 확인된 부분만 반영한다. 해석 문장의 수를 추천 가중치로 사용하지 않는다.
4. 중복되는 메뉴를 줄이고, 사용자가 원한 범위에서 새로운 후보를 섞는다. 탐색 방식과 실제 무작위 노출 확률을 기록한다.
5. 후보를 생성한 기록과 실제로 화면에 보인 기록을 구분해 저장한다. 순위·이유·모델·정책 버전을 함께 남긴다.

충분한 노출·선택 자료가 확보되면 후보 집합 `C`와 선택하지 않음 `outside`를 포함한 선택 모형을 비교한다.

```text
P(choice=d | C, current_context) = softmax(U_d over C ∪ {outside})
U_d = 맛의 예상 가치 + 명시된 상황 적합성 + 학습된 선택 요인
```

무응답·앱 이탈은 `outside` 선택과도 다르므로 관측된 거절/다른 선택만 그 라벨로 사용한다. 유효한 후보 집합을 모르는 과거 선택은 완전한 선택모형의 학습 행으로 가장하지 않는다. 비교 응답은 실제로 먹은 경험을 참조하고 새 식사 수를 추가하지 않는다.

협업 필터링은 여러 사용자가 겹치는 메뉴·음식군을 평가한 자료가 있을 때 비교한다. 미평가를 낮은 호감으로 처리하지 않는다. 그룹 연결은 후속 제품 가치이며, 고정된 군집 하나에 영구 배정하는 알고리즘을 필수 조건으로 두지 않는다.

## 8. M6: 가설 생성·비교·채택

### 8.1 가설의 형태

```text
hypothesis_id, claim, conditions, target, phase
direct_support_refs, cooccurrence_refs, counter_refs
alternative_hypothesis_refs, unresolved_factors
state, allowed_uses, model_version, evidence_set_hash
posterior_statement: 정의·검증된 수학적 명제가 있을 때만
```

한 입력에서 다양한 가설을 만들 수 있다. 다만 `감칠맛이 부담스러움`, `식감이 아쉬움`, `소스 조합의 문제`는 동시에 가능할 수 있으므로 합이 100%인 확률로 강제 정규화하지 않는다. 명확히 정의된 상호 배타적 모델 비교가 없는 자연어 가설에는 확률을 붙이지 않는다.

후보는 검토한 패턴 규칙, 조건별 통계, 필요한 경우 LLM 제안으로 만든다. 지지·반대·동시 관찰을 구분하고, 입력에 등장하지 않은 구체 원인을 사실처럼 추가하지 않는다. 무한히 많은 가설을 저장하기보다 다음 설명·선택·질문에 차이를 만드는 후보만 남긴다.

### 8.2 상태와 사용 범위

| 상태 | 판정 | 허용 범위 |
| --- | --- | --- |
| `candidate` | 근거가 연결된 검토 후보, 일반화 미검증 | 내부 검토·질문 후보. 단정적 프로필과 회피 조건에는 사용하지 않음 |
| `provisional` | 아래 채택 조건을 모두 통과한 제한적 관계 | 조건을 붙인 잠정 설명·검증한 추천 특징 |
| `contested` | 같은 적용 범위의 반대 근거 또는 중요한 대안이 남음 | 적용 범위 축소·확인·재검토. 단정적 추천 근거에서 제외 |
| `inactive` | 근거 삭제·정정·대체로 더 이상 유효하지 않음 | 활성 설명·추천에서 제외 |

직접 응답의 요약은 가설 승격을 기다리지 않는다. 한 번의 감각 긍정도 “이번 음식의 이 감각을 좋게 느꼈다”까지 바로 설명할 수 있다. 일반화된 개인 취향으로 사용하려면 추가 조건이 필요하다.

`provisional` 채택은 다음 조건의 AND다.

1. **근거 유효성:** 활성 원문과 관찰로 추적 가능하고 재시도·재분석·동의어를 중복 지지로 세지 않는다.
2. **범위 일치:** 음식·부위·시점·맥락이 주장과 일치한다. 모르는 조건까지 확장하지 않는다.
3. **근거 종류 일치:** 감각 선호라는 주장에는 직접 감각 평가나 그 주장 수준에 맞게 검증된 관계가 있다. 전체 평가와 동시 선택만으로 원인을 주장하지 않는다.
4. **반대 근거 검토:** 동일 범위의 반례가 해결되지 않았다면 `contested`로 둔다. 긍정 기록만 골라 설명하지 않는다.
5. **안정성과 적용 가능성:** 한 식사 군집을 제외했을 때 결론의 방향이 쉽게 뒤집히거나 새로운 조건이면 일반화를 보류한다. 단순 입력 개수로 승격하지 않는다.
6. **검증 정책 통과:** 해당 주장 유형·음식 범위에서 근거 일치·관계의 안정성·잘못된 설명의 허용 기준을 통과한 정책이 있다. 미래를 예측하는 주장에는 미래 예측·보정 기준을 추가한다.

초기 파일럿에서 검증 정책이 아직 등록되지 않았으면 자동 승격하지 않는다. `max_false_claim_rate`, 적용 가능한 범위와 검토 표본은 최종 평가 전에 고정하고, `min_predictive_gain`은 예측 주장에 적용한다. 임계값 미설정은 통과로 처리하지 않는다. 이는 무조건 여러 기록이 있어야 요약할 수 있다는 제한이 아니라, 개인 취향을 넓게 단정하는 단계의 조건이다.

### 8.3 출력 계약

경험 요약·속성 프로필·조건 차이·예외·변화·그룹 비교 등 출력 유형마다 같은 활성 근거를 읽는 생성기를 둔다. 각 출력의 내용은 다음 네 가지를 구분한다.

- `observed`: 이번 또는 명시한 과거 기록에서 확인된 내용.
- `tentative`: 허용된 조건부 패턴. 없으면 비운다.
- `unknowns`: 취향 이해에 중요한 미확인 정보만 선택한다.
- `next_action`: 선택적인 확인·정정·관련 경험 탐색. 후속 추천 단계에서는 후보를 포함할 수 있다. 필수 필드나 항상 필요한 CTA로 취급하지 않는다.

각 문장에는 `claim_type`, `evidence_refs`, `scope`, `policy_version`을 붙인다. LLM은 허용된 주장 묶음을 문장으로 바꿀 수 있다. 참조가 깨졌거나 원래보다 강한 표현이 생기면 검증기가 해당 문장을 제거하고 직접 관찰 템플릿으로 대체한다.

정제 관찰을 새 출력에 맞춰 다시 쓰거나 생성한 해석을 새 관찰로 학습하지 않는다. 여러 출력은 같은 `evidence_set_hash`를 공유하고 자신의 생성 규칙 버전을 가진다. 비교 가능한 자료가 없는 장기 변화·그룹 유사성은 계산하지 않고 부족한 범위를 표시한다. 다양한 관점은 지원하되, 원문에 없는 성격·원인·확률을 채우는 방식으로 다양성을 늘리지 않는다.

“이번 돈가스를 좋게 기록했어요”는 직접 관찰이다. “바삭해서 좋아했어요”는 원인을 주장하므로 전체 긍정과 바삭함 선택만으로 생성하지 않는다. 사용자가 “바삭해서 좋았다”고 직접 말하면 자기보고된 이유로 인용할 수 있지만, 다른 음식에 대한 인과 효과로 확대하지 않는다.

## 9. 프로필 갱신과 취향 변화

프로필은 `직접 표현한 선호 + 검증 범위의 조건부 관계 + 관측 범위 + 미확정 영역`으로 구성한다. 대표 문장·6축 카드·비슷한 사용자 표시는 이 상태에서 만드는 별도 조회 결과다.

갱신 절차는 다음과 같다.

1. 현재 버전의 유효 관찰 집합을 고정하고 해시를 만든다.
2. 감각 관찰·전체 호감·감각 평가·선택의 해당 모델만 갱신한다.
3. 바뀐 근거를 참조하는 가설의 지지·반대·상태를 다시 계산한다.
4. 이전 파생 문장을 무효화하고 현재 근거로 다시 만든다.
5. 작업 시작 버전이 여전히 최신일 때만 개인 상태를 게시한다.

학습은 질문의 의미와 유효 관찰 기준으로 허용한다. 사진만 저장한 경우에는 음식 후보·회상 기능은 갱신할 수 있지만 감각·호감 라벨은 생기지 않는다. 새 관찰은 해당 범위에만 반영하며, 입력이 추가됐다는 이유로 모든 축의 확신을 올리지 않는다.

첫 모델은 장기 경향과 최근 기록의 차이를 관찰하되 자동 시간 감쇠를 기본 진실로 두지 않는다. 제공 음식의 변화·상황·표현·실제 취향 변화라는 대안을 검토한다. 이후 시간 가변 개인 파라미터를 도입한다면 변화 폭과 시간 단위를 미래 평가로 정한다. 식사 시각이 미확인인 기록에 정확한 시간차를 만들어 적용하지 않는다.

## 10. 추가 질문을 고르는 방법

질문은 필수가 아니다. 저장을 완료한 뒤 한 번에 하나를 제안할 수 있으며 건너뛰기는 부정 라벨이 되지 않는다.

처음에는 다음 조건으로 검토 가능한 질문 후보를 만든다.

- 하나의 중요한 감각 관계를 서로 다른 가설이 설명한다.
- 사용자가 이미 답한 내용이 아니고 대상이 명확하다.
- 답에 따라 사용자가 받는 해석이나 가설의 적용 범위가 달라질 수 있다.
- 현재 세션에서 질문을 이미 했거나 피로 신호가 있으면 다음 기회로 미룬다.

예를 들어 `전체 아쉬움 + 진한 감칠맛`에서는 감칠맛을 회피할 근거가 없다. 감각과 호감의 관계를 이해하는 데 도움이 될 때 “그 감칠맛 자체는 어땠어요?”를 후보로 둔다. 긍정 답변은 전체 평가를 바꾸지 않고 감칠맛 회피 가설의 반대 근거가 된다.

질문의 가치는 취향 이해와 해석의 불확실성을 얼마나 줄이는지, 그에 비해 응답 부담이 어떤지를 기준으로 평가한다. LLM의 자체 점수를 기대 정보량이나 실제 효용으로 사용하지 않는다. 응답률뿐 아니라 해석의 명료함·근거 충실도·사용자의 이해와 정정·기록 부담을 확인한다. 선택 개선은 후속 추천 계층에서 별도로 평가한다.

## 11. 검증과 모델 채택

### 11.1 자료 분리

최우선 평가 대상은 **정제한 기록에서 제공한 해석·인사이트가 실제 근거에 충실하고 사용자의 취향 이해에 도움이 되는가**다. 경험 요약은 해당 경험의 원문과 비교하고, 조건별 관계·변화는 그 주장이 사용한 비교 범위와 반례를 검토한다. 사용자의 단순 동의율만으로 정확성을 판단하지 않는다.

미래 호감·그룹 기반 추천을 예측하는 모델의 평가 대상은 그 시각까지의 자료로 예측한 후속 경험이다. 이때 자료를 시간순으로 나누고 같은 경험·식사·공유 제공 음식의 관련 관찰을 한쪽에 둔다. 같은 원문의 재추출·수정본이 학습과 평가에 동시에 들어가지 않는다.

개인화 유지 사용자, 새 사용자, 새 메뉴, 드문 음식군, 전체 평가만 있는 입력, 자유문장 입력을 나눠 성능을 본다. 평가용 원문은 추출 프롬프트 예시와 임계값 조정에 재사용하지 않는다. 음식 사전·검색 인덱스·M2 특징·개인 상태에도 같은 시간 경계를 적용한다.

추천과 질문은 관측할 데이터를 바꾼다. 알려진 무작위 노출 정책에서는 실제 노출 확률을 남기고, 공통 피드백 요청을 일부 유지해 선택적 보고를 살핀다. 확률을 모르는 이력에 임의 확률을 넣어 보정하지 않는다. 역확률·이중 강건 평가 등은 필요한 가정과 겹침 범위를 확인한 뒤 사용한다. [추천 데이터의 선택 편향 원연구](https://proceedings.mlr.press/v48/schnabel16.html)

### 11.2 평가 항목과 비교

| 영역 | 측정 | 비교/실패 판정 |
| --- | --- | --- |
| 개인 해석·인사이트 | 근거 일치, 유용한 관점, 조건·예외 이해, 정정 가능성 | 원문·범위·반대 근거를 독립 검토. 문장 수나 사용자 동의율만으로 성공 판정하지 않음 |
| 출력 재사용 | 같은 근거에서 다양한 출력의 의미 일관성, 출처 추적, 수정·삭제 전파 | 출력 증가가 관찰·경험 수를 늘리거나 출력을 원문으로 재학습하면 실패 |
| 음식 식별 | 정답 연결 정확도, 잘못 채택한 비율, 보류한 범위 | 이름 매칭 기준과 비교. 잘못된 강한 연결을 따로 집계 |
| 의미 추출 | 대상·부정·시점·관찰 종류 정확도, 근거 없는 필드 생성 | 사람이 검토한 원문과 비교, 부분 정답과 보류 구분 |
| 전체 호감 | 순서형 예측의 log loss·ranked probability score·보정 | 음식 평균/음식군 분포와 비교 |
| 개인화 | 사용자별 미래 성능과 집단별 편차 | 개인 기록을 제거한 동일 모델과 비교 |
| 감각 관계 | 직접 평가와 조건별 예측, 반례·범위 과장 | 전체 평점을 감각 평가로 복제한 결과를 정답으로 사용하지 않음 |
| 후속 그룹 연결 | 비교 가능한 근거의 겹침, 유사점·차이의 타당성, 사용자에게 주는 연결 가치 | 감각 존재를 선호로 복사하거나 결측을 비선호로 처리하면 실패 |
| 후속 그룹 기반 추천 | 그룹 추천·평가 출처, 개인 관련성, 실제 식후 만족·선택 도움 | 인기/유사 메뉴 기준과 비교. 최우선 개인 해석 지표와 별도 평가 |
| 해석 | 문장 근거 일치, 부당한 원인·일반화, 사용자 이해 | 원문·범위·반대 근거를 독립 검토 |
| 부담 | 저장 시간, 중단, 수정, 질문 건너뛰기 | 입력 수준별 비교. 자세한 입력률을 성공의 필수 조건으로 두지 않음 |
| 수명주기 | 재시도 불변, 수정 교체, 삭제 후 제외, 버전 충돌 | 기대 계약 사례 중 하나라도 어기면 모델 연결 중단 |

평가 오차는 사용자·식사 군집을 고려해 추정한다. 새 모델은 미리 정한 주 지표를 개선하고 보정·설명·입력 부담의 기준을 통과해야 한다. 평가 표본 수와 오차 구간 없이 “더 정확하다”고 발표하지 않는다.

### 11.3 모델을 추가하는 순서

| 순서 | 후보 | 추가 이유 | 채택 조건 |
| --- | --- | --- | --- |
| 0 | 정제 관찰과 규칙·템플릿 해석 | 적은 입력으로 다양한 개인 인사이트 제공 | 출처·의미 일치, 유용성, 원문 불변, 수정·삭제의 모든 출력 반영 |
| 1 | 감각 수준·조건·조합·시간 비교 | 개인의 선호 관계·예외·변화를 이해 | 비교 가능한 근거, 반례·범위 검토, 과도한 일반화 방지 |
| 2 | 필요한 계층적 관계 모델 | 적은 개인 기록과 전체 경향의 결합 | 목표한 해석의 개선. 미래를 예측하는 경우 기준 분포 대비 시간순 성능·보정도 검증 |
| 3 | 입맛 그룹 비교·연결 | 개인 취향을 다른 사람들과의 유사점·차이로 확장 | 공유 범위, 비교 근거, 유사성의 타당성과 연결 가치 |
| 4 | 그룹 기반 식당·메뉴 추천과 선택 모델 | 비슷한 입맛 그룹의 경험을 탐색에 활용 | 추천·평가 출처, 노출·선택 자료, 후속 만족·선택 도움 |
| 5 | 그래프·임베딩·물질 특징 | 해석·연결·추천 중 필요한 범위를 보완 | 기존 특징을 뺀 비교 실험과 적용 범위 검증 |

K-Means·DBSCAN·MDS는 군집·구조를 살펴보는 보조 도구 후보다. 군집에 이름을 붙이는 것만으로 개인 호감을 예측하거나 해석한 것으로 취급하지 않는다. GNN·임베딩은 검토된 관계와 평가 자료가 갖춰진 뒤 비교하며, 음식 그래프를 보유했다고 반드시 도입하지 않는다.

## 12. 이번 설계의 결정과 남은 실증

이번에 정한 것은 모델의 역할, 라벨, 첫 호감 모델, 식전/식후 정보 경계, 개인 상태의 갱신, 가설 상태·허용 범위, 질문 정책, 평가 절차다. [계약 예시](./tba-model-contract-examples.json)는 이 규칙을 검토하기 위한 가상 자료이며 실행된 엔진 결과나 예측 성능이 아니다.

후속 [로컬 파일럿](./tba-platform-pilot-report.md)은 작은 선택지 사전과 근거 저장·해석 규칙을 실제 SQL에서 실행한다. 그 [생성 결과](./tba-platform-pilot-results.json)는 실행된 계약 검증 자료지만, 사용자 입력은 가상이며 통계 모델을 학습한 결과는 아니다. `candidate`·`contested` 처리를 확인하고 가설을 검증된 취향으로 자동 승격하지 않는다.

파일럿의 정제·출력 생성기는 같은 유효 관찰에서 경험 요약·속성별 프로필·평가 공존 해석·선택적 확인 후보·그룹 비교 준비 특징을 만든다. 출력마다 관찰 참조·소유자와 범위·규칙 버전을 보존하며, 실제 그룹 매칭이나 추천은 수행하지 않는다.

후속 [개인 취향 분석 엔진 v1](./tba-personal-engine.md)은 이를 반복 호감·맥락별 차이·강도와 평가·조합 인사이트로 연결하고, 미각 타입의 메인·날개를 근거와 함께 제안한다. 개인 서술은 타입 소개문을 조합하지 않고 해당 발견과 원문을 입력으로 사용한다. 실제 모델 서술은 인용 검사와 의미 검증을 구분한다.

모델 가중치·사전분포의 규모·곡선 복잡도·확률 보정·잠정 해석의 허용 오판 수준은 실제 자료와 평가 없이 확정하지 않는다. 해당 값이 준비되지 않은 초기 제품도 근거에 맞는 경험 요약·감각 프로필·조건 차이·미확정 정보 등 다양한 개인 해석을 제공할 수 있다. 생리적 민감도·정확한 물질 함량·좋아한 인과적 이유를 추정 완료한 것처럼 보여주지 않는다.

계약 예시는 의미와 활성 근거의 기대 결과에 집중한 축약 자료다. 운영 API의 전체 스키마는 아니며, 실제 구현에는 소유자·기준 버전·정밀도·척도 상속·접근 범위를 포함해야 한다. 통합 검토에서는 데이터 의미, 수정·삭제, 예측 시점과 근거 범위를 우선 확인한다.
