# TBA 디시 종류 태그 설계

작성일: 2026-09-05 · 상태: 검토 후보 · 앱 코드와 기존 태그 값은 변경하지 않음.

**사용자는 면·구이·중식·발효음식처럼 익숙한 디시 종류 태그를 같은 화면에서 함께 고른다.** 면은 음식 형태, 구이는 조리 형태, 중식은 요리 문화, 발효음식은 만드는 특징을 가리킨다. 모두 음식 경험을 떠올리는 유효한 입구다. 분류 기준별로 답해야 하는 여러 단계의 설문을 만들지 않는다.

디시 종류 태그는 어떤 음식을 기록하는지 설명하고, 미각 버블은 사용자가 실제로 무엇을 느꼈는지 기록한다. 메뉴·사진으로 준비한 태그는 출처와 확인 상태를 보존한다. 태그 입력은 기록의 필수 단계가 아니다.

사용자용 입구 태그 50개와 내부 구성 태그 122개를 연결했다. 내부의 7개 기준은 저장과 조합을 위한 것으로, 사용자에게 반드시 구분해서 고르게 하지 않는다.

## 종류·메뉴·세부 맵의 구분

| 구분 | 예시 | 역할 |
| --- | --- | --- |
| 디시 종류 | 튀김 · 면 · 구이 · 중식 · 발효음식 | 여러 음식의 공통 특징을 선택 |
| 음식 이름 | 돈가스 · 짜장면 · 리조또 · 카레 | 먹은 메뉴를 원문으로 보관 |
| 세부 맵 | 크림소스 면·밥 요리 · 우유를 더한 커피 | 확인된 구성에 맞춰 버블 가지를 조합 |

`튀김·돈가스`처럼 종류와 메뉴를 하나의 태그로 합치지 않는다. 돈가스는 튀김 맵의 메뉴 예시에 둔다. 리조또·카레도 종류 목록에서 분리했다. 파스타처럼 여러 메뉴를 묶는 세부 음식군은 면의 하위 분류 후보로 두되, 크림 파스타 같은 구체 메뉴명과 구분한다.

이 구분은 저장할 정보의 역할을 나눈 것이다. 사용자는 알고 있는 종류 하나만 고르거나 메뉴 정보 없이도 기록할 수 있다. 메뉴 이름과 종류 태그를 모두 입력하게 하지 않는다.

`돈까스`처럼 사용자가 적은 표기는 원문으로 남기고, 검색용 별칭만 `돈가스`에 연결한다. 메뉴 이름은 감각 관찰의 증거가 아니다.

## 메뉴명으로 먼저 자동 선택

**메뉴를 선택하거나 이름을 입력하면 근거가 충분한 종류 태그가 먼저 선택되고 버블 맵이 준비된다.** 사용자는 틀린 태그만 고친다. 별도의 확인 단계 없이 기록·저장할 수 있다.

`돈까스 → 튀김`, `짜장면 → 면·중식`, `연어 → 생선`처럼 태그마다 판단한다. 조리법·요리 문화가 불명확하면 해당 태그만 비워둔다. 자동 선택해도 사용자가 직접 확인한 사실로 바꾸지 않는다.

자동 태그를 전부 해제하면 빈 선택을 그대로 저장한다. 다시 열거나 재추정해도 태그가 되살아나지 않게 한다. 이름이 모호하거나 분류에 실패하면 공통 맵으로 기록한다.

## 사용자에게 보이는 디시 종류

국·탕 · 찌개·전골 · 구이 · 볶음 · 찜·조림 · 회·생요리 · 튀김 · 밥·곡물 요리 · 덮밥·볶음밥 · 죽 · 면 · 파스타 · 만두·딤섬 · 두부·콩 요리 · 샐러드·생채 · 채소 요리 · 절임 · 빵 · 떡·한과 · 케이크·크림 디저트 · 초콜릿·견과 과자 · 빙과·아이스크림 · 과일 · 커피 · 차 · 와인 · 맥주 · 막걸리·약주 · 주스·탄산음료 · 한식 · 중식 · 일식 · 양식 · 이탈리안 · 프렌치 · 태국음식 · 베트남음식 · 인도음식 · 멕시칸 · 중동음식 · 퓨전 · 발효음식 · 훈연음식 · 향신료 음식 · 고기 · 생선 · 채소 · 치즈 · 디저트 · 음료

**조합 예시:** 중식 + 면 + 볶음 / 일식 + 면 + 발효음식 / 한식 + 구이 + 발효음식.

중식 하나만 골라도 넓은 중식 맵을 사용할 수 있다. 면이 함께 선택되면 면의 식감 가지를 중심으로 구성하고, 볶음이 더해지면 볶은 향·소스 가지를 연결한다. 중식이라는 이유만으로 매운맛·불향·기름기를 사용자 관찰로 확정하지 않는다.

## 태그와 버블 맵 연결

| 메뉴 예시 | 확인된 구성 태그 예시 | 사용할 맵 | 추가·제외 |
| --- | --- | --- | --- |
| 돈가스 | 튀김 · 돼지고기 · 튀기기 | 튀김 | 기본 가지 |
| 연어회 | 회·생요리 · 연어 · 생으로 내기 | 회·생해산물 | 기본 가지 |
| 구운 연어, 크림소스 | 구이 · 연어 · 굽기 · 크림소스 | 생선구이 | 추가: cream |
| 연어튀김 | 튀김 · 연어 · 튀기기 | 튀김 | 추가: cooked_seafood |
| 크림 리조또 | 밥·곡물 요리 · 쌀 · 크림소스 | 크림소스 면·밥 요리 | 제외: noodles |
| 크림 파스타 | 파스타 · 밀·밀가루 · 크림소스 | 크림소스 면·밥 요리 | 제외: rice |
| 메뉴 미확인 사진 | 미확인 | 공통 맵 | 추가: basic, finish |

각 조합은 검토 예시다. 기본 맵을 고른 뒤 알려진 주재료·소스·조리 방식으로 가지를 더하고, 해당하지 않는 가지를 덜어낸다. 같은 단어 ID는 합쳐 중복 표시를 막는다. 알려지지 않은 재료의 부재나 알레르기 안전성을 이 태그로 판정하지 않는다.

혼합 요리는 여러 디시 종류 태그를 동등하게 함께 보관할 수 있다. 예를 들어 카레 덮밥은 밥의 식감과 카레소스를 함께 연결한다. 분류가 불확실하면 공통 맵으로 바로 기록하고 분류는 나중에 보완한다.

## 기존 19개 태그의 대응

후보가 여러 개면 전부 자동 적용하지 않는다. 기존 ID·라벨을 보존한 뒤 메뉴 문맥 또는 사용자 정정으로 세부 태그를 결정한다.

| 기존 ID | 새 태그 후보 | 처리 기준 |
| --- | --- | --- |
| seafood | 생선 · 조개·굴 · 새우·게 · 오징어·문어 · 해조류 | 해산물 안의 세부 재료를 확인. 모두 선택하지 않음. |
| meat | 육류 | 하위 재료가 확인되면 소고기·돼지고기 등으로 구체화. |
| vegetable_herb | 잎채소 · 뿌리채소 · 열매채소 · 버섯 · 허브·향채 | 채소와 허브를 구분. |
| legume_tofu | 콩·두부 | 콩·두부 재료로 이동. 디시 기본 종류는 별도 판단. |
| grain_noodle | 밥·곡물 요리 · 면 · 파스타 · 빵 · 잡곡 | 음식 형태를 확인한 뒤 하나 이상의 실제 해당 태그만 선택. |
| dumpling_batter | 만두·딤섬 · 밀·밀가루 | 만두와 반죽 재료를 구분. 전은 조리 방식과 재료로 보완. |
| broth | 국물 · 국·탕 | 디시가 국인지 일부 국물인지 구분. |
| sauce_glaze | 소스·양념 · 단맛 글레이즈 | 소스 부위와 글레이즈 종류를 구분. |
| grilled_smoked | 굽기 · 훈연 | 굽기와 훈연을 구분. 불향 관찰로 자동 변환하지 않음. |
| stir_fried_wok | 볶기 | 실제 조리법으로 이동. 불향을 확정하지 않음. |
| fried_crispy | 튀기기 · 튀김 | 튀김 조리와 바삭함 관찰을 구분. |
| steamed_braised | 찌기 · 졸이기 | 찌기와 졸이기를 문맥에 따라 구분. |
| raw_cured | 생으로 내기 · 염지·큐어 · 절이기 | 생식·염지·절임을 구분. |
| fermented_jang | 발효 · 장류 양념 | 발효 공정과 장류 양념을 구분. |
| dairy_cheese | 우유·크림 · 치즈 | 우유·크림과 치즈를 구분. |
| spice_heat | 향신료 · 고추 양념 | 재료·양념만 옮김. 느낀 매운 강도는 관찰로 따로 수집. |
| cold | 차갑게 · 얼린 상태 | 제공 온도를 확인. 시원한 맛으로 변환하지 않음. |
| dessert | 케이크·크림 디저트 · 빙과·아이스크림 · 과일 · 초콜릿·견과 과자 · 떡·한과 | 구체적인 디저트 종류를 확인. |
| beverage_pairing | 커피 · 차 · 와인 · 맥주 · 막걸리·약주 · 주스·탄산음료 | 음료 종류를 확인. 페어링 여부는 식사 맥락에 원본 보존. |

## 수집·정제 계약

- 사용자 확인, 메뉴 명시, 모델 추정을 서로 다른 출처로 남긴다.
- 원본 태그를 보존하고 분류 정의 버전을 저장한다.
- `튀김`에서 `바삭함`, `연어`에서 `지방감 선호`, `향신료`에서 `매운맛 선호`를 자동 생성하지 않는다.
- 태그 수정으로 맵이 달라져도 이미 고른 버블과 원문은 유지한다. 음식 자체가 잘못 식별됐다면 해당 경험과 관찰 대상을 함께 정정한다.
- `국물`과 `소스`는 디시 전체일 수도 일부 구성일 수도 있으므로 대상 범위를 기록한다.
- 기존 사용자 변경과 실행 중인 앱 계약은 유지한다. 실제 마이그레이션과 메뉴 분류기는 구현하지 않았다.
