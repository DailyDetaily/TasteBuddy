# 감각 상세 확장: 독립 개발 평가와 공개 참고 자료

## 평가 역할과 동결

`../../scripts/tba-engine/sensory-review-cases.json`은 생산 추출 규칙을 읽기 전에 사용자 요구만 보고 직접 작성한 한국어 예문 50개다. 기존 고정 회귀 fixture와 다른 **개발 검토 세트**다. 실제 이용자 발화나 사용자 취향 데이터가 아니다. 첫 실행 결과를 읽어 정답을 만들지 않았다.

- 버전: `sensory-review-v1`
- 동결 SHA-256: `c0e764cd172ec8ed6bae940510260f35c49c4c86ae0a70dae1273251dab35fa4`
- 초기 출력: `../../scripts/tba-engine/sensory-review-baseline.json`. 최초 저장은 `wx`로 수행해 기존 파일 덮어쓰기를 금지했다. 재평가 때 이 파일은 수정하지 않는다.
- 최초 저장 시 생산 버전은 이미 `tba-rules/4`였다. 확장 시작 전 버전의 성능이라고 주장할 수 없다.
- SR-033, SR-043, SR-044와 명시 호감 누락 SR-010, SR-013, SR-047는 오류 수정을 위해 생산 담당자에게 공유했다. 따라서 비공개 holdout이나 블라인드 최종 검증이라고 부르지 않는다.

기대 상세는 `kind=sensory_detail`, `scale=sensory-detail-v1`, 원문 부분구절을 포함하는 **원문 그대로의 value**로 검사한다. 앞뒤 원문이 추가로 포함되는 것은 허용한다. 평가기의 감각 영역 매핑은 생산 코드의 구체적 속성명과 각 영역의 `.unspecified`를 허용한다. 여운은 `finish`이며 삼킨 뒤 단맛은 `taste` 또는 `finish`, 이에 달라붙는 감촉은 `texture` 또는 `mouthfeel`을 허용한다. 이들은 표현 규격 호환이며 원문 기대 구절을 줄이거나 정답 문장을 바꾼 것이 아니다.

## 지표 해석

상세 회수, 명시 호감 회수, 선택된 안전성 제약, 원문 span 무결성, 미해석 비율을 따로 보고한다. API 대기 또는 unresolved가 남은 문장은 의미 성공으로 세지 않는다. 원문을 통째로 보존했다고 대상·시점·조건·조합의 관계를 해석했다고 세지 않는다. 관계 검토가 필요한 문장 8개는 자동 관계 정확도를 `null`로 남긴다.

초기 저장 출력 재평가: 상세 15/42, 명시 호감 5/16, 안전성 위반 문장 3/50, 잘못된 원자 원문 span 0/50, 미해석 포함 41/50. 이 수치는 전체 자연어 정확도나 사용자 취향 예측 정확도가 아니다. `semanticSuccess`는 좁은 자동 검사 통과 수에 불과하며 제품 전체 정확도로 보고하지 않는다. 자동 검사가 모든 잘못된 대상 연결·이유 귀속·음식 은유를 잡는다고 보장하지 않는다.

SR-043은 첨부하지 않은 사진 분석 요청을 `식감을 분석해 줘.`라는 감각 경험으로 만들었다. SR-044는 식당 조명의 따뜻함을 음식 온도로 만들었다. SR-033에서는 소스에 찍는 조건을 소스의 바삭함으로 귀속한 오류도 발견했다. 세 사례는 생산 규칙 수정 후 같은 기대값으로 재평가해 잘못된 원자 생성이 사라짐을 확인했다. 후속 실행에서 상세 16/42, 호감 7/16, 선택된 안전성 위반 0, 잘못된 원문 span 0, 미해석 포함 39/50이었다. 최신 실행값은 결과 JSON을 기준으로 확인한다.

```sh
node --test scripts/tba-engine/sensory-review-evaluation.test.mjs
node scripts/tba-engine/sensory-review-evaluation.mjs --baseline
node scripts/tba-engine/sensory-review-evaluation.mjs --output docs/product/tba-sensory-review-results.json
```

`--baseline`은 저장된 최초 결과에 같은 평가기를 적용한다. 기본 실행은 현재 생산 규칙을 새로 실행한다. 따라서 같은 규칙 버전 문자열 아래 작업 중 변경이 있을 수 있으며, 실행 시각과 실제 출력 파일을 함께 보관해야 한다. 새 결과에는 생산 rules·sensory-language·semantic-lexicon 파일 SHA-256도 함께 남긴다. 최초 baseline에는 당시 파일 해시가 없어 null로 명시한다. 평가기의 단위 테스트 개수는 추출 정확도의 근거가 아니다. LLM/API는 호출하지 않는다.

## 형식 중복 및 호감 정답 검토

동결 분모 42는 정확 묘사 원문 회수 지표이며 전체 의미 정확도 분모로 사용하지 않는다. SR-033의 바삭함, SR-034의 버터 향, SR-036의 허브 향, SR-048의 강한 신맛은 기존 의미 원자가 해당 내용을 충분히 보존할 수 있다. 이 네 사례의 명시된 대체를 `meaningCoverage`에서 허용했다. 원문 상세만 세는 `detailRecall`과 구분하며, 잘못된 대상 귀속은 대체로 통과시키지 않는다. SR-003의 자몽 속껍질 같은 쓴맛은 단순 쓴맛 원자만으로 구체적 비유가 보존되지 않으므로 상세 회수가 필요하다. 기록 전체의 원문 보관과 감각 묘사를 의미 원자로 재사용할 수 있는지는 다른 평가다.

최초 호감 미회수 11개를 수동 분류했다.

- 분명한 호감이나 감각 영역/표현을 정제하지 못한 6개: SR-004 부담스러웠음, SR-009 구수한 향이 좋았음, SR-010 냄새가 싫었습니다, SR-013 탄성이 좋았습니다, SR-014 까슬함이 거슬렸다, SR-019 미끄러지는 감촉이 좋았다.
- 관계 귀속을 조심해야 하는 4개: SR-032 두 음식 조합, SR-034 온도 변화에 따른 향 호감, SR-038 비린 감각의 부재에 대한 긍정, SR-047 향과 입안 느낌의 서로 다른 평가. 해석해야 할 정보는 있으나 무조건 전체 호감 하나로 바꾸면 안 된다.
- 정답 주석의 불확실성 1개: SR-027 `재미있었다`는 관심·흥미 표현이며 명확히 좋아한다는 뜻인지는 단정하기 어렵다. 최초 동결 기대값을 몰래 바꾸지 않고 `rubricReview`에 주석 결함을 표시했다. 엄격히 명시된 호감만의 보조 분모는 15이고 최신 회수는 7/15다. 이 역시 속성별 관계 귀속 정확도가 아니다.

최신 미회수 9개는 명확한 감각 평가 5개(SR-004/009/010/014/019), 조건·평가 분리 3개(SR-033/034/047), 주석 불확실성 1개(SR-027)다. 미해석 39/50은 API를 쓰지 않았다는 상태 설명이며 성능 성공의 근거가 아니다. 생산 구현 피드백으로 공개된 실패를 포함하므로 개선된 수치로 독립 일반화 성능을 주장하지 않는다.
