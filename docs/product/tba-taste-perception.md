# 맛을 느끼는 경향 · taste-perception/1

나의입맛의 기존 레이더·미각변화·특이사항 카드를 TBA의 유효 원응답과 연결한다. 강도를 호감·알맞음·생리적 민감도로 변환하지 않는다.

## 입력과 비교

- 식사: 완료된 현재 소유자의 직접 강도 선택과 기존 TBA 규칙으로 정제한 직접 강도 문장만 사용한다. 원문·원선택·관찰 시점·저장 시점·원본 기록 ID를 보존한다. 생성된 요약, 별점, sensitivityVector는 입력하지 않는다.
- 같은 식당·메뉴·음식 분류·맛·부위·시점의 기록을 묶는다. 식당이나 메뉴 식별 근거, 부위, 시점이 부족하면 확인 중이다. 기록하지 않은 온도·조리 차이가 같다고 가정하지 않는다.
- 같은 식사·맛·음식·조건은 한 표다. 같은 식사의 중복 표현은 횟수를 늘리지 않는다. 같은 조건의 강도 충돌이나 존재 부정은 해당 식사의 강도를 미확정으로 둔다.
- 현재 경향은 최근 3번의 비교 가능한 식사에서 약함·중간·강함 범주의 중간값이다. 3번은 제품 표시의 최소 조건이며 통계적 신뢰도나 임상 기준이 아니다. 범주의 순서를 사용하고 간격이 같다고 해석하지 않는다.
- 변화는 직전 3번과 최근 3번을 비교한다. 두 기간의 관찰 시점이 겹치거나 어느 쪽이 부족·충돌이면 비교를 만들지 않는다. 변화가 없거나 비교할 데이터가 없을 때도 카드를 유지하며 제목은 **아직 변화없음**이다. 부족한 경우 설명은 **비교할 기록이 더 필요해요.**이다.
- 특이사항은 같은 음식의 부위 또는 시점 한 조건만 다르고, 각각 3번 이상 있으며 비교 기간이 겹칠 때의 강도 차이다. 조건이 원인이라는 인과 주장을 하지 않는다.

## 기준 음식 회상

레이더 상단 기간을 눌러 출처를 선택하며 회상은 원래 0–4 강도를 표시한다. 0은 유효한 응답이며 미응답·모름은 채우지 않는다. 문항·음식·조건·척도·회상 기간·설문 버전이 동일한 이전·최근 설문만 비교한다. 같은 시각의 사본은 과거 응답으로 보지 않는다. 회상 응답을 식사 횟수에 합치거나 음식 간 민감도 순위로 만들지 않는다. 지방맛은 예비 단서로 안내한다.

웹은 기존 측정 이력과 현재 소유자의 완료된 식사 원응답을 읽는다. 로컬 설문 이력은 원응답 객체로 최근 7개를 보관한다. 원격 식사 조회는 예시 예약을 생성하지 않는다. iOS·Android는 기존 프로필 이력과 완료된 DiningEntry의 검증된 관찰을 사용한다.

## 화면과 근거

기존 SectionCard·레이더·해석 카드·시트를 재사용한다. 강도를 모르는 축은 사용자 요청에 따라 가장 짧은 그래프로 표시한다. 이 길이는 화면에만 적용하며 원응답은 미응답으로 유지한다. 중립값이나 평균 근거를 만들지 않는다. 각 축의 적용 조건·근거 수를 표시하고 상세에서 이전·최근 기간과 분포, 해당 기간의 원본 기록으로 연결한다. 식사와 설문 자료는 별도 출처를 유지한다.

## 검증

공통 19개 사례는 식사 중복, 같은 ID의 충돌, 완료 여부, 다른 사용자, 호감·알맞음 제외, 조건 부족, 지방 질감 제외, 전후 비교, 조건별 차이, 미래 기록 차단을 포함한다. JavaScript·Swift·Kotlin이 동일한 fixture로 검사한다. 설문 0·모름·버전/조건 변경·같은 시각 사본의 비교 금지도 별도 검사한다.

실행 결과와 기기 확인 경계는 이번 작업 보고 및 `android/PORTING_STATUS.md`를 따른다.

### 미각변화 전체 화면 연결 (2026-09-07)

- 미각변화 카드는 기존 `미각 변화` 전체 화면으로 이동한다. 레이더·특이사항에서 여는 근거 시트는 유지한다. 기존 기간 탭, 기간 이동, 맛 선택, 선 그래프, 이전·최근·변화 요약을 사용한다.
- `TasteChangeSeries`는 기존 비교 결과의 이전·최근 두 기간을 표시용으로 전달한다. 음식·부위·시점이 다른 식사와 기준 음식 회상은 각각 별도 계열이다. 동일 맛 안에서 음식·출처를 선택한다. 식사는 약함·중간·강함, 회상은 원래 0–4 범주로 표시한다.
- 기간 필터는 각 묶음의 마지막 관찰 시점을 기준으로 적용한다. 근거 부분에는 묶음의 실제 시작·종료일과 식사 횟수 또는 회상 응답 수를 표시한다. 충분한 이전·최근 자료가 모두 보일 때만 강해짐·약해짐·같은 강도를 표시한다. 빈 데이터에 샘플 점수·날짜·추세선을 만들지 않는다.
- 식사 그래프의 근거는 해당 두 기간의 원본 식사 기록으로 연결하며, 회상은 제출 당시 문항·조건·응답을 보여준다. 그래프와 요약에 재사용해도 근거 수를 늘리지 않는다.
- 웹: `npm test` 32개 및 별도 실행 검사, 최종 `npm run build`와 PWA 생성 통과. 모바일 화면에서 빈 카드 → 전체 화면 → 뒤로, 회상 2→0, 기간 필터·이동, 식사 3+3 비교, 원본 응답 펼치기, 기록 없는 맛 전환을 확인했다.
- iOS: 새 DerivedData에서 앱·전체 테스트 타깃 컴파일과 관련 XCTest 4개 통과. 변경된 미각변화 관련 소스는 빌드 중 유지됐으며 별도 작업의 `HomeView.swift` 변경은 이번 검증 범위에 포함하지 않았다. `--taste-perception-qa --perception-change-page`의 빈 상태와 `--perception-meals` 식사 비교 상태를 시뮬레이터에서 확인했다. iOS 실제 탭 이동·VoiceOver 검증을 의미하지 않는다.
- Android: 단위 검사 483개, 앱 및 기기 검사 APK 빌드 통과. `TastePerceptionJourneyTest`를 전체 화면 진입·뒤로·원본 연결 경로로 갱신했다. 앞서 확인한 에뮬레이터 시스템 ANR 때문에 실제 기기 동작 확인은 남아 있다.
