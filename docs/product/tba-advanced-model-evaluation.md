- 시나리오: 32개. 실패를 없애려고 기대 의미를 바꾸지 않는다. 새 계약에 필요한 필드 연결은 별도로 기록하고, 표현만 달라지는 경우 허용/금지의 의미를 유지한다.

## 입력과 적용 경계

감각 예시는 현재 실제 선택인 `sour-fresh`(산뜻한 산미), `umami-clear`(맑은 감칠맛), `bitter-roasted`/`aroma-roasted`(구운 향), `texture-crisp`(바삭함)을 사용한다. `liking`은 liked/neutral/disliked, 강도는 light/medium/strong, 알맞음은 tooWeak/justRight/tooStrong이며 nil은 미응답이다. 대상·시점은 실제 DTO 값으로 제한한다. 음식종류 A/B는 새 가상 분류가 아니라 실행 fixture를 연결할 때 기존 계약에서 선택할 서로 다른 두 종류를 뜻한다. 종류 이름만 보고 감각을 추론하지 않는다.

전체 평가는 별도의 `DiningOverallEvaluation` 5단계 원값을 사용한다. 개별 감각 3단계의 세분화나 가중치가 아니다. 기록의 소유자·식사 식별·현재 유효성·입력 시점은 출처 계약을 따라야 한다. 기준 동결 당시 Native에는 같은 식사를 묶는 식별 정보가 부족했다. 현재는 mealID로 같은 식사의 메뉴 기록을 묶으며, 과거 기록의 UUID fallback만으로 실제 식사 독립성이 새로 입증된다고 보지 않는다.

질문 중복 제어와 미래 누수 검사는 기준 동결 당시 DTO에 없던 이력/시점 계약이 필요했다. 연결 전에는 '필수 계약 미연결'로 남겼으며, 이후 연결과 실제 실행 결과를 아래에 구분해 기록했다. 질문 노출 자체를 감각 근거로 세지 않는 원칙은 유지한다.

## 평가 방식과 완료 판정

실행 검사는 입력 fixture와 동결 기대 기준을 연결한 뒤 수행한다. 각 시나리오 결과는 통과/실패/계약 미연결/실행 미검증으로 구분하고, 실패 출력과 실제 원자료 참조를 함께 보존한다. 비교 검사는 동일한 감각 평가를 유지하면서 전체 평가나 저장 순서 등 한 조건만 바꿔 금지된 변화가 발생하는지 확인한다. 다른 조건이 동시에 바뀐 경우 원인을 하나로 설명하지 못하도록 검사한다.

검증 항목은 의미 보존, 유효 근거의 수와 출처, 조건·예외의 보존, 회수와 시간 경계, 미확인의 표현이다. 특정 점수식·클러스터·가중치·문장 일치 자체를 정답으로 삼지 않는다. 근거가 불충분한 상태를 숨겨 그럴듯한 문장을 만든 결과는 통과가 아니다. 문구를 선택적으로 생략할 수 있더라도 근거가 보여 주는 반대 사례와 미확인을 감추어 반대 의미를 전달하면 실패다.

이 32개는 수작업 개발 안전성과 계약 검증이다. 전체 사용자 언어 이해 정확도, 실제 음식 선택 성공률, 취향 변화 예측, 추천 효과를 측정하지 않는다. 그런 주장은 동의받은 실제 기록, 별도 학습/평가 분리, 시점과 개인·식사를 지킨 평가, 사용자 해석 검증이 있어야 한다. 기준을 동결할 때는 문서 작성까지만 진행했다. 이후 실행 검증 결과는 아래에 기록했으며, 실제 외부 API 호출은 0이다.

## 기준 동결 당시 상태

당시에는 기준을 동결했고 새 생산 모델·출력을 읽기 전이었다. 자동 실행 fixture 연결과 검사 실행도 하기 전이었으며, 문서만 추가한 단계라 앱 빌드를 실행하지 않았다.

## 독립 실행 연결

고정 원자료는 `scripts/tba-engine/advanced-personal-cohorts.json`에 별도로 보존했다. 버전은 `advanced-personal-cohorts/1`, 파일 SHA-256은 `97f44fd703fb056f5ecaec0c7790f80d832ab50b1e758e75dacf2042c0110706`이다. 새 생산 알고리즘을 읽기 전에 다섯 cohort의 159개 식사, 정답 방향과 61개 순차 holdout을 동결했다. 32개 기대 표는 그대로다.

각 holdout 식사 직전까지 관찰되고 알려진 현재 유효 입력만 사용해 다시 모델을 만든다. 같은 식사는 학습과 평가에 함께 넣지 않으며, 개인이 다른 입력도 제외한다. 비교 baseline은 사전에 고정한 조건 없는 속성별 식사 최다 응답이다. 최소 3개 식사 미만과 동률은 유보한다. 모델과 baseline에는 동일한 학습 식사·시점 필터를 적용한다. 이후 결과가 알려진 holdout은 다음 평가 시점의 학습 입력에 들어갈 수 있는 순차 평가이며, 무작위 분할 평가가 아니다.

**이 평가는 대상·강도·시점·음식종류 조건이 명시적으로 제공된 뒤의 호감 반응 비교다.** 해당 조건을 먹기 전에 알았다고 가정하지 않는다. 평가 metadata는 `queryKnownConditions`를 명시하고 `preConsumptionPrediction:false`를 둔다. 실제 미래 음식의 감각을 추정하는 모델이나 섭취 전 메뉴추천 성공률을 평가하지 않는다.

정확도는 응답 방향을 낸 평가 건만 분모로 쓰고, 예측/유보 coverage와 그 분모·개수를 cohort마다 함께 보여준다. 방향을 하나도 내지 않으면 정확도는 0 또는 100%가 아니라 null이다. 잘못된 확정 응답 수는 유보하지 않고 낸 방향이 정답과 다른 횟수이며, 확률 보정이나 Brier 점수라는 의미가 아니다.

초기 실행은 모델 단독 29개 기준 가운데 26개 통과, 3개 실패였다. 실패는 AM-05 미경험 음식종류로의 일반화, AM-07 교란된 미관찰 조건 조합 예측, AM-30 미경험 강도로의 일반화였다. 원자료·기대값을 바꾸지 않고 생산 담당자에게 전달했다. 초기 상세 결과는 `tba-advanced-model-evaluation-initial-results.json`에 남겼다.

AM-18/22/27은 모델 record 단독 입출력만으로 완료라고 셀 수 없으므로, `AppModelAdvancedModelTests.swift`의 실제 미완료 기록 제외, 빈 선택과 legacy IDs 재시작, 질문 노출·보류·해결 이력의 재시작 및 증거 불변 검사로 연결했다. 최종 전체 XCTest는 2026-09-06 20:36:28 KST에 **268/268 통과, 실패 0, skip 0**으로 완료됐다. 결과 bundle은 `/tmp/tba-advanced-personal-final-native.xcresult`다. 이 실행에 `AdvancedPersonalTasteModelTests.swift` 18개, AppModel 검사 4개, `PersonalTasteQuestionResolutionTests.swift`의 질문 해결 회귀 검사 9개가 모두 포함됐다.

따라서 동결 AM 기준은 **JS 모델 단독 29개 + Native 실제 진입 AM-18/22/27 3개 = 32개 모두 연결 검증 완료**다. 질문 해결 추가 9개는 다른 감각·미완료·미지원·다른 조건 저장을 잘못된 해결로 세지 않고, 원기록 보완과 새 식사 탐색을 구분하며 실제 강도와 직접 호감이 함께 있을 때만 탐색을 해결하는 회귀 범위를 검증한다. 이 개발 검증 통과는 실제 사용자 품질이나 예측 정확도를 입증한다는 뜻이 아니다.
