# 미각 버블·디테일 v2 앱 반영

## 적용 범위

- iOS `DiningFeedbackSheet`와 웹 `NativeDiningEditor`의 실제 미식 기록 흐름에 적용했다.
- 새 기록은 미각 버블 160개, 디테일 태그 147개를 사용한다. 음식 프로필 15종과 구성 오버레이 4종을 지원한다.
- 기존 원형 지도, 6축 색상, 팬·줌, 최대 3개 선택을 유지한다. 음식별로 축당 최대 2쌍을 교환하므로 160개 중 최소 136개 위치가 유지된다. 디테일은 음식에 맞는 목록으로 바뀌며 전체 표현 검색도 가능하다.
- 버블 없이 디테일만 기록할 수 있다. 음식 전체가 기본 설명 대상이며, 흐름 태그의 버블 연결은 사용자가 직접 고른 경우에만 저장한다.
- 같은 디테일을 다른 대상·시점으로 추가하면 별도 선택 인스턴스로 보관한다. 연결한 버블을 삭제해도 디테일 원문은 보존하고, 연결이 끊긴 해석은 보류한다.
- v1 기록의 단어·버전·응답과 알 수 없는 원문 필드를 보존한다. 새 표현 위치나 단어만으로 호감·평점을 만들지 않는다.

## 데이터와 재생성

원본은 `docs/product/tastebuddy-sensory-redesign-v2.json`이다. 원본 문서의 표현들은 편집 후보이며 사용자 연구로 검증되었다는 뜻은 아니다.

```sh
node scripts/build-sensory-v2.mjs
node scripts/build-sensory-v2-fixtures.mjs
node scripts/build-sensory-v2.mjs --check
node scripts/build-sensory-v2-fixtures.mjs --check
```

같은 런타임 카탈로그를 웹과 iOS에 번들한다. Android에는 동일한 리소스 파일을 생성하지만 이번 앱 흐름 연결·검증 범위는 iOS와 웹이다.

표시 버전, 음식 프로필, 구성 확인 상태, 지도 순서와 제안 디테일 목록을 기록에 저장한다. 실제로 화면에 들어온 단어와 사용자의 주의는 측정하지 않았으므로 `viewportVisibility=unmeasured`, `attention=unknown`으로 남긴다.

## 검증

- 웹 단위·회귀 검사: `npm run test:native-web` 180개 통과. 새 선택의 인스턴스별 후속 응답과 기존 분석·저장 동작을 포함한다.
- 기존 설문·피드백 검사: `npm test` 통과.
- iOS: 앞선 빌드와 33개 단위 검사는 통과했다. 이후 변경분의 최종 재검사는 사용자의 “검증은 내가 할게” 요청에 따라 중단했다.
- 공유 비교: 선택 사례 316개와 음식 맥락 42종을 Swift와 JavaScript에서 비교한다.
- 웹 브라우저: 실제 입력 화면에서 새 단어 `조청 같은 단맛` 검색·선택, 커피용 태그, 버블 삭제 후 `마실수록 쌓임` 유지, 디테일만 저장, 재진입 복원을 확인했다. 430×932 화면에서 지도와 2줄 가로 태그 목록을 확인했다.
- 웹 검증은 게스트 기기 저장으로 수행했다. 원격 계정 동기화·실기기 배포는 이 검사의 범위에 포함하지 않았다.
- 웹 최종 타입 검사와 빌드는 통과했다.
- 첫 iOS UI 검사 실행은 시뮬레이터의 AX 초기화 시간 초과로 시작하지 못했다. 후속 자동 검증은 사용자 요청으로 중단했으므로 iOS 화면·동작 검증 완료로 간주하지 않는다.
