## 버전과 원본 보존

- 새 정제 규칙: `tba-rules/6`; 네이티브 분석 버전: `tba-native-sensory/5`.
- 기존 v5 규칙은 `scripts/tba-platform-pilot/rules-v5.mjs`로 보존하고 저장 artifact의 버전별 검증 경로에 등록했다. 기존 v3/v4/v5 artifact를 v6 결과로 조용히 바꾸지 않는다.
- 현재 iOS·웹의 원문 재분석은 새 규칙을 사용한다. 기존 JS 저장 artifact의 일괄 재처리·이관은 실행하지 않았다.
- 생성된 iOS 감각 계약은 153개 파서 예문을 포함한다. 이는 JS/Swift 계약 일치 검사이며 독립 정확도 평가를 뜻하지 않는다.
- 개인 모델 최소 식사 수, 반례 유보, facet 우선 질문 순위는 변경하지 않았다. 실제 사용자 자료 없이 해당 정책을 더 정확하다고 보정하지 않는다.

## 평가 결과를 읽는 방법

새 평가기는 `sensory-review-evaluation/2`다. 기존 50개 개발 문장과 동결 해시는 유지하고, 따로 작성한 4개 관계 기준만 `scoped_relations`로 검사한다. 관계 기준이 없는 문장은 부분 검사를 통과해도 의미 성공으로 세지 않는다.

현재 개발 자료의 detail 회수는 16/42, 명확한 호감 회수는 7/15다. 4개 명시 관계 기준 중 3개가 통과한다. 이는 새 집계 정의의 결과여서 이전 버전의 `semanticSuccess` 수와 개선율로 비교할 수 없다. **전체 의미 정확도는 계속 null**이며, 사람 검수·비공개 평가·실사용자 효용은 미검증이다.

### iOS 실행 한계와 보존 자료

처음의 직렬 빌드는 병렬도를 2로 조정하기 위해 중단했다. 캐시를 재사용한 다음 빌드에서 앱과 테스트 번들이 생성되었지만 시뮬레이터 실행 준비가 지연됐다. 재시작 후에는 재컴파일 없이 재시도했다. 중단한 실행은 각각 원본 로그로 보존했고, Xcode가 테스트 로그를 종료하지 못해 일부 `.xcresult`는 불완전할 수 있다.

- 컴파일·링크 기록: `native-launch-r2-tests.log`.
- 최종 실행 시도: `native-tests.log`, `native-command.json`.
- 실제 제한: `native-runtime-limitation.json`, `simulator-app-status.json`.
- 네이티브 파서 직접 실행: `native-parser-check.log`, 당시 사용한 `native-parser-source.swift`.
- 이 작업에서 만든 시뮬레이터에만 종료를 요청했다. 다른 작업의 기기나 CoreSimulator 서비스 전체를 재설정하지 않았다.

실기기, 실제 사용자 자유문 정확도, 운영 계정 동기화, Android, 전체 앱 시각 검사는 이 수정의 검증 범위가 아니다. 실제 iOS 저장 경로 검사를 작성하고 컴파일했지만 그 실행 성공을 주장하지 않는다.
